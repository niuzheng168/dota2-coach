# 双机教练 v0.4.1：玩家模式小地图明细与 120fps 窗口采集

v0.4.1 改了游戏端两处：Debug 记录玩家模式小地图明细，以及窗口采集帧率上限。配对、视频协议和自动教练与 v0.4.0 相同，两端都用 v0.4.1 即可（视频协议仍是 v3，v0.3.x 不能配 v0.4.x）。

**窗口采集帧率**：Windows 默认每 16 ms 最多交一帧窗口采集画面，在 144Hz 显示器上实测只有约 48 fps。v0.4.1 设置 `MinUpdateInterval = 1 ms`（需 Windows 11 24H2 及以上），在 120/144Hz 显示器上实测可采到 **119.8 fps**。系统不支持时自动保持原行为，采集方式名称会写明“此Windows版本采集上限约60fps”。

## 为什么要改

2026-11-17 第一次真人对局实测：

| 问题 | 结果 |
|---|---|
| Plus 实时观战比游戏机慢多少 | 中位数 −62 → −31 ms，P10 约 −150 ms，P90 +60…+94 ms，两边整秒游戏时钟一致。测法偏低 0.1–0.2 秒，换算真实延迟约 **0–0.2 秒**。教练机 `console.log`（`-condebug`）显示 Plus 实时观战直接连到这局的游戏服务器，不经过广播中继 |
| 游戏机自己的 GSI 有没有小地图 | **有**。快速模式一局 5863 个有效自身状态包全部带小地图，单位数 103–288（中位 164） |

v0.3.1 / v0.4.0 的游戏端只统计小地图**数量**。小地图里到底有哪些单位、敌方英雄是否只在有视野时出现（战争迷雾过滤），还无法回答。

## 改了什么

- 游戏端状态行：`玩家模式小地图：有，N 个单位，其中敌方英雄 K 个`。K 按英雄名去重（同一英雄可能有多个条目，阵亡时可能留下视野为 0 的静止条目）。
- 游戏端开启 Debug 后，对局中**每秒**记录一条 `player-minimap`，格式与教练端 Plus 观战的 `spectator-snapshot` 相同：
  `[单位名, 阵营, x, y, 视野半径, 图标]`，另有游戏时间、游戏状态、己方阵营、建筑阵营、事件类型。
- 菜单阶段不记录。每个 GSI 包仍有一条 `gsi-status`，新增 `enemyHeroes`。
- 不解析玩家昵称、SteamID 或原始 GSI；数据只写本机 Debug 目录，**不上传、不进模型**。约每小时 40 MB。

## 怎么测

1. 游戏机打开游戏端（v0.4.1 及以上），展开“Debug”，勾选 Debug（v0.4.2 起叫“开启 Debug 记录”）。
2. 粘贴配对码，点“连接”（v0.4.1 叫“连接并开始”）。若提示 GSI 配置已写入/更新，完全重启 Dota 一次。
3. 打一局真人对局。对局中可以随时看状态行里的敌方英雄数：如果它随视野变化（例如 0–3），说明有迷雾过滤；如果始终是 5，就要重点核查。
4. 赛后用正常方式关闭游戏端，把 Debug 目录里带 `-game-` 的文件夹拷出来分析。
