# Luna 7.41f：100 场录像研究与局势教练设计

> 这 100 场仍属于 7.41f，不计入[7.42 露娜与巨魔的高分局研究](farming-742.md)。

日期：2026-11-16，香港时间。

> **已完成：100 场入选回放完整解析、100 份逐场大模型复盘、交互路线图与证据定位。** 数量与统计见 `data/luna-hundred-audit.json`。这是离线研究交付，实战路线没有启用。

## 方法与边界

- 来源是 Dota2ProTracker 的 Luna Carry 比赛表，实际通过浏览器逐页读取了 174 个不同 match ID，其中 59 个在 Pros Only 筛选结果中。职业标识优先，其余按页面显示的**对局平均** MMR 排序；不按胜利或高收入筛选。
- 赛事标识不是个人 MMR；职业名、smurf 名均为网站标签，未独立认证实际操作者。
- 下载 OpenDota 提供的 Valve replay URL；不猜 salt。按文件魔数解压，保留下载、解压、解析文件的散列。公开接口够用，没有读取 Steam 账号文件。
- 每场完整解析到终局：7.41f 官方时间窗口、独立客户端 build 历史、28 个营地及刷新框、22 座塔、10 名玩家的终局补刀逐项校验。旧 build 不直接当成旧子版本，缺少 build 来源时先补证据再重验。
- 每秒保留全图状态和装备技能；Luna 本体约每 0.1 秒采样，交互轨迹保留真实点而非插值路线。全图信息只用于离线复盘，**没有玩家视野掩码**。
- 逐 30 秒计算兵线、野怪、英雄、建筑分项实际金币；分开本体与幻象击杀事件。金币累计计数仍包含受控单位，不能由事件数量倒推出幻象的精确金币。
- 全场每 60 秒提供世界背景，每 30 秒提供收入窗口；不只选取漂亮片段。每场由独立配置的 `gpt-6-astra` 做离线复盘，包含事实、解释、现场要判断的问题、反例、未知项。程序只做事实提取、校验和呈现，**不选择刷钱路线**。
- 所有模型观察必须引用该场真实窗口 ID。引用存在不代表解释必然正确，仍需抽查原始数据。这里是检索/上下文研究，不是训练了新的模型权重。
- 这些是观察性样本，不是固定装备实验、反事实执行、随机抽样或最优收益证明。完整 10–20 分钟统计排除提前结束的比赛；不能把短局外推到 20 分钟。
- 部分旧 build 的单位名称字段没有解出，因此单只击杀到营地的关联会保留未知；出生器句柄、营地活怪计数、本体坐标和金币计数是不同证据，不因为前者未知就随意推断后者。不能声称所有字段均已无歧义解析。
- 入选集中有 **14 场**的野怪击杀事件全部未能消歧到营地。界面保留“未消歧”，没有用最近野点补猜。路线图本身仍来自实际本体坐标。

## 100 场实际统计

最终入选：**50 场职业筛选标识 + 50 场其他高分天梯**。其中 30 场赛事、70 场天梯，57 场天辉、43 场夜魇，48 胜、52 负，合计 **57.24 小时**。对局开始时间为 2026-09-19 至 2026-11-15（UTC），均在已核验的 7.41f 窗口内。

有数字 MMR 的入选对局显示范围为 7221–8372；赛事与排行榜名次不冒充个人/对局 MMR。重复玩家不能当成独立人群样本：这 100 场对应 39 个账号标识，最多同一账号 11 场。

**只有 92 场完整覆盖 10–20 分钟**，下表分母均为 92：

| 指标 | 实测 |
|---|---:|
| 同时获得兵线与野怪金币 | 92 / 92 |
| 线野金/分中位数 | **558.85** |
| 线野金/分第 25–75 百分位 | 482.625–623.825 |
| 各场兵线占线野收入比例的中位数 | **42.73%** |
| 自己的叠野计数在窗口增加 | 62 / 92 |
| 观察到幻象线上击杀事件 | 73 / 92 |
| 窗口内有本体死亡转变 | 67 / 92 |

上述金/分不含工资、英雄、建筑或其他金币；含受控单位。**558.85 不是当前教练模型的实战 GPM，也不是固定装备 Luna 的预计收益。**

空间上，完整窗口的存活本体采样中，天辉约 **79.4% 在地图南半边**，夜魇约 **80.1% 在北半边**。这里仅按真实坐标 `y` 分半，不是“安全地盘”、刷野耗时或最优区域分类。它支持你说的局部线野衔接，但不支持把所有阵营的 Luna 都写死为下半区。

100 场中，95 场曾在主物品栏观察到疯狂面具，96 场观察到分身斧；有分身斧样本的首次持有时间中位数为 **16:49.6**。这是样本描述，不是购买规则，也不能证明装备造成了收入提升。

额外检查了九页、共 100 张真实本体路线缩略图：紧凑的局部往返很常见，但中途换边、转线、回补和交战也很明显。轨迹重叠次数不能当作有效清野次数。`9089693720` 这样的短局低活动样本保留为反例，不作为正向模仿范本，也不推断玩家主观原因。

### 具体学到了什么

1. **不能只优化营地。** 兵线贡献的中位比例约四成，模型若把“清更多野点”当目标，很容易漏掉主要收入来源。应比较当下可回收的兵线与已确认野怪，而非永远先线或永远先野。
2. **刷新要与当前工作串起来。** whph 的双拉是在连续清理资源过程中，通过远程技能触达、位移和刷新时间衔接做到的。应让模型判断“当前是否还有时间、蓝量、合适目标和撤退条件”，而不是每到某秒钟就机械提醒拉野。
3. **分身后要规划两套任务。** 73/92 个窗口有幻象线上击杀，因此本体路径不等于整名玩家的收入路径。教练需要区分本体资源与幻象资源，且不能让幻象任务抢占必要的保命用途。
4. **高收入片段不等于稳定策略。** 多数样本该阶段有死亡，胜局也存在零收入转移；不能以复盘结局倒推每次转区正确。提醒要持续重估当前可见风险和完成任务后的接续，而不是一次规划三分钟后不再更改。
5. **装备、等级与团队空间不可混为因果。** 同是 Luna，十分钟等级、经济、队友支援和装备时点差异很大；不能把 whph 的高值套给更落后的用户。

| 案例（10–20 分钟） | 兵线金 | 野怪金 | 线野金/分 | 对教练的启示 |
|---|---:|---:|---:|---|
| whph `9089477184` | 3768 | 4507 | 827.5 | 双拉与后续收线都重要；该场团队优势扩大，不能作为通用收益保证 |
| fn `9087050491` | 1729 | 2570 | 429.9 | 有叠野、换区与幻象分工，也有死亡断档；不要只截取漂亮片段 |
| Inmare `9087623056` | 3341 | 2888 | 622.9 | 本场未观察到疯狂面具，不能把装备常见搭配写成必须条件 |
| miCKe `9065451128` | 2816 | 3507 | 632.3 | 中期收入较高仍是败局；收入指标不能替代局势判断 |
| D2PT 标记 Ame (smurf) `9017174132` | 1249 | 3368 | 461.7 | 该场有换区和死亡；旧 build 的营地击杀关联未知，不据此编造营地顺序 |

1. **没有完整仇恨目标和玩家输入指令**，不能逐键还原操作，也不把本场施法秒数变成通用拉野规则。

## 如何做成“根据局势提醒”

### 1. 学的是取舍，不是固定路径

教练需要决定“此刻更值得接线、清野、安排幻象、为刷新调整位置、换区、补给还是支援”，而非“Luna 到十分钟走 A→B→C”。同一选手、同一装备阶段也会因局势改变任务。

历史案例应给模型提供**对比问题**：当时有什么资源、消耗了什么时间、之后有没有收入中断、换到当前局面有哪些条件不成立。不能直接复制职业选手进入过的区域，更不能把营地阵营前缀当作实时安全判断。

按你先前的要求，初版教练不把对方野区列为可执行打钱目标；职业录像里的扩图或入侵不会自动放宽这个约束。己方野区也不能仅凭阵营标签就判为安全。

### 2. 输入必须是当下可见信息

建议数据流：

```text
本机 GSI：自己英雄、装备、技能、血蓝、时钟、位置
          +
本机定时截图：可见兵线、小地图可见英雄、实际看见的营地/塔
          ↓
带来源和时间戳的局势记忆：已看到为空 / 有怪 / 没看到，三者分开
          ↓
历史案例检索 + 大模型比较当前可行任务
          ↓
地图/时效/可活动区域/机制工具复核
          ↓
一句简短字幕 + 小地图私人悬浮标记
```

- 敌人消失不等于已离开；最后目击坐标不能假装实时位置。
- “野点为空”必须来自有效观察；整分过去只能产生刷新假设，不等于已经确认有怪。
- 先补齐小地图英雄、兵线、营地状态与塔况识别验收。现有本地视觉原型主要核验 HUD/假腿属性，**尚不具备这些完整能力**。
- 3090 Ti 可以作为本地视觉推理的候选硬件，当前没有新的实机视觉准确率、显存占用或延迟结论。
- 回放全图事实与实时可见事实使用不同入口，不能靠一条提示词混在一起防泄漏。

### 3. 大模型负责策略，工具负责事实与可执行性

模型提出若干合理选项，查询相应兵线/营地与移动、清理估值工具，再选择或放弃；工具不替模型排路线、固定循环或设置营地配额。

输出建议包括：

- **下一步**：一个当前任务及地图目标。
- **后续意图**：短期线野衔接方案，允许局势改变后撤销。
- **为什么现在**：引用当前观察，不讲长篇推理。
- **成立条件**：哪些兵线、营地、支援或撤退条件必须确认。
- **取消条件**：新威胁出现、资源被队友处理、兵线不再可接、补给状态改变等。

金币数字只能来自经过校准的工具，没有可靠估值时宁可不报；不能照抄录像收入。

### 4. 定时看画面，不等于定时刷字幕

采集可以连续进行，提醒应有节制：

- 保留当前意图；只有模型判断任务需要改变，才更新主要提醒。
- 字幕优先“一步动作 + 一个原因”。例如“这波线可接，先收线；野点留作下一步”是**交互形式示例，不是当前游戏指令**。
- 小地图先显示一个目标；后续意图用淡线，不能画出未经路径/区域复核的精确行走线。
- 幻象任务与本体任务区分显示，不把两处收入归为本体同时到达。
- 战斗中避免复盘式长解释。死亡、切出游戏、旧截图、换局、过期模型回复立即撤回。
- 采样频率、调用限流、过期检测是工程约束，不是选择打钱策略的规则。

现有桌面 `JungleOverlayWindow` 可复用为私人、鼠标穿透的悬浮层；不注入游戏、不发队伍 ping。它当前按纯野路线结构绘制，仍需增加兵线/幻象/条件化意图的协议与 UI。

### 5. 不把离线复盘延迟当成实战延迟

本轮每场离线请求含整场大量事实，不能直接塞进实战循环。实战只传紧凑局势、少量相关案例及最近变化，模型输出也应短。必须另测截图→识别→推理→标记的端到端延迟；没有测量就不承诺“每几秒完成一次最优规划”。

## 下一阶段验收

1. 先在自定义局录制真实采集数据，对小地图坐标、敌方可见性、兵线/营地状态逐项标注并测误差。
2. 用玩家可见回放前缀做“影子教练”，不读后续事件或全图敌方位置。当前普通提取没有全图视野掩码，不能直接声称完成此项。

5. 实战/受控实验分别测金钱、死亡/撤退、时间损失与提示负担；观测到的职业收益不是新方案的反事实收益。
6. 只有当前输入与执行工具通过验收后，才逐步启用私人字幕与标记；不宣称最高收益保证。

### 新录像复盘的默认模型

新运行的文字复盘使用 **GitHub Copilot（本机 Codey 网关）／`gpt-6.2-sol`／`reasoning.effort=xhigh`**。这只影响对结构化录像数据的解读，不改变本地 DEM 解析、实战教练或上面已经发布的 100 份 Astra 复盘。

启动自己的 Codey 网关，并给运行脚本的进程提供 `CODEY_MODEL_API_KEY`（模型网关密钥，不是 GitHub 登录令牌）。默认地址是 `http://127.0.0.1:4141/v1`；自定义回环端口可设置 `DOTA_COACH_COPILOT_BASE_URL`。

```powershell
npm run replay:study:review -- --check-model   # 只查目录，不发录像、不调用推理
npm run replay:study:review -- --one           # 复盘首场；新配置没有缓存时会使用订阅额度
```

脚本只向目录中唯一标记为 `github-copilot`、支持原生 HTTP `/responses` 且列有所选 effort 的模型发送请求；不会自动降档或回退 Azure。可用 `REPLAY_REVIEW_PROVIDER`、`REPLAY_REVIEW_MODEL` 和 `REPLAY_REVIEW_REASONING_EFFORT` 显式覆盖。选回 `azure` 或 `openai` 时须与 `JUNGLE_PLANNER_PROVIDER` 的凭据匹配；不覆盖模型和 effort 时，沿用原规划器部署名和 `medium`。

新复盘按 `reviews/<提供商>--<模型>--<effort>/` 分开缓存。`replay:study:publish` 要求同一配置的 100 份结果才发布，不会拿旧结果凑数。要从原有 Astra 缓存重建历史发布，可用 `npm run replay:study:publish -- --legacy`（不调用模型）。

可选开发验证：`node scripts/test-codey-gateway.mjs --routes-only` 使用指定版本的本机 Codey 和模拟上游，检查转发出去的模型 ID 与 `xhigh`，不使用真实订阅。

### 录像工作目录

Windows 默认工作根目录为 `Z:\dota2coach\data`。普通下载、`.partial`、解压的 `.dem`、`.facts.json` 和进度文件在 `replays\`；分析子进程的临时目录在 `replays\tmp\`，轨迹、证据和按模型分开的复盘在 `replays\study\`。7.42 专项使用同一根下的 `farm742`、`farm742-more` 等目录。历史资料里的 `.tmp/replays` 对应现在的 `Z:\dota2coach\data\replays`。不用重新下载、搬移或删除已有数据。

显式传给下载器的目录、Python 的 `--root` 优先。要让整套流程统一改用别处，在启动命令前设置进程环境变量，例如 `$env:DOTA_COACH_REPLAY_WORK_ROOT = 'D:\dota2coach\data'`。不修改系统 TEMP；所选盘不可用时不会回退到 C 盘。非 Windows 默认保留仓库 `.tmp`。发布的索引和报告仍按显式发布命令写入仓库。

这只适用于 D2PT 离线研究。桌面端封存的私人对局使用独立解析器，不允许映射网络盘作为工作盘；模型密钥、工具和私人对局档案不会随研究缓存转移。
