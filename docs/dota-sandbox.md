# 简化 Dota 地图与 API 实验台

更新：2026-11-15，香港时间。

**撤回通知：** 当前沙盒路线加载和付费规划已关闭，手动机制测试及离线复现保留。线野示例触及夜魇营地，己方区域未核验，详见 [区域审计](sandbox-own-area-audit.md)。下文的模型调用/载入命令描述历史行为，不代表当前允许运行或已具备实战安全。

**最新版本已改为线野总收益，并支持实际追逐、拉兵线和堆野。** 当前 API、模型反例比较与界面说明见 [v2 线野实验](dota-sandbox-economy.md)。下文保留 v1 的历史机制与结果，不能将旧 408.3 纯野 GPM 当成新版模型最优值。

目标是先验证「**模型观察环境 → 提出行动/路线 → API 执行 → 读取金币、血蓝、失败原因 → 模型修改方案**」，而不是先宣称已在真实游戏中求得最优路线。

**游戏机制由确定性程序执行；营地顺序、目标优先级和施法计划由模型提出。没有规则搜索生成候选，也没有模型失败后的固定路线回退。**

## 当前范围

- 28 个营地与固定版本的步行网格；三条**示意**兵线。
- 每 0.1 秒推进一次，支持暂停、逐步推进、加速和同种子重置。
- 三路双方每 30 秒各出 3 近战、1 远程兵，自动行军和互攻；这些是明确的沙盒参数，不是完整 7.41f 兵线复刻。
- 普通野怪组合按种子抽样，整分刷新；仍有野怪或单位占刷新框时不刷新。
- Luna 普攻、物理护甲、逐目标月刃弹射、月光伤害/前摇/蓝耗/冷却、疯脸攻速/沉默/减甲、主攻击实际伤害吸血、英雄回复。
- 金钱只在英雄造成的单位死亡时结算。野怪、兵线分账，工资为零。死亡结束实验；GPM 的分母始终是 **180 秒**，不扣除空闲或死亡后的时间。
- 当前固定场景：天辉 Luna，10:00 开始、10 级，敏捷假腿＋疯脸，月光 3 / 环月 1 / 月刃 4 / 月蚀 1 / 月刃衰减天赋；1018 HP / 556 MP，起点为天辉下侧大野 5 附近。状态来自 `tests/fixtures/luna-741f.json`。

重要缺口：全图可见；没有敌方英雄、塔、战争迷雾、动态地形、购买、升级、引野追逐、堆野、野怪技能/光环/升级/回复或水生进化。水生营地暂用普通组合。月光不实现眩晕，环月和月蚀不支持；疯脸不增加移动速度。兵线几何、单位尺寸、弹射与攻击表现是简化模型。

**因此，沙盒 GPM 不是现实 GPM，也不是旧数值基准的可直接对比结果。**

## 启动与真实模型实验

```powershell
npm run sandbox
```

服务器只监听 `127.0.0.1:3221`（可用 `SANDBOX_PORT` 改端口）。启动日志提供带临时会话 token 的地图地址；token 也写入被 Git 忽略的 `.tmp/sandbox-session.json`。页面读入后会移除地址栏中的 token。它不是 Foundry 密钥。

网页本身**不发云端请求**。可手动选择营地、清理、指定攻击目标、施放月光/疯脸、推进时间。清理一个营地不会自动选下一站。另一个终端显式运行：

```powershell
npm run sandbox:reason
```

这会使用项目 `.env` 的独立规划模型配置，**产生实际模型调用费用**：

```dotenv
JUNGLE_PLANNER_PROVIDER=azure
JUNGLE_PLANNER_MODEL=实际部署名
JUNGLE_PLANNER_FOUNDRY_ENV_FILE=C:/path/to/private-foundry.env
```

外部文件包含 `FOUNDRY_ENDPOINT`、`AOAI_ENDPOINT`、`FOUNDRY_KEY`。项目只保存文件引用，不复制密钥；不会改动语音资源配置。文件引用方式不能同时设置独立 `JUNGLE_PLANNER_ENDPOINT` / `JUNGLE_PLANNER_API_KEY`，避免将文件密钥发送给另一个端点。

离线实验最多 6 轮、每轮 3000 输出 token、8 次工具调用、150 秒总时限。最后一轮强制使用提交工具，但**由模型选择哪个已验证候选**。模型不提交时明确失败，不由程序自动选最高分。真实游戏规划仍保留原先 25 秒时限，不因离线实验放宽。

实验结束后，模型选择的方案载入地图并停在起点；点击「播放」查看执行过程。结果保存在：

- `.tmp/sandbox-model-report.json`：提案、API 结果、请求耗时及 token 使用量；不保存隐藏推理。
- `.tmp/sandbox-model-selected-report.json`：恢复模式的最终选择。

若旧实验已生成方案但没有提交，可以重新通过 API 验证旧方案，仅让模型做最后选择，不重新支付生成全部方案的费用：

```powershell
npm run sandbox:reason -- --finish-existing
```

该模式要求现有报告的环境版本、种子与当前沙盒相符。加载方案时若用户已换种子，会拒绝覆盖。界面的手动操作会取消当前自动路线。

## 本机 API

所有 `/api/*` 请求需要 `Authorization: Bearer <沙盒会话 token>`；POST 需要 JSON。服务校验 Host、Origin，不允许跨站或 DNS 重绑定访问，不接收/返回 Foundry 密钥。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/context` | 机制参数、地图、营地、起始英雄、示意兵线 |
| `GET /api/state` | 游戏时钟、位置、血蓝、冷却、存活单位、分账金币、事件、已加载路线 |
| `POST /api/reset` `{seed:741}` | 重建固定起始场景；相同种子可复现 |
| `POST /api/action` `{action:...}` | 下达行动，不自动推进时间 |
| `POST /api/step` `{seconds:10}` | 推进 0.1–180 秒，须为 0.1 的整数倍 |
| `POST /api/evaluate` `{seed?:741,visits:[...]}` | 在指定种子的独立起始环境执行 180 秒，**不改变地图上当前状态** |
| `POST /api/plan` `{seed?:741,visits:[...],model?,summary?}` | 在当前种子起点加载可播放路线；给出不匹配种子则拒绝 |

支持的行动：

```json
{"type":"move","position":{"x":-1454,"y":-3356}}
{"type":"attack","targetId":"从 state.units 读取实际 ID"}
{"type":"farm","campId":"neutralcamp_good_5","targetPriority":[]}
{"type":"cast","name":"luna_lucent_beam","targetId":"current"}
{"type":"cast","name":"item_mask_of_madness"}
{"type":"stop"}
```

`farm` 是对**已指定营地**的低层执行命令：走到中心，按调用方给定的单位名称优先级攻击；没有优先级时按稳定出生顺序。它不判断下一站，也不自动施放技能。显式 `attack` 不自动更换目标。当前逐营地计划 API 仅接受本方营地，手动行动可以探索全图。

路线格式与已有模型工具一致，施法秒数相对**实际到达营地**：

```json
{
  "visits": [
    {
      "campId": "neutralcamp_good_5",
      "targetPriority": [],
      "casts": [{"name":"item_mask_of_madness","seconds":0}]
    }
  ]
}
```

这只是 API 格式示例，不是推荐路线。非法、冷却中、蓝不足或沉默中的施法会记录失败，不会由模拟器挑选更好的时机。动作、空转、刷怪与兵线始终在同一世界时钟下执行。

## 已完成的真实调用记录

使用用户授权的 Foundry 外部配置，核验资源中确有 `gpt-6-astra` 部署；不是从公开模型目录推断已部署。

1. 原实时预算试跑：两次成功响应提出方案，第三次请求因整个任务达到 25 秒而取消。**API 已通，但该试跑没有完成实时路线提交。**
2. 新沙盒：六轮真实提案通过本机 API 执行，耗时约 89.5 秒。野怪金币依次为 **1191、1176、1191、1191、1208、1225**。
3. 这次实验暴露了「用完所有轮数继续改方案、没留提交轮」的问题；已增加最后轮提交约束和恢复模式。
4. 对六个候选重新执行 API 后，由模型选择第 6 个。最后选择的输入显式包含最大生命值，结果 **1225 金 / 180 秒 ≈ 408.3 模拟纯野 GPM**，最低血量约 835.5/1018；包含一次疯脸因蓝不足而失败。
5. 不再调用模型，将同一选定路线在 742–746 五个未参与提案的种子上复跑：**407.0、390.3、404.0、425.3、395.3** 模拟纯野 GPM。该结果不能证明泛化到真实对局，也不能证明全局最优。

可随仓库复现的完整提案和结果见 `data/sandbox-luna-api-run.json`。这是**模型生成的实验记录，不是生产策略模板**；启动沙盒或生产规划时不会自动采用该固定路线。

## 验证与下一阶段

- 单元/API 覆盖：同种子复现、不同时间分块一致、精确刷新边界/占框、施法释放与窗口截断、实际伤害吸血、兵线分账、试验隔离、鉴权/跨站拒绝、地图播放与 API 试验结果一致、模拟模型工具调用。
- 浏览器覆盖：手动清野、模型方案载入与播放、画布渲染、窄屏无横向溢出；不调用云端。
- 本轮真实模型实验与离线测试分开记录，不能用模拟 Responses 的测试替代模型效果验证。
- 最终验证：`typecheck`、**118 项 Node 测试**、沙盒浏览器测试、原 LLM/GSI 浏览器回归、显式旧数值基准浏览器回归均通过。真实模型选择的方案又在正在运行的沙盒中播放到 13:00，页面与 API 同为 1225 野怪金币 / 408.3 模拟纯野 GPM；随后恢复为起点暂停状态供用户播放。

下一阶段应优先校准单次击杀/清营耗时与承伤，再加入环月、引野和水生机制；之后增加线野决策、多种英雄/装备输入和更多未见种子。最后再接回真实游戏截图/GSI与小地图覆盖层，单独测延迟与实战金币。**不因为沙盒分数上涨就声称实战收益上涨。**
