# 双机教练：Plus 实时观战的对手面板、离开视野和守卫提醒

教练端看到的队伍信息、发到游戏机的图层、交给分钟模型的资料，是三件不同的事。只接纳与游戏机本人**同一非零对局号、同一阵营**的新鲜 Plus 队伍视角。自己打游戏的 GSI 不提供敌方全图；错局、错队、延迟或完整观战均不能当作实战来源。

| 想看什么 | 需要的来源 | 游戏机怎样读 |
|---|---|---|
| 对手等级和装备 | 观战 GSI + 本机视觉扫描读到可见敌人的 HUD | 画面左侧是一名英雄一行的**上次读取**，不是实时背包。 |
| 离开己方视野 | 只需 Plus 队伍小地图 | 字幕带最后出现的地点，例如「剃刀 离开视野 · 最后在我方下路一塔大野」。失去视野也可能是阵亡。 |
| 目击的守卫 | 只需 Plus 队伍小地图中的实际守卫实体 | 已校准的小地图上用 ◆ 表示当时目击的点；不是推测，也不等于仍然存在。 |
| 可能的插眼 | 扫描读到敌方携带量减少 + 那段时间的可见行踪 | 最多 3 个黄色眼睛（首选较亮，备选更小更淡）。失去视野 15 秒以上不标点；少了一个也可能是转交、扔掉或卖掉。见[眼位规则与实测](twopc-enemy-wards.md)。 |

## 使用

1. 两端用同版本，通过配对码连接。教练端打开「设置 → Plus 观战与扫描」，一键配置本机观战 GSI，按提示完全重启 Dota。用另一个有 Plus、与玩家为好友的账号实时观战。旧版的 GSI 配置步骤见 [Plus 观战 GSI](twopc-v031-plus.md)（包内 `PLUS-SPECTATOR.md`）。
2. 要读装备、推测插眼：在教练端指定**本机素材工作目录**和装有视觉依赖的 Python，再回主页点「启动视觉扫描」。默认运行教练包所带的扫描脚本，不带 Python、HUD 素材或标定；守卫数量要有 `hud-digits-1080.npz`。保持观战窗口在前台。首次会配置专用 GSI，再按提示重启；按钮显示运行／退出状态，点停止或关闭教练端会结束自己启动的扫描。详见[视觉扫描](hero-scan.md)。
3. 按需勾选「对手等级和装备」「对手离开视野」「可能的敌方眼位」。**新配置默认不推送眼位**。状态行可核对是否有匹配队伍视角、是否在等扫描或本人连接。关掉装备显示，仍可单独显示眼位；关掉推送，不会停止已配置来源的记录，也不会开启模型共享。
4. 装备面板一直显示到本局结束：每个敌方英雄保留上次读到的等级和装备，扫描暂时读不到、Plus 包断一下都只让读取年龄变大，不会消失；换局、换阵营或本局结束才清空。眼位在教练端确认过小地图框时按框画，否则按游戏端「游戏内显示」的小地图位置和大小画。游戏端可分别隐藏字幕、装备和眼位，见[游戏内显示](twopc-game-overlay.md)；已经记录的事实仍可[赛后复盘](twopc-match-information.md)。离开视野／插眼字幕也经本人 GSI 连接送到游戏端，分钟路线显示时不抢占它。连接见[不传画面](twopc-status-only.md)。

扫描默认只切换可见的敌方或仍需辨认的玩家。每约 0.5 秒更新 `%LOCALAPPDATA%\DotaCoach\hero-scan\live.json`，所需图标放旁边的 `icons\`。教练端核对时效、阵营和对局后才下发；游戏端缺图标可向配对教练端取，不接收扫描原始帧。

## 规则

**对手面板**
- 每行：英雄头像、等级、六格主装备（空格显示为暗格）、中立物品，最多 5 名敌方英雄，按选手顺序。
- 装备取最近一次读取：有格子没认出来的那次读取跳过，图纸显示为空格；消耗品、守卫照常显示，和游戏里的物品栏一致。
- 读取满 30 秒标“30秒前”，一分钟后标“N分前”并整行变暗，从没读到的为“未见”。等级快读、目击或收到一份相同的文件不会把旧装备刷新为刚读；小窗口只在内容或年龄标签变化时重画。

**离开视野**
- 敌方英雄在视野里至少待了 3 秒，然后连续 3 秒不在，就提醒一次，带上最后出现的地方，按 7.42 地图命名（[`coach-map-742.md`](coach-map-742.md)）：我方或敌方高地、野怪营地（“敌方上路边缘水生中野”）、塔附近（“我方中路一塔附近”）、肉山、痛苦魔方、前哨、神符、莲花池、智慧神龛、双生之门，其余是上路、中路、下路、河道、我方或敌方野区。地图数据缺失时退回旧的粗分区。
- 视野边缘一闪而过（离开不到 3 秒又回来）不算。同一个英雄 20 秒内最多提醒一次。
- GSI 分不出被击杀和走进迷雾，在视野里被杀也会提示“离开视野”。游戏暂停时不计时。

**对手插眼**
- 同一个敌人两次读取之间守卫少了，就推测这段时间插了眼，按它这段时间出现过的位置和这一队的 7.42 常见眼位，在游戏机小地图上圈出最可能的 1–3 处，到守卫该消失时撤掉；友方看到附近的敌方守卫时也撤掉。
- 交给队友、扔掉、卖掉也算“少了”。两次读取之间敌人不在视野越久越不准，15 秒以上字幕注明“不确定”。详见 [`twopc-enemy-wards.md`](twopc-enemy-wards.md)。

普通 Plus 字幕的时长在教练端「设置 → AI 模型 → 字幕显示」调整（默认 3 秒，1–15 秒）。几条提醒在 0.7 秒内先后到达时合成一条字幕。前一条还在显示时来了新的，会把前一条留在前面一起显示，总长超过 120 字时先丢掉最旧的。

## 实测

- **对手面板的装备**：用 15 段高分局扫描记录（含完整观战真值，共 2,869 次装备读取）回放，把所有英雄都当作敌方。每次新读取之前面板上显示的装备，和当时的真值比：每一格 98.7% 正确，一整行 7 格全对 92.2%（差的主要是两次读取之间刚买、刚换的东西，其次是达贡的等级、侦查和岗哨守卫，以及个别图标相近的物品）。曾试过“连续两次读到一致才更新”，因为跟不上购买，反而更差（每格 97.9%、整行 87.7%），所以改为显示最近一次读取。
- **离开视野**：用 2026-11-17 一局真人 Plus 观战的教练端 Debug 记录（41 分钟游戏时间）回放，按上面的规则平均每分钟约 4.6 条提醒，对线期尤其频繁。之后如果嫌多，可以把“至少待 3 秒 / 离开 3 秒 / 20 秒冷却”调大。
- **7.42 新物品**：重新提取素材后，在官方英雄试玩里把所有新商店物品和当前掉落池的 48 件中立物品放进物品栏读取，新商店物品和中立物品全对，详见 [`hero-scan.md`](hero-scan.md) 的“7.42 更新后的验证”。游戏端安装包的图标要在重新提取之后打包才含新物品；旧包缺的图标会向教练端要。
- **对手插眼**：早期 3 场职业录像模拟视野，首选点在守卫 600 码内占 42%，三个圈最近的占 60%（一直可见时首选点为 67%）。v0.4.8 的 47 场录像重算中，**有画圈的推测**首选点在 600 码内占 82%；是不同数据和口径，不能比较成排位命中率。见[眼位的分组统计](twopc-enemy-wards.md)。
- 2026-11-21 有一局真人 Plus 队伍视角记录，可重放当时的守卫读数。修订后的扫描节奏、当前档案和显示流程没有据此在新真人排位里验收。

## 测试

```bash
dotnet run --project desktop/DotaCoach.TwoPc.Tests -c Release
dotnet run --project desktop/DotaCoach.TwoPc.UiTests -c Release -- .tmp/twopc-ui-<新的目录名>
.tmp/vision-tools/Scripts/python.exe -I tests/hud-vision.test.py
```

第一项检查区域命名、离开视野的计时、冷却、友方和完整观战排除、扫描文件的校验（过期、换对局、非队伍视角、旧版本、非法物品名）、图标只按 Dota 名称读小 PNG、面板的校验（最多 5 人、等级、六格、重名）、面板不续期就消失、字幕合并，以及面板、图标和提醒经真实 TLS 到达游戏端；还用替身脚本检查“启动视觉扫描”的子进程：找仓库和 Python、先 setup、输出逐行到达、关闭标准输入就自己停、不停的被结束。第二项用真实教练窗口和合成的 Plus 数据，确认离开视野进了字幕、扫描的面板和图标推给了游戏机、关掉开关后面板撤回、扫描按钮能启动和停止（替身脚本）且关窗口时一起停；再用真实游戏端窗口确认它取到了面板和图标。第三项检查装备读取规则，以及扫描写出的面板文件（只含敌方、按选手顺序、图标复制到 `icons\`、完整观战不写）。插眼推测和 7.42 地点名的检查分别见 [`twopc-enemy-wards.md`](twopc-enemy-wards.md) 和 [`coach-map-742.md`](coach-map-742.md)。
