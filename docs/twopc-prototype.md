# 双机教练客户端 v0.1.2

日期：2026-11-16（香港时间）。

**最新实际验收：** [Luna本地模型闭环](twopc-model-e2e.md)连续3次通过，已看到真实模型字幕、按校准地图投影的黄色圆环/箭头及过期清除；88项核心检查和27项UI事件检查通过。仅限定本地机器人局实验模式，不等于跨两台物理机器、低延迟体验或实战收益验收。v0.1.2已本机构建，旧v0.1.0发布包未覆盖。

## 本次实现的边界

这是两个独立的 **Windows 11 x64 原生客户端**，不依赖 Node、浏览器或 WebView2。发布包自带 .NET 运行时，解压后运行：

| 机器 | 程序 | 职责 |
| --- | --- | --- |
| 游戏机 | `DotaCoach.GameClient.exe` | 前台 Dota 客户区采集、JPEG 编码、官方自身 GSI 接收、网络传输、私人字幕和画面坐标标记 |
| 3090 Ti 教练机 | `DotaCoach.CoachClient.exe` | 启动加密接收、最新画面预览、可选本地视觉识别、测试字幕/标记回传 |

**基础链路和本地机器人局实验模型闭环已打通，不是已完成的实战自动打钱教练。**

- 首版使用 **最多约 1 fps 的 JPEG 抽帧流**，经 HTTPS 传输；不是 SRT、WebRTC、60fps 连续视频或硬件 H.264 编码。
- 游戏端不运行模型；教练端的本地视觉需要明确点击，且只做观察，不替代完整局势识别。
- “回传测试字幕 / 标记”是**人工联调工具**，不会伪装成模型决策。
- 普通模式不调用云模型。显式 `--local-bot-e2e` 模式可用指定Foundry配置运行真实图像＋GSI推理，并输入历史研究中的六条观察；没有固定路线选择或规则回退。全量案例动态检索、完整路径/收益验证仍未接入。旧实战路线默认关闭状态没有改变。
- 没有读取Steam密钥或自动下载模型。验收模式会读取显式指定的Foundry配置并发生付费请求，只有显式Arm后执行，限制1–6次；详见验收报告。

## 两台机器如何连接

### 1. 在教练机

1. 解压教练端包，运行 `DotaCoach.CoachClient.exe`。
2. 地址选这台机器的有线局域网 IPv4。**跨机不能选择 `127.0.0.1`**；它只用于同机测试。
3. 默认端口是 **TCP 38471**。点击“启动局域网接收”。
4. 如果 Windows 防火墙阻止连接，只为本程序/端口允许**专用网络**入站，最好限制游戏机 IP。程序不会自动修改防火墙、路由器或证书信任库；不要做公网端口映射。
5. 点击“复制配对码”，安全地传到游戏机。配对码包含连接密钥和服务证书指纹，**不要发到公开聊天或日志里**。

### 2. 在游戏机

1. 解压游戏端包，运行 `DotaCoach.GameClient.exe`，粘贴配对码。
2. 第一次先选 **“诊断画面（不采集桌面）”**，点击“连接并开始”。
3. 教练端应显示明确写有“非游戏画面”的动态测试图。
4. 在教练端点击测试图左下角，输入短句，点击“回传测试字幕 / 标记”；游戏端的预览和字幕栏应显示结果。它不是一张真实 Dota 地图。
5. 测试通过后停止连接，改选“Dota 2 前台画面”，重新连接并确认采集，再切回 Dota。
6. 切出游戏时暂停采集并结束旧会话，回到游戏时重新建立会话；不会截取其他前台应用。

两端停止或退出即可断开。教练端重启、撤销配对或改变配对地址后，需重新复制配对码。连接失败不会不断重试或静默换到别的服务。

### 3. 配置自身 GSI（推荐，但不是视频传输前提）

游戏端连接一次后会尝试启动 **仅监听 `127.0.0.1:3219`** 的官方 GSI 接收器：

1. 点击“导出本次 GSI 配置”。
2. 把文件放到**游戏机**的 Dota 安装目录：
   `game/dota/cfg/gamestate_integration/gamestate_integration_dota2_coach_twopc.cfg`。
3. 如游戏没有加载新文件，重启 Dota 后在自定义局验证。
4. 此版 GSI 密钥只在本次游戏端进程有效，**游戏端重启后需重新导出配置**。不覆盖你已有的其他 GSI 配置。

网络只携带白名单内的自身英雄、阵营、时钟、血蓝、可用位置、装备、技能。GSI 身份、昵称、认证字段、旁观者嵌套玩家数据及任意全图字段不会转发。不存在的信息保持未知；没有 GSI 时也不会假装已经可靠识别全部自身状态。

### 4. 教练机上的本地视觉（可选实验）

- 服务地址固定为教练机的 `http://127.0.0.1:11434`。若模型跑在 WSL，先自行确认 Windows 能访问该地址；无需向局域网暴露模型端口。
- 输入**已经安装**的 Ollama 视觉模型名称，点击“识别最新游戏画面一次”。
- 先检查本地模型元数据，必须是具备 vision 能力的 GGUF 模型；有 remote/cloud 标记时拒绝发送图像。
- 不下载模型、不访问云端视觉、不读取 API 密钥。每次由用户明确点击，最多一个识别请求在执行。
- 结果是未经游戏专项准确率验证的**画面观察**。只有点击“回传本次观察字幕”且原始画面仍有效时才会显示在游戏端；不生成地图目标或刷钱路线。
- 断线、换局、阵营/英雄变化、时钟回退或结果过期时，旧观察不能变成新的有效提示。

3090 Ti 的实际推理延迟、显存、功耗没有在本次验收中测量。游戏端仍有 GDI 采集、缩放和 JPEG 编码成本，**双机不等于零开销**。

## 字幕与标记

- 真实游戏模式中：显示透明、鼠标穿透、不抢焦点的**私人悬浮层**。不会修改游戏引擎、读写内存、发送键鼠操作或向队友 ping。
- 普通人工联调标记来自预览中的归一化画面点选。机器人验收模式则由模型选择真实地图地标ID，服务端校验阵营并投影到已校准的小地图；不是人工填点，但也不是完整导航路径。
- 同一来源画面经过等比例缩放，标记按原游戏客户区尺寸还原；尺寸变化会使旧标记失效。
- 当前仅验收1280×720默认左下小地图；其他布局、动态资源和完整通行路径仍待验证，不能用单个地标投影冒充已完成的自动导航。
- 首版只声明窗口/无边框模式为目标测试模式；独占全屏、HDR、多显示器 DPI 和真实游戏覆盖效果仍需两台实际机器验证。

## 隐私、时效和失败行为

- 完整客户区可能包括游戏聊天。当前捕获是前后检查 Dota 前台状态的屏幕区域采集，**不是隔离窗口的 Windows Graphics Capture**；系统通知/遮挡层可能进入画面。应用启动真实采集前明确确认。
- 普通模式不录音、不写视频或截图到磁盘，只保留当前 JPEG 和有界元数据。显式验收模式另存有限的模型输入、覆盖层证据和白名单日志到指定私有目录，不打包这些文件。
- HTTPS 使用每次服务启动新生成的身份；游戏端严格校验配对码里的 SHA-256 证书指纹。没有“忽略所有证书错误”的开关，也不自动信任系统证书。
- 配对码仅接受局域网/本机 HTTPS 数字 IP 地址；不使用 URL 中的密钥，不跟随重定向。
- 先领取服务器短期采集凭据，再采集和上传。凭据 3 秒失效；画面序号必须前进，凭据不可重复使用。
- 两端使用单调时钟和相对时限，不要求两台机器的系统时间完全同步。
- 接收画面停止超过 4 秒时，预览和提醒不再有效；单条提示还受到来源画面最多 12 秒及发布后最多 8 秒的双重上限。轮询不会续命。
- 新会话、尺寸/来源/阵营/英雄/比赛变化、游戏时钟回退、英雄死亡均撤回旧提醒。没有新鲜 GSI 时不借用之前已失效的自身数据。
- 回传类型有 `manual-link-test`、`local-vision-observation`，以及只允许本地对局自身状态的 `experimental-bot-advice`；不会接受伪装成已验证最优路线的消息。

## 开发、打包和测试

在仓库根目录执行（需要 .NET 10 SDK）：

```powershell
dotnet run --project desktop/DotaCoach.TwoPc.Tests -c Release
dotnet run --project desktop/DotaCoach.TwoPc.UiTests -c Release -- .tmp/twopc-ui
dotnet run --project desktop/DotaCoach.GameClient -c Release
dotnet run --project desktop/DotaCoach.CoachClient -c Release
powershell -File desktop/build-twopc.ps1
```

打包脚本生成两份独立、自带运行时、**未签名**的 ZIP 和 SHA-256 清单。拒绝覆盖已有输出；重打包请指定新的 `-OutputDirectory`。

测试分层：

1. 协议测试：配对码、证书固定、认证、JPEG 尺寸/上限、凭据重放、序号、生命周期、状态变化、数据白名单。
2. **真实本机 TLS 往返**：不是用 mock 网络证明通信。
3. 官方 GSI 接收器：真实 HTTP，认证与菜单失效。
4. 本地视觉：fake HTTP handler 验证调用约束，**不是实际模型准确率测试**。
5. 两个实际 WPF 窗口的 UI 事件回归：诊断 JPEG 持续传输、预览解码、字幕/标记、清除、过期、撤销、重新配对及退出。

最新本机验证：**88项核心/协议/模型约束检查、27项WPF UI事件检查通过**，另有3条真实Luna模型闭环及实际像素证据。早期版本还跑过186项Node测试、418条旧桌面核心断言和TypeScript类型检查；这些不冒充本轮重新执行的结果。

这些仍是**同机双角色**测试。真实模型响应、实际游戏字幕和标记均已核验，但不是视觉准确率评测、两台物理机器测试或实战收益证明。最新证据、剩余延迟问题及复现命令见[Luna验收报告](twopc-model-e2e.md)。
