# 每日打钱和出装录像记忆

Codex 桌面端的本地计划任务 **「Dota 2 每日录像复盘」** 按香港时间 **00:05 主跑、02:05 和 04:05 补查**。每天的目标是露娜 `luna`、巨魔战将 `troll_warlord`、斯温 `sven` **分别 20 场新复盘**。补跑仍按香港日期计数。若不足即报告实际数量，失败不计，不卡住另外一个英雄。同一英雄同一场不跨日重复入库；两个英雄同场时复用一份 DEM，各自核对玩家、抽取装备和收益、独立复盘。

## 运行与查看

```powershell
# 查看今天已入库的局数（只读，不发模型请求）
npm run replay:memory -- --status
# 按明确版本/英雄读取；例如：
npm run replay:memory -- --patch 7.42 --hero sven
# 只看一场中的指定分钟：15 表示 15:00 起，不是 14:00–15:00
npm run replay:memory -- --patch 7.42 --hero troll_warlord --match 9098789898 --minute 15
# 找“有线但敌方全消失”或“远处真的交手”的历史对照，再按返回的局号、分钟打开
npm run replay:memory -- --patch 7.42 --hero troll_warlord --situation all-off-map
npm run replay:memory -- --patch 7.42 --hero troll_warlord --situation distant-contact
```

在桌面端 **Scheduled（计划任务）** 中查看、暂停或手动运行「Dota 2 每日录像复盘」。使用本地项目 `C:\g\dota2-coach`，不要选云端或隔离工作树：受信任的解析工具在此工作区，`Z:` 是教练机当前用户映射的盘。保持教练机开机、用户登录（可锁屏）、桌面应用运行，时区为 UTC+8。缺网或 Z 盘不可用时不得改用 C 盘。Codex 只负责调度和报告；解析、Copilot 模型、去重和每日账本仍由原研究脚本负责。已满额不再发模型请求。

任务名、重复规则、执行模式、工作目录、提示词在 [`scripts/replays/codex-daily-schedule.toml`](../scripts/replays/codex-daily-schedule.toml) 中有留档，便于换机重建。不要再注册 Windows 任务 `DotaCoach-Daily-Replay-Study`。如需在终端手动补跑，执行 `npm run replay:daily`（只启动一次研究，不安装计划任务）。暂停计划不删除已存记忆。

可信 Node 和安装了 `gem-dota==0.14.0` 的 Python 分别在仓库 `.tmp\postgame-replay-v2\node`、`.tmp\replay-tools`。本机 Codey 需能读取当前用户的 `CODEY_MODEL_API_KEY`；密钥不写入调度配置、研究盘或解析器环境。

## 什么才计数

1. 每轮都向 Valve 重新确认最新已发布的**精确补丁**，包括字母小版本。优先查近期比赛；稍早的比赛须仍属当前补丁且有可核验的录像。公开 D2PT 目录要求精确版本；没有精确标签时，Valve 若只给 UTC 发布日期则排除当天。可取得 OpenDota 的大版本编号及上线时刻时，再与比赛元数据交叉检查。提交结论前再查 Valve，一旦换版就停止向旧版发布。
2. D2PT 天梯样本须为一号位，对局平均 MMR ≥ 8000 或该英雄玩家榜单前 200。同一高分大厅也能提供另一位明确的一号位，不能把队友排名当成该英雄排名。OpenDota 以公开的英雄职业赛事、英雄榜玩家天梯历史和高段位对局为候选：赛事必须是有 `professional` / `premium` 分级的赛事大厅；公开天梯须独立确认该英雄玩家为榜单前 200。**“职业玩家”标签、英雄积分、冠绝图标都不能单独入选。**
3. 用原始 Valve 下载包、DEM 和元数据的 SHA-256 核对本地副本，解析至终局，校验比赛 ID、时长、英雄/队伍、实际 build、十人最后补刀。不猜 replay salt，不把网页表格充当录像。以**游戏时钟每 60 秒**为复盘单位，各分为 **`:00–:30` 和 `:30–下一整分`**。半段记录新增补刀、兵线/野怪金币分项、叠野计数的变化、本体端点坐标；整分钟另记净资产与装备。装备主栏首见不等于购买；角色经济计数包括受控单位。
4. 模型仍为本机 Codey 的 **GitHub Copilot / `gpt-6.2-sol` / `xhigh`**，每英雄每场一次请求，不按分钟重复提交。新研究不再是“每分钟限一句话”：每个实录分钟（含末段）和能定位的线野切换、跨营补刀、地图危险或机会变化，都有带己方视野的暂停点。模型必须给每个点写独立判断、另一种具体打法、风险收益与改判信号，另写带证据的出装和发育观察。详细模式使用模型目录核实的输出上限（最多 128,000 tokens，**是上限不是用量**），保留答复实际 `usage`。重复/遗漏、证据不全、答复截断或引用不存在的局面，一律不作为完整复盘入库。每天每英雄仍最多 20 个模型预约；同一份已发请求无回执不盲目重发。

### 把战争迷雾放回决策里

- **决策前**：从原 DEM 的己方 `CDOTA_DataRadiant/Dire.m_bNPCVisibleState` 位图，在完整网络包处理后按约一游戏秒采样。按出场英雄外观汇集可见标记；不从多个相同标记里挑真身，也不把死亡状态的标记算作当前活人。`hidden`、缺少位图/英雄身份的 `unknown`、`visible` 分开；只有可见标记才导出坐标。`lastSeen` 是过去最后一次**单一标记**的位置与年龄，不沿着敌方真实轨迹外推。不知道玩家是否看了小地图、语音沟通、未露头的 TP 或眼位；这不是客户端画面的像素复刻。
- **远处打架不是“几个人站在一起”**：先要求己方可见的敌我英雄类伤害/死亡日志，再用事件当时或之前不超过 1.5 秒的双方位置，要求相距不超过 1500 且敌方没有多个同名标记才定位。卡片列最近 15 秒的对手、队友、最后交手距今多久、打点离己方英雄/候选兵线多远。全图打架但己方没观察到不算；记录已过时、还有先手没出现或对方能回防都可能翻转结论。没有证据≠没有打架。
- **候选目标**：只比较从己方视野实际采到的敌方线兵/中立怪；`null` 不能读作空线/空营。列最近目标的直线距离、同组可见单位血量和毛赏金区间、最近己方塔和存活队友离目标多远。线兵按最近兵周围 600 单位分组，不声称是整波；野怪有可用 spawner 时按其分组。直线距离不是可走路程；赏金不是确定到账。看不到线时允许参考近 45 秒内最后采到的附近线兵，但要注明陈旧程度。保留自己的血蓝、装备/技能及冷却字段、此前已结束的半分钟线野实得与装备主栏首见。
- **事后单列**：回放可以帮我们选暂停时点，却不能替教练选答案。提交给模型的是乱序的己方局面，不提供局号、选手排名、胜负、暂停点为何选中、下一次补刀、未来收益或全图坐标。每个点只能用本卡已有线索；同场多卡一起审，不等同于每个暂停点单独隔离盲测。模型判断保存后与实录下一次本体补刀类型、随后最多 30 秒的经济作对照。`different-family` 只说明首选与下一笔补刀不同，**不代表选手犯错**；停手/转移/掩护不以补刀评好坏。区间可能重叠，不能跨点相加。
- **粒度与索引**：每分钟至少一张卡；分钟内可有多张。最长 30 秒内相邻的、可区分的本体线野切换全部定位；同 tick 同时吃线野不编先后。跨营需死亡 tick＋单位名唯一指向营地；另外标记附近有线且敌方全不见、近处出现威胁、远处新交手等窗口。同种地图信号抖动 15 秒内不重复触发；这些距离/时间是查找样本的口径，不是游戏规则或安全阈值。无法识别每次走位或鼠标指令，不会替玩家编动机。

**实战对照（7.42 巨魔 `9098789898`，夜魇视角）**：7:17.4 有兵，但巨魔 419/880 血，沙王最后露头仅 1 秒、距候选兵约 114，适合等视野而不是从 1246 外靠过去。14:00.4 满血，沙王和小鹿刚在远处与虚无之灵交手；4 个可见线兵距 924、毛赏金 151–175，2 只可见萨特距 1051、32–38，倾向先接这波而不是先刷萨特；帕克有多个同名标记，小强未露，不能据此一路摸塔。15:36.4 己方根本没采到敌方线上兵，不能拿观战图的“更近”替回线找理由。21:35.4 又是全消失，但候选兵距己方塔只有 209，宜把“塔侧先收一波”与“跟下一波深入”分开评。这四条在 Z 盘按证据哈希锚定，来源 `codex-offline-case-study`，不是历史 Copilot 答复。

### 分钟证据的边界

`<matchId>:<hero>:m15` 对应 15:00–16:00，`:a` 和 `:b` 分别是前、后半分钟。收益用累计值作差，切点取整分/半分或其前最近的有效快照；开局用鸣锣后首个样本，终局用最后实录值。`sampledFrom` / `sampledTo` 保留实际采样时刻。末段标 `partial`，不补零、不折算成整分钟，也不进完整分钟的跨局中位数。

半分钟是**出兵节奏的参照，不是被击杀小兵所属的波次**。整分也不代表某个营地实际刷新。另按扣除暂停的战斗日志时间统计该英雄击杀敌方线上兵/中立怪的已记录事件，区分本体、幻象、归属未知，排除反补；缺少日志时为 `null`。`bodyOrder` 表示已确认的本体补刀类型顺序（`L` 线、`N` 野、`L+N` 同 tick 无法排序），不是英雄行走路线。坐标或金币不能证明清了哪座营、选手的视野或意图。

旧案例的五分钟 `:wN` 文字观察和原始模型答复永久保留，不会冒充新的 `:mN` 解读。`npm run replay:memory:backfill-minutes -- --patch 7.42` 可在研究任务空闲时从已有、校验过哈希的逐秒事实离线补建分钟证据，不下载、不调用模型、不改当日配额。分钟查询对这种案例返回 `source: verified-facts-backfill`、`modelReading: null`；有新模型逐分钟解读的则是 `minute-model-review`。`minuteEvidenceCases` 与 `minuteReviewedCases` 分别报告两种覆盖程度。

`npm run replay:memory:backfill-fog -- --patch 7.42 [--hero troll_warlord --match 9098789898]` 可从已经核验的本地 DEM 单独补建己方视野与决策证据，不用付费重评、不改旧档。分钟查询的 `decisionSource: team-dem-backfill` 表示仅补证据，`modelJudgement: null`；新模型完整复盘的则是 `team-view-decision-review`。`fogEvidenceCases`、`decisionPoints`、`reviewedDecisionPoints` 分别是有迷雾证据的英雄案例数、暂停点数、已获详细模型评判的点数。每张点的 `before` / `after`、可选 `offlineCaseNote` 与 `modelJudgement` 来源分开。

### 技能威胁：先说明谁能打到，再报数字

新复盘对每个暂停点另写 `threatRead`：点名相关的敌方先手和跟进者，比较施法距离和最后目击地点，核对蓝耗、冷却、自己能否在控制前用道具。不是把五个英雄的满级技能相加。每条判断引用本卡有效依据，并在有数值依据时给一个程序能逐字段复算的 `threatMetric`（区分打在自己还是队友、实测还是某等级的基础值）。错误目标、技能、等级档、数值或未来事件均不能作为有效数字入库。

- `spellRules` 来自与 **DEM 服务器 build** 匹配的 Valve 游戏文件。准备器核对同一不可变提交的 `steam.inf`（ClientVersion/ServerVersion）、英雄目录 Git tree、每个 hero/item 的 blob；本地文件只在字节哈希相符时复用。记录原始伤害类型、逐级基础伤害、控制、蓝耗、距离、冷却及条件分支；未学、天赋、魔晶/神杖不能默认为已生效。`7.41f` 的旧战斗表不能给 `7.42` 报数。若新 build 无法核实就不报面板数字，保留该局己方能见的实测，绝不套上一版。
- `spellThreatBefore` 的敌方蓝量/英雄等级只来自**过去一次单一且存活的可见外观**。己方可见的技能施放与命中分列；实际录像的施法事件常无阵营字段，此时仅按已经确认的敌方阵容署名归类（`roster-label`），不提供隐藏位置、真假身或实际剩余 CD。`castRankReplayAudit` 是该次施放的引擎等级，只供复盘核验，**不进入模型的事前卡片**。把一份施放记录的等级当作此刻已知加点是错误的。
- `strongestObserved5sInLast90s` 汇总同一段不超过 5 游戏秒的伤害，只计己方可见、明确打在焦点**本体**的对手英雄署名日志；保留组成、伤害类型、次数、起止和当时防具。它不包含塔/兵或其他未归属伤害，不是净扣血、预期爆发或必杀线。控制按该本体实录、可配对的 stun 添加/移除求区间并集；沉默/减速不是眩晕，未能配对也不凑时长。
- `spellBaseScenarios` 是**条件算术**：一次可见施放按各档原始 CD 起算，不假定敌人期间没再用；最近实测爆发中的两个主动技能若要重新各放一次，比较基础耗蓝与最后一次看见的蓝；对魔棒、仙灵火只计有记录的格数和冷却，估算可按出的治疗时才按生命上限封顶。没有可靠状态时，不猜有效魔抗、护甲、增幅、减疗，不把一次雨滴格挡当常驻额外生命。
- 7.42 巨魔 `9098789898` 可重查 **7:17.4**：之前 6:33.87–6:38.27 本体留下 562 点日志伤害，其中沙王穿刺 58、小强穿刺 116、沙暴 21×11；附近两段实际眩晕去重共 2.667 秒。当前 419 血，但沙王最后仅 156 蓝，同时新付两招至少 185；巨魔已有雨滴和 12 格棒。这是“不为两只兵走进双控范围”的理由，不是“沙王一穿必死”。同场 **14:00.4、15:36.4** 另存了不同局面的条件判断。

```powershell
# 一次性准备可核验的公开规则；新 build 在主跑时也会尝试查证
npm run replay:spell-rules -- --patch 7.42 --build 6988
# 为旧案例补技能目击/伤害实录：仅已存 DEM 和已备好的本地规则，不下载或调用模型
npm run replay:memory:backfill-spells -- --patch 7.42
# --minute 7 返回 7:00 起的决策，包括 7:17.4；事前、事后等级核验和文字判断分开返回
npm run replay:memory -- --patch 7.42 --hero troll_warlord --match 9098789898 --minute 7
```

`spellEvidenceCases` / `spellDecisionPoints` 仅表示证据已建，`spellReviewedCases` 才是该协议完整模型复盘的局数。人工逐段核对的 `codex-offline-spell-case-study` 不会计作 Copilot 新评；局号、版本和原始旧记忆不变。

## 数据与教练读取

所有研究产物、日志及解析临时文件在 `Z:\dota2coach\data\daily-study\`。盘未挂载或空间不足不切换到 C 盘。不自动删除历史记忆或已核验的原始回放；空间占用随采集增长。

| 位置 | 内容 |
| --- | --- |
| `raw\<matchId>\` | 压缩原包、DEM、OpenDota 元数据、校验清单；可复用同盘已核验录像 |
| `catalogs\`、`evidence\<补丁>\<英雄>\<matchId>\` | 资格来源快照、解析事实、模型输入依据和已核验答复 |
| `memory\<补丁>\<英雄>\matches\<matchId>.json` | 长期单场记忆：资格、模型、出装和打钱观察、证据窗口 |
| `memory\<补丁>\<英雄>\farm-minute-v2\<matchId>.json` | 为旧案例单独补建的实录分钟序列及源文件哈希；没有新的模型文字 |
| `evidence\<补丁>\<英雄>\<matchId>\team-map-v2.json` | 己方包边界地图采样与己方可见交手日志；不写隐藏敌方当前位置 |
| `spell-rules\<补丁>\<build>.json`、`spell-rules\sources\` | 公开技能与防具的版本化定义、原始 KV 和校验依据 |
| `evidence\<补丁>\<英雄>\<matchId>\team-spells-v2.json`、`memory\<补丁>\<英雄>\spell-threats-v2\<matchId>.json` | 己方实际见证的施法、受到的伤害及本体资源；逐决策的证据与定义快照。`spell-field-notes\` 独立保存带哈希的案例判断 |
| `memory\<补丁>\<英雄>\fog-decisions-v2\<matchId>.json`、`field-notes\<matchId>.json` | 旧局补建的前后对照；独立撰写的案例注明来源和决策证据哈希。新模型的全场逐决策评判归入不可覆盖的 `matches` |
| `memory\<补丁>\<英雄>\coach.json` | 汇总样本数、装备首次持有中位数、终局保留装备的常见先后顺序、每个完整分钟及两个半段的补刀和线野收益中位数、带出处和原始粒度的教练问题 |
| `runs\<香港日期>\status.json`、`events.ndjson` | 今日目标、已完成数、当前阶段、失败原因和各次尝试；`tmp\` 是研究临时区 |

教练代码可以调用 `readCoachMemory(patch, hero)` 或 `readCoachMinute(patch, hero, matchId, minute)`；已认证的本机沙盒提供只读 `GET /api/farming-memory?patch=7.42&hero=sven`，追加 `&match=<ID>&minute=<分钟>` 可取单场分钟证据。未建库的补丁/英雄不会回退到旧版本。`lessons` 可提供给 `visibleFarmingContext` 作为**历史**案例，不会把全图轨迹当作玩家当前视野，也不自动接管游戏。每个问题都能用 `matchId` 与 `evidenceIds` 回到原始时间段。样本频率是观察结果，不是最优出装或路线的证明。
