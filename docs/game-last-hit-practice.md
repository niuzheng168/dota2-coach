## 自己对线、补塔刀：纯画面档

- 用 `--lane-vision` 快捷方式打开面板，或选 **我的对线 · 纯画面 / 塔下节奏**，点 **显示小兵血量**。首次建议低负载档（上限 60 FPS）。只识别前台 Dota 客户区里的默认红／绿普通兵条，不需 GSI，不读英雄属性、实体 ID、游戏内存、回放、观战或远端数据。此档不检查比赛类型或英雄等级，请在自己的玩家视角使用；切出或停止就撤下数字。技术上可用于自己的匹配／天梯窗口，不代表获得 Valve 对第三方工具的许可。
- **只显示 HP，不显示百分比。** `近≈275 HP` 表示这只近战兵当前约有 275 血；`近≈275 / 远≈150 HP` 表示兵种未定，同一根血条按两种满血基准各能换算成多少，不是两只兵。兵种和节奏均确认后，`近≈275 → 181–210 HP · 0.65s` 表示约 0.65 秒后**若再吃同样一击**，预计剩 181–210 血，不是现在就该出手。不会拿未确认的兵种做单值预测。
- 默认基准已核对本机 Dota build **6980**：`game/dota/pak01_dir.vpk` 中 `scripts/npc/npc_units.txt` 的 `StatusHealth`，天辉／夜魇的普通 `melee` 均为 **550**，普通 `ranged` 均为 **300**。原文件 SHA-256：`8c03a13181777495ce46dbb5c183a5ecd14281eb040b4c29e9d3157da302fdb7`。这是**基础**满血；强化单位有单独配置，不能认定每波或每个特殊兵都是同一数值。程序不读取游戏时钟或自动识别兵营状态。如果实际波次的血量不同，可在停止显示后按游戏面板修改「本波满血」再开始；这两个值应用于本次识别的双方普通兵，不能同时拟合不同升级状态的两队。
- 预测依据是同一轨迹上两次**实际掉血**的幅度及间隔（目前针对约 0.8 秒的早期塔下节奏）。不从第一击承诺下一击，也不把伤害来源当作已确认的塔。换目标、重叠无法匹配、明显混伤、多目标竞争、长断帧、下一击到期却没来时撤预测。其他单位若打出了**相同幅度和节奏也可能触发**；塔改仇恨但尚无画面证据时也可能给出过时估计。不预测首发弹道、不保证击杀归属。
- 稳定目标优先验证原位置的边缘和填充；移动时查附近，约每 30 ms 按来源时间重新找新兵，跟丢时当帧重新找。检测总是读取本帧像素。被一条遮挡线干扰时需要两条一致的独立扫描线及底边；对已跟踪的低血目标，三条同阵营扫描线确认才接受最后一像素。连续掉血不再人为等待 16 ms 再通知界面；若绘制跟不上只处理最新值。兵群挤不下长预测时先保留短血量。缩放、颜色设置、重叠、仇恨转移、高地和特殊兵仍有漏读或误判的可能。
- `--measure-lane-vision` / `--measure-lane-vision-fast` 是**主动启动**的本机测量（约 30 秒，60/150 上限），用同一采集器。JSON 里的 `ObservedHealthLosses` 和 `HealthLossToFirstWpfDraw.Count` 需一起看，没画出的掉血不算零延迟；这个延迟从首次采到发生掉血的画面算起，不含它出现前的等待，也不等于显示器出光。没有必要开第二个抓屏工具。
- [HP 版验证与旧版历史对照](../benchmark-results/lane-vision-2026-11-19/README.md)。可用 `--lane-vision-e2e` 测试从输入像素到渲染后的读数、以及第三次受击后的 HP 是否落在预测区间；测试不是天梯实测。

## 露娜试玩：估算绝对 HP

1. 打开游戏端的「本机练习：小兵血量」（`--practice` 快捷方式直接展开）。默认关闭，打开面板不会采集。点 **显示小兵血量** 才启动。默认低负载档上限 60 FPS，另有手动 150 FPS 档。独立练习不用点「连接」。
2. 在窗口或无边框模式下，进入 **英雄 → 露娜 → 试玩**，使用默认血条、开启小兵。保持一级空装（TP 可以）、白天、未暂停，时间在前 7 分半。首次配置自身 GSI 后，如提示重启，请在 Dota 启动选项加入 `-gamestateintegration` 并完全重开游戏。正式对局、观战或缺少自身 GSI 时不运行这个识别器。
3. 数字紧贴兵条，优先放在上方。半血时，近战兵显示 **近≈275 HP**，远程兵显示 **远≈150 HP**；未知则并列两种 HP。原生红绿血条保留，不额外画彩框。若没有不挡血条的邻近空位，则略过该数字。切出、缺少新鲜画面或点 **停止显示血量** 会撤下标记。

## 数字的含义与限制

- 只用 Windows.Graphics.Capture 获取前台 Dota 窗口，在本机未编码的 NV12 图像中测量红绿兵条内部的填充像素数。剩余 HP = 满血 × 填充长度 ÷ 内部宽度，最后一步才舍入；下一击的预测同样直接用 HP 向外取整。**不是读取单位的精确 HP**。若兵条内部宽 78 像素，默认近战每像素就相当于约 7 HP。
- 兵种推断沿用持续交战的双方前后排阵型，或同一敌兵连续两次符合一塔的掉血幅度和间隔。不单靠一根兵条的位置猜兵种。轨迹交叉、消失、长时间断帧不沿用旧身份，矛盾证据会退回近／远两种 HP。数字本身不依赖露娜攻击力、距离、弹道或出手冷却。
- 有遮挡、血条只剩极少像素时可能读不到；不保证能识别特殊兵、车兵、超级兵、所有皮肤或非默认 HUD。HP 模型只适用于上述普通兵练习条件。
- 独立的「手动试算」仅对手填的出手距离、兵种、HP 和塔弹时间计算。它不影响游戏内数字，也不需要启动采集。

## 开销和验证

- 窗口采集在 GPU 缩放和回读前限流，低优先级线程只处理新帧。数字共用可复用的小块透明窗口和字形缓存，不另采桌面、不用全屏绘图窗口。面板的「供帧 / 检测 FPS」是采集源交付与识别的新帧率，**不是 Dota 的渲染帧率**。提高检测上限不保证游戏不掉帧。
- 对局中不要再开第二个抓屏工具做验收。纯离线测试如下，图形测试只在内存位图上软件绘图，不打开窗口或采集游戏：

  ```powershell
  dotnet run --project desktop/DotaCoach.TwoPc.Tests -c Release -- --last-hit
  dotnet run --project desktop/DotaCoach.TwoPc.UiTests -c Release -- --offline-practice
  ```

- 只有主动选择测量时，才使用游戏端 `--measure-last-hit`（60 上限）或 `--measure-last-hit-fast`（150 上限），检测到有效试玩后预热 2 秒，输出约 30 秒数据。`--measure-last-hit-long` 和 `--measure-last-hit-fast-long` 延长至约 5 分钟。它们只使用游戏端自身的采集器；如要测游戏 FPS，需另做同场景关／开的对照。
- `latencyMsTotal` 分别统计从新画面到算出血量（`FrameToReadout`）、到 WPF 提交绘制（`FrameToWpfDraw`）、每个发生变化的读数从首次观测到首次绘制（`ReadingChangeToFirstDraw`）。后者需与 `ObservedReadingChanges` 对照：来不及绘制或没有位置的读数不能算作零延迟。超过 50 ms 的画面不用于发出新标记；这不是对每次可见更新的 50 ms 保证，WPF 绘制时间也不是屏幕实际出光时间。

历史数据：[旧版 4K 游戏机采集/检测率](../benchmark-results/last-hit-240-2026-11-18/README.md)、[旧版补刀决策的离线延迟](../benchmark-results/last-hit-latency-2026-11-18/README.md)。两者都不是当前多兵血量显示的实战帧率或准确率。
