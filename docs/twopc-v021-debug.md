# 双机教练 v0.2.1：Debug 抽帧与运行记录

> **v0.3.0已更新数据流**：普通模式持续H.264视频由教练端抽帧；日常只开教练端Debug，游戏端不重复存图。以下两端存JPEG的描述仅适用于v0.2.1历史实现。当前说明见 `twopc-v030-video.md`（v0.3.0包内README）。

普通对局自动教练、字幕和地图功能仍默认开启。模型配置、GSI和4K校准的首次使用方法见包内 `NORMAL-USE.md`。

## 开启 Debug

1. 在**游戏端和教练端分别**展开“Debug / …”区域。
2. 勾选“Debug：保存抽帧图片与运行日志”。建议先开两端再复现问题。
3. 路径及已写入大小、图片数、丢弃数会显示在界面。点击“打开 Debug 目录”可定位本次文件。
4. 取消勾选或关闭客户端，会停止并排空写入队列。客户端退出后不会在下次启动自动录制。

Debug是单独的隐私开关，**默认关闭，不改变自动教练默认开启**。不需要调试时不保存这些图片。每台机器默认根目录为：

```text
%LOCALAPPDATA%\DotaCoach\Debug\
  20261116-...-game-<随机ID>\
  20261116-...-coach-<随机ID>\
```

它只保存本机，不自动上传。共享给开发者前，请自己检查游戏聊天、昵称和其他画面内容；**图片本身没有自动打码**。

## 每个目录包含

```text
session.json       客户端版本、进程、开始时间、限额与隐私说明
events.jsonl       每行一个事件，可直接按 sessionId / sequence / reminderId 关联
frames/*.jpg       抽帧和模型输入实际使用的JPEG，文件名包含内容散列
summary.json       正常停止/触及限额后的统计与停止原因
```

- **游戏端**：保存捕获到、准备传输的JPEG；记录上传完成、接收提醒、提醒清除、覆盖层绘制回执、错误及周期状态。
- **教练端**：保存实际收到的帧，冻结预览也不停止Debug；记录模型真正使用的原始帧、结构化结果、耗时、token、发布或拒绝原因。
- **周期状态**：约每2秒保存连接状态、自身GSI、模型状态/次数、已返回的token统计、校准信息、内存和CPU累计耗时。
- **GSI结构摘要**：只记录已知区段是否存在、是否出现嵌套队伍/观战结构、是否被自身状态解析器接受；不保存旁观者隐藏字段的值。
- 错误只保存操作类别、异常类型和错误码，**不保存可能含请求地址/密钥的原始异常文本或HTTP响应**。

帧是实际传输/推理的压缩JPEG（当前最大1600×900），不是4K无损原图。原始3840×2160等客户区尺寸会另存，因此可以排查源像素、JPEG和DPI混用。重复引用同一帧会复用JPEG文件，但保留每一次模型输入的事件。

普通模式的JPEG通常不含我们的覆盖层；`overlay-rendered`是绘制回执，**不是截图像素验收证明**。不要把这类回执当成已经看到真实字幕/标记的证据。

## 限额和失败处理

- 每次Debug最多2GiB、2小时或7200次图片记录（包含模型输入引用），先到者停止。
- 异步队列有界，磁盘慢时丢弃新日志而不阻塞游戏传输，并显式增加丢弃计数。
- 磁盘写入失败只停止Debug，不关闭正常采集或模型；部分已写入文件保留。
- 不删除旧Debug目录，不清理用户其他文件。多次测试产生的旧目录需自行检查后清理。
- 意外结束进程时可能没有`summary.json`，也可能存在已写图片但尚未写出的事件；不能将“没有错误日志”当作运行成功。
- 两台机器的UTC时间可能不同步。优先使用共享会话ID、帧序号、图片SHA-256与提醒ID关联，不能直接把两边UTC相减当精确单向网络延迟。

结构化日志不包含Foundry密钥、配对码、GSI认证token、捕获票据、原始GSI、昵称/SteamID字段或完整HTTP请求。模型文字会过滤常见凭据格式，但画面/模型输出仍可能涉及游戏聊天等私人内容；**不是可直接公开的匿名数据集**。

## Dota Plus 实时观战与GSI

Valve官方Dota Plus功能说明提供的是：无转播延迟地观看**好友的队伍视角**。这不是“获得全部对局实体信息”的接口承诺。

- 观战画面的队伍视野，与GSI实际返回的字段范围是两个问题。
- 即使观战GSI比玩家自身GSI多，也不能假定包括所有兵线、野怪、刷新状态、树木和完整通行信息。
- 更不能因为画面保留迷雾，就假定GSI的每一个字段也已经按同样规则过滤。
- 需要用当前7.41f真实观战样本逐字段对照，再决定“被观战英雄、队友、可见敌人、未知信息”的输入边界。
- 当前普通教练只接入白名单的自身/扁平玩家状态。嵌套观战结构会被拒绝，Debug可显示`observer-shaped`，**没有在本版把它放入普通实战模型**。扁平结构是否一定代表自身，也不能仅凭结构证明；尚未做Dota Plus实测。

后续观战模式应与普通自身模式明确分开，设定被观察英雄和队伍，缺失/不可见信息保留未知。当前Debug结构摘要有助定位接口形态，但它并不是完整GSI审计记录。

依据：Valve《Dota Plus》官方功能页，2026-11-16查阅：<https://www.dota2.com/plus>。未找到Valve对7.41f实时观战GSI全字段及迷雾过滤的完整保证，所以本版不作这样的承诺。
