# 本机刷野教练：可测试原型与验收边界

日期：2026-11-15（香港时间）。

> 本文记录上一轮原型。后续“不要规则、使用大模型”的修改已转为独立模型提案，不再默认调用数值搜索。以 [多录像与模型推理说明](luna-multi-replay-reasoning.md) 为准；旧 `0.2.1-jungle-preview` 包不包含本轮完整变更。

**当前不是“最高收益已保证”的成品，也未部署到生产服务。默认关闭，只用于自定义局验证。**

## 本次实现

### 规划器

- 保留固定 7.41f 数据、180 秒窗口、己方可达营地、整分回访、框外等待与限宽搜索。
- 金钱从**每只单位的死亡事件**累计；存活单位不记钱，最后未清完整营地的击杀可以计入。未完成步骤只能结束路线，不会假清空后刷新再记一次。
- 法术等施法前摇结束才应用伤害、消耗蓝量并开始冷却；不能在窗口结束前开始读条、却把窗口结束后的死亡提前计钱。
- 疯脸使用已收取的物品冷却，模拟主动 100 攻速、6 秒持续、16 秒冷却、25 蓝耗、7 点减甲、自我沉默；持续时间和冷却跨营地传递。没有冷却输入不假定就绪。
- 适配普攻主目标按实际造成伤害吸血，不对过量伤害计吸血；不声称月刃弹射吸血已支持。
- Luna 明确学到的 `special_bonus_unique_luna_7` 减少 5 个百分点逐跳衰减；新增月光的单目标伤害、蓝耗、冷却适配。
- 数值来源：仓库固定提交 `b8fbea101ddaeaf069b32d3a86a3476969a207f4` 的 `npc_dota_hero_luna.txt` 和已有物品快照，没有切换游戏版本。
- 水生组合枚举接入 `estimateCamp` 和营地跟踪，已不再直接套普通中野。**仍不是历史封野感知或真实概率**：初始出生时间用最近整分假设，规划后有效刷新沿用路线时间；不同进化顺序按模型均匀样本处理。
- 假腿属性有网页 / 桌面 UI → 鉴权消息 → 房间运行时 → 属性重算链路。切鞋后重选；换局、换英雄、回退时钟、重新开启时清空确认。

### 本机截图与视觉

桌面 `LocalHudVision` 默认关闭：

1. 每 3 秒尝试采集一次，最多一个正在执行的请求，没有截图队列。
2. 只有前台进程名为 `dota2`、客户区未最小化、且有新鲜 GSI 时才截取；切出游戏不截其他应用。
3. 只向本机 `http://127.0.0.1:11434` 发送拼接后的**游戏时钟＋所选英雄 HUD**，不发送整屏；默认 16:9 HUD 裁剪避开聊天、小地图和顶栏英雄。不同 HUD 布局仍待验证，不能保证任意布局都不含其他内容；不落盘保存，不发往云端。
4. 开始前要求 `/api/show` 确认为本地 GGUF 模型，不允许 cloud 名称、远端模型元数据或 HTTP 重定向，不自动拉模型。
5. 返回结构化英雄、游戏时钟、假腿属性和置信值；5 秒超时则丢弃，继续使用 GSI，不回退付费云端。
6. 服务端按房间权限、当前 context、英雄、时钟、捕获时间、顺序和置信门槛复核。跨局、旧帧、不一致结果拒绝。
7. **连续两帧也只形成假腿属性建议，不自动覆盖玩家确认。** 置信值不是正确率保证，视觉不能替代完整 GSI；尚未实现仅凭截图恢复所有技能/装备/坐标。

本机硬件已读取到 RTX 3090 Ti，显存约 24GB，WSL 发行版 Ubuntu-26.04。本轮没有安装 Ollama、下载模型或测量模型在真实 Dota 画面上的准确率/延迟。

当前采集采用带前后台检查的屏幕客户区裁剪，不是窗口隔离的 Windows Graphics Capture；系统通知或其他叠加层可能进入裁剪区域，仍须自定义局验证。

可选模型接口按官方 `qwen3-vl:4b` 页面与 Ollama 结构化输出协议准备：2026-11-15 检查时该标签为约 3.3GB、Q4_K_M 权重配视觉投影器，页面要求 Ollama ≥0.12.7。**权重下载大小不等于运行显存需求，也不是边玩游戏边推理的性能保证。**

来源：

- `https://ollama.com/library/qwen3-vl:4b`
- `https://docs.ollama.com/capabilities/structured-outputs`

在用户自行选择安装和下载后，可在 Windows 或支持 localhost 转发的 WSL 中启动本地服务：

```text
ollama pull qwen3-vl:4b
ollama serve
```

本机视觉页面填写已安装标签，点击开启。WSL 服务必须从 **Windows** 可访问 `127.0.0.1:11434`；不要把服务端口开放到公网。需要实测并给 Dota 留出显存及 GPU 时间，不能因为有 3090 Ti 就假定 3 秒必定完成。

### 小地图悬浮标记

- 新增原生透明、置顶、鼠标穿透、不激活窗口；不读游戏内存、不注入、不发键鼠动作或队伍 ping。
- 绘制在**游戏小地图上的私人悬浮层**，不是写入游戏引擎，不是大场景地面上的 3D 标记。
- 画出未来三个步骤的折线、顺序和自己的白点；每 250ms 更新显示条件，真实规划更新来自 GSI。
- `Ctrl+Shift+J` 请求重新规划；快捷键被占用时使用桌面按钮。
- 切出 Dota、数据超过 8 秒、计划超过 12 秒未更新、死亡/不能行动、断线/换房间、关闭功能时隐藏或清空。
- 客户区像素与 WPF DPI 分离，使用游戏窗口原点，支持窗口移动；**分辨率改变后必须重新标定**。
- 当前小地图范围需手工标定。UI 数值只是试标定示例，不是已测得的 7.41f HUD 坐标：先试“仅白点”，在几个相距较远的位置核对图标，再勾选确认启用路线。左右小地图通过客户区 `left/top/width/height` 设置。
- 仅无边框/窗口模式是预期测试路径；没有对独占全屏、不同 HUD 比例、DPI、HDR 或多显示器完成实机验证。
- 标定目前只在当前进程内保存，重启后须重新确认，避免默默使用旧布局。

## 验证方式

```text
npm ci
npm run typecheck
npm test
npm run report:luna
node tests/jungle.browser.mjs
node tests/desktop-workspace.browser.mjs
node tests/native-transport.mjs
dotnet run --project desktop/DotaCoach.CoreTests -c Release
dotnet build desktop/DotaCoach.Desktop -c Release
```

浏览器测试可指定已安装的 `PLAYWRIGHT_MODULE`（Windows 使用 `file:///C:/.../index.mjs`）和 `PLAYWRIGHT_EXECUTABLE_PATH`。测试使用临时账号与假语音引擎，不需要真实账号或付费请求。

`tests/fixtures/luna-741f.json` 明确列出等级、技能/天赋、装备、鞋子属性、初始血蓝、时钟、位置和假设；`report:luna` 输出属性、路线、逐营地结果、逐只死亡、资源和未建模项。**输出标签为 synthetic-only-not-measured，不是实际收益，更不是理论上限。**

Windows 基线测试发现旧测试把 NTFS mode 当 POSIX `0600`，本轮将该断言限于非 Windows。其余存储与认证测试仍执行，**没有把它伪装成 NTFS ACL 的安全测试**。

本轮最终验证：`typecheck`、**96 项 Node 测试**、**417 条 .NET 核心断言**、刷野浏览器回归、桌面工作台浏览器回归、真实 .NET HTTP/WebSocket 协议往返均通过；桌面 Release 构建 0 警告、0 错误，`git diff --check` 通过。Luna 源文件 SHA-256 与仓库固定输入散列一致。测试包为 `0.2.1-jungle-preview`，自带运行时，未签名、未投放生产服务器或 NAS；仍需要新版服务端。

没有运行 Docker、其他浏览器套件、本地视觉模型、真实游戏采集或实际游戏 overlay 验收。测试包不是“已实机验证”的正式发布。

## 尚未完成的验收项

1. 环月的碰撞、减伤与站位，月蚀，月刃弹道/距离，野怪技能、光环、召唤。
2. 初始已经开启疯脸时的完整状态重建；GSI 沉默状态目前仍保守撤回路线。未来接通 active 状态后才应放宽，不能单独去掉保护。
3. 移动攻击、引野追逐/脱战、水流、合拉与堆野；不能用固定折扣伪造职业清野效率。
4. 实际出生、历史封野和进化顺序，实际组合/概率；目前仍是样本保守包络。
5. 单靠视觉读取完整技能/装备/天赋/位置；局内升级和购买未来预测；线野混刷的独立目标。
6. 本地模型部署及真实画面识别测试，Windows 实际 Dota 小地图对齐、无抢焦点/无误截测试。
7. 固定配置下 180 秒实际纯野赏金、清野/步行时间、血蓝偏差验收。
8. Astra 尚未接入，也未调用任何付费规划模型。确定性搜索仍有剪枝，`optimal: false`。

所以“最终收益最高”目前应理解为待验证目标：只能比较**相同已建模假设下搜索到的预计金钱**，无法在敌人、封野、随机野怪和玩家执行未知时保证实战全局最优。
