# 线野总收益、刷新与拉野实验（v2）

2026-11-15，香港时间。对应用户指出的「职业 Luna 常在下半区循环、线野双收、利用刷新与拉野」。

**同日后续撤回：** 线野示例第 13 步实际接触并击杀夜魇营地单位，原校验只看营地编号/血量，不能称为“安全候选”。两个显示过的对照都未通过己方活动区域验证，已撤下；当前路线加载及付费规划关闭。下列数字保留为**历史、无活动区域限制的机制实验**，不是当前可用建议。完整实证与未完成项见 [区域审计](sandbox-own-area-audit.md)。

## 这次修正了什么

1. **收益目标从纯野改为 180 秒英雄线野补刀总金币**。仍独立记录野怪、兵线、总金币；GPM 使用固定 3 分钟分母，不删除空转或死亡后的时间。工资、队伍赏金、建筑收入不混入。
2. **兵线不是 10:00 才空地图起步**：起始前先预演 120 秒的小兵行军/互攻，因此起点已有残血波与后续波次。预演不产生英雄收入。
3. 增加模型可选的收线、等待、移动、引野行动。收线支持 `push` / `last_hit` 微操执行模式；它们不是选择路线的规则。
4. 野怪受攻击/英雄接近后实际追逐，脱战后步行归位。刷新判定检查**当时单位的坐标是否占框**，不再因为「这个营地还有活怪」就永远禁止刷新。
5. 引到兵线附近的、已激怒野怪可与小兵互攻；小兵会被吸引。**不直接发拉野/堆野金币，小兵击杀也不算英雄收入。**
6. 堆叠标记的金币/经验乘 0.8，一次标记不会重复乘；拆分单位继承标记。数值参照官方 7.39e 的堆野惩罚变动，但标记范围、时机及后续完整客户端行为尚未实机校准。官方原始接口：`https://www.dota2.com/datafeed/patchnotes?version=7.39e&language=english`。
7. 修复了一个影响策略评估的导航错误：英雄直线追兵会落入不可行走网格，导致下一步误报不可达。现在英雄追逐保留网格可达性，且每个时间步不得超过移动预算；**野怪/小兵追逐仍为近似**。

下半区循环只作为用户和录像提出的**待检验策略**。没有「下半区加分」「多走路固定扣分」「固定营地数量」「固定第 53 秒拉野」等策略规则。模型自行选择地点、时间、目标优先级以及是否值得拉野。

历史 v1 纯野实验仍可通过 `evaluateRoute(seed, visits, 'v1')` 重现。不能直接用旧 v1 的 408.3 GPM 与新机制下的数据比较。

## 实际模型实验：保留不符合预期的结果

模型为用户授权 Foundry 配置中的实际 `gpt-6-astra`。所有数字来自本机 API 执行，不采用模型自报金币。

| 新版环境、同种子 741 | 野怪金 | 兵线金 | 总金币 / 180 秒 |
|---|---:|---:|---:|
| 较广下半区路线 | 673 | 86 | 759 |
| 中路线野往返 | 624 | 248 | 872 |
| 刷新循环，不主动堆野 | 908 | 172 | 1080 |
| 下路线野＋主动堆野示例 | 908.4 | 210 | 1118.4 |
| 旧模型的纯野路线在 **v2 重新执行** | 1208 | 0 | 1208 |
| 接受上述反例后新测的局部线野循环 | 750 | 248 | 998 |
| 接受反例后新测的兵线优先方案 | 91 | 458 | 549 |

**结论不是「线野一定更差」，而是这批无活动区域校验的方案不能用来判定职业式路线优劣。** 模型曾看到 1208 金对照后选择该对照，没有被程序强制改选下半区方案。此前“安全候选”的称呼错误：只检查过最低血量，没有验证路径安全。

线野＋堆野示例的历史输出约 **372.8 模拟总 GPM（已撤回作为路线依据）**，最低血量约 799.8/1018；包含 9 号营地引出框后的刷新与后续清理，也包含来自夜魇营地的 13.6 金。不能只减去这笔钱就认定问题解决，也不能把方案差异全归因于拉野。

同一线野方案不再调用模型，在未参与生成的种子 742–746 上复跑，总金币分别为 **1171.2、1148.2、1096.2、1092、1089**；这是对近似环境的复跑，不是实战验证。

完整提案、失败与反例保存在 `data/sandbox-luna-economy-api-run.json`。其中保留首轮比较和接收纯野反例后的模型修订，而不是只保存最高分或删掉失败结果。最早的导航错误试跑只得 354 金，已单独留在本机 `.tmp/sandbox-economy-before-navigation-fix.json`，不算作最终机制结果。

## v2 API

仍是仅监听本机、使用临时沙盒 token 的独立服务。Foundry 凭据只由显式模型实验脚本读取，不进入地图页面。

| API | 行为 |
|---|---|
| `GET /api/context` | 版本/机制修订、地图几何、营地出口、兵线、关闭原因与已撤下对照名称 |
| `GET /api/initial` | 当前种子的起始世界，不重置正在播放的世界 |
| `GET /api/state` | 活单位、兵线波次/金币、刷新框、冷却、分账收益、动作/事件 |
| `POST /api/action` | `farm_lane`、`pull` 及原有 `move/attack/farm/stop/cast` |
| `POST /api/evaluate` `{seed,steps}` | 在独立世界执行指定计划，返回线野分账、最低血量、实际时序、未赶上的波、拉野/堆野事件 |
| `POST /api/plan` `{seed,steps,model,summary}` | 当前一律 `409 OWN_AREA_UNVERIFIED`，不改变手动实验 |
| `POST /api/load-example` `{id}` | 当前一律 `409 OWN_AREA_UNVERIFIED`，不加载历史路线 |

旧 `visits` 格式仍用于显式纯野兼容回归，新模型使用 `steps`：

```json
{
  "seed": 741,
  "steps": [{
    "kind": "lane",
    "campId": null,
    "laneId": "bot",
    "position": {"x":2016,"y":-3872},
    "duration": 30,
    "untilClock": null,
    "targetPriority": ["lane_ranged","lane_melee"],
    "attackMode": "push",
    "casts": []
  }]
}
```

这是格式说明，不是推荐路线。`kind` 可为 `camp/lane/pull/move/wait`：

- `duration` 为该动作含移动的总时间上限。
- `untilClock` 为 600–780 的绝对游戏时钟截止时间；`null` 表示无额外截止时间。
- `camp` 清空后提前完成；`lane` 观察到的局部波消失/死亡后提前完成；`pull` 到撤离位置后完成；`move` 到点后完成。
- 没遇到兵线可以等待至时限，也会被如实记作空转。不会自动选另一个营地或兵线。
- 施法时间相对第一次实际到达；冷却/蓝量/沉默失败会记录，不自动换成更优时机。

## 仍未解决的实战差距

全图可见，没有敌方英雄、塔、真实视野与占线压力；固定等级装备，水生进化、完整环月/野怪技能、攻击投射物与真实碰撞仍缺失。兵线几何与追逐参数尚未逐录像/实机校准。尤其是缺少敌方威胁，会让长距离刷图显得过于安全；不能为修正这种偏差而添加任意「下半区奖励」。

下一步应校准兵线到达时刻、清营耗时、归位/追逐和堆野标记，再加入**可观察的**塔/敌人/视野状态；之后继续用同环境、同时间窗口和未见种子比较。当前变化仅接入沙盒，**没有宣称真实游戏截图规划或小地图标记已完成线野实机验收**。
