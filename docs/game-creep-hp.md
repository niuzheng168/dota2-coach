# 游戏端：小兵血量数字

只给**半血以下**的普通兵在血条上方显示当前血量（友方绿字、敌方白字）；**现在出手、这一刀落地时必能打死**时数字变**红**，提醒正补（敌方兵）或反补（友方兵，半血以下才能反补）。红字默认**提前看**：已经算上你的反应、网络延迟、英雄前摇和弹道，以及这段时间里别的兵和塔按节奏还要打的几下，看到变红就按攻击（见[提前看](#提前看红字什么时候出现)）。塔下的兵要先垫刀时，血条右边的**黄色数字**是要垫几刀（不论血量），垫完等塔打到变红再补。全部在游戏机本地完成：这个血量功能只在本机显卡上识别和绘制，不编码、不传给教练端，也不需要配对或模型。不读内存、不注入游戏进程。

## 使用

1. 在游戏端主页点 **显示小兵血量**。首次会写入本机自身 GSI 配置；若提示重启，在 Steam 的 Dota 启动选项加入 `-gamestateintegration`，完全退出并重开 Dota 一次。
2. 默认血条，无边框或窗口模式。Dota 在前台时显示，切出 Dota 隐藏。数字窗口不进录屏和截图。
3. 没有收到自身 GSI 时只显示百分比（血条本身分不出近战、远程、攻城兵），也不标红；状态行会写明原因。
4. 状态行写着当前的红字线和一塔下满血兵的方案，例如 1 级裸装露娜：
   `红字＝一刀必死：近战兵 ≤46 · 远程兵 ≤52 · 攻城车 ≤26（已算护甲；攻击力 52–58，每 1.37 秒一刀）`
   `黄字＝塔下先垫几刀，之后等塔打到变红再补。一塔下满血：远程兵 不用垫 · 近战兵 垫 1 刀（塔每 0.83 秒一下）`
   `红字提前看：反应 0.15 秒＋延迟 0.08 秒＋出手到命中约 0.73 秒，算上这段时间里别的兵和塔按节奏要打的几下`
5. **设置 → 小兵血量** 里有 **红字提前看** 开关（默认开）和两个滑块：**反应提前量**（默认 150 毫秒，比你从看到变红到按下攻击的时间短约 50 毫秒）、**网络延迟**（游戏里的 ping，默认 50 毫秒）。改动立即生效，只存本机（`%LOCALAPPDATA%\DotaCoach\TwoPc\creep-hp.json`）。关掉提前看就回到只看这一帧。

**和教练端配对时：** 如果只看小兵血量，不必连接教练端。v0.6.2 起游戏端只有一种连接，只传本人 GSI，不传画面；连接不会打开或关掉血量识别，连接前后都可点「显示小兵血量」开关。画面和小兵识别结果只在游戏机本地，关闭识别不影响本人 GSI 记档或接收装备、眼位和字幕，详见[不传画面的连接](twopc-status-only.md)。

## 什么时候变红

- **攻击力**：由自身 GSI 的英雄、等级、属性加点、天赋和身上的装备（6 格主物品栏 + 中立物品格；背包、储藏处不算）推算，数据取自本机安装的客户端（`data/dota2-hero-attack.json`，build 6989，`scripts/client/build-hero-attack.ts` 生成）。算的是：基础攻击 + 主属性（全才英雄每点属性 0.45）+ 属性加点（每级全属性 +2）+ 通用的攻击/属性天赋 + 露娜月之祝福（每级 +2，被破坏时不算）+ 装备上游戏自己列为属性行的加成（“+$damage”“+$agi”等；负的也算，如贤者石）。补刀斧/狂战斧对兵的额外伤害按近战/远程另算（不叠加）。
- **对兵实际打掉多少**：按攻击力的**最小值**，乘兵的护甲减伤（近战兵、旗手 2 甲，超级/巨型 3 甲；远程兵 0 甲，超级/巨型 1 甲），攻城车受英雄伤害减半。
- **判定**：血条这几个像素能对应的**最高**血量，加上到命中这段时间里兵回的血，减去这段时间里预计别的兵和塔还会打掉的（提前看，见下节），也不超过上面这一刀，才标红。血量刚好在线附近几点的兵要再掉一点血才变红。
- **回血**：近战兵、旗手每秒 0.5，远程兵 2，攻城车 0；同阵营旗手在 700 码内时每秒再加 3（旗手光环，按 GSI 小地图位置判断；这一帧没配上位置时按有光环算）。
- **出手到命中**：攻击前摇（按攻击速度缩短）加弹道飞过实际距离（英雄和兵的 GSI 小地图位置；缺位置时按满射程）的时间，再加约 0.04 秒服务器处理（补刀实验室实测：正对目标约 1 帧，要转身约 2 帧）；攻击速度＝基础攻速 + 敏捷 + 装备上的攻速属性行 + 攻速天赋。兵在射程外 100 码以上时英雄要先走过去，不提前看。
- **有意不算的**（只会让红字出现得偏晚，不会让不该红的变红）：其他英雄的被动/光环加攻击、队友和神符的增益、百分比基础攻击、暴击和触发类伤害、假腿和臂甲切到哪个属性（按加得最少的算）。
- **不支持的英雄**：杰奇洛的普攻分两下、每下打折，不标红。数据里没有的新英雄也不标红，状态行写明。

## 提前看：红字什么时候出现

- **为什么要提前**：从看到变红、按下攻击，到这一刀落地，要经过你的反应、网络延迟、英雄前摇和弹道；1 级露娜站在射程边上大约 0.9 秒。这段时间里兵还在挨别的兵和塔的打。只看这一帧的血量，红字出现时往往已经来不及（补刀实验室：反应 0.2 秒的玩家这样只补到 31% 的露娜机会）。
- **节奏**：线上兵每 1 秒打一下，塔每 0.83 秒一下，同一个攻击者会一直打同一只兵（实验室里 88–93% 会打下一下）。血条上两次大小相近、正好隔一个节拍的掉血，就推定下一拍还会来；节拍断了（该来没来）就不再算。单独一次掉血（英雄、刚开始打的兵）不推测。
- **何时变红**：现在出手的话，落地时间＝反应提前量＋网络延迟＋约 0.03 秒（本机采集、绘制和服务器的帧）＋出手到命中。这之前预计会挨的几下打完，剩下的血不超过你最弱的一刀，就变红。
- **能等就等**：如果要靠预计的那几下才够一刀，而等那一下真打出来再出手也来得及（之后还扛得住一下没预计到的），就先不红，等它打出来。这样预计落空时不会让你出手太早；远程英雄、塔下、几只兵一起打时来不及等，就提前红。
- **两个滑块**：反应提前量取你的反应时间减约 50 毫秒最好（实验室：反应 0.15/0.2/0.25 秒时，提前量 0.10/0.15/0.20 秒最好）；网络延迟填游戏里的 ping。
- **远程英雄补刀站近一点**：要提前的时间越短，红字越准。实验室里 1 级露娜从 340 码站到 200 码（弹道少 0.16 秒），补到率 66% → 77%。限制红字准确度的主要是这段时间里新来、换目标的攻击者（血条上看不出来），不是你的反应，见[补刀实验室](last-hit-lab.md#上限在哪缺的是接下来谁会打它不是反应)。
- **核验**：见[补刀实验室](last-hit-lab.md)，用 Dota 自定义游戏里的引擎真值离线评估，再用真实游戏端读画面、按红字出手做闭环。

## 补塔刀：先垫几刀

- **显示**：塔下的兵要先垫刀时，血条右边一个**黄色数字**＝现在先打几下。不用垫（塔自己就能把它打进一刀范围）就不显示。垫完数字消失，等塔打到数字变红再补。
- **哪些兵**：GSI 小地图上还立着的塔，对面阵营的近战、远程、旗手、超级/巨型兵在它射程内（700 码 + 塔和兵的碰撞半径）就算，不论血量：自己塔下的敌方兵是正补，对面塔下的友方兵是反补（友方兵半血以上打不了，只等塔打）。攻城车不算（塔打攻城车的伤害没核实）。按“塔正在打这只兵”来算。
- **塔的数值**（客户端 npc_units.txt，build 6989）：一塔每下 88–92，二、三塔和基地塔 170–174，每 0.83 秒一下（0.9 ÷ 1.1 = 0.818 秒，服务器按每秒 30 帧取整到 25 帧，补刀实验室实测 0.833）；打近战兵按 2 甲减伤。
- **怎么找最少的垫刀**：从现在的血量出发，先试不垫（0 刀），再 1、2、3 刀；每种垫法再试塔打 1–10 下。要求塔打完这几下以后，剩下的血**一定还活着**、又**一定能被你一刀补掉**。每一下都按平均伤害算，剩下的不确定（塔和你的伤害浮动、血条像素、塔具体什么时候开火）留两倍标准差的余量；回血只算对补刀不利的那一边（旗手中途可能死）。
- **攻速**：垫刀一刀接一刀要隔一个攻击间隔，最后一刀还要再隔一个间隔，加上出手到命中的时间，必须在塔打出下一下之前落地；按塔马上就开火算。所以同样的血量，攻速慢的英雄可能要多垫或者排不出方案（排不出就不显示）。
- **例子**（1 级裸装露娜，一塔，近战兵 46–52 一刀、远程兵 52–58）：满血远程兵不用垫（塔打 3 下后补）；满血近战兵垫 1 刀（再等塔打 6 下）；对近战兵一刀只打 26–30 的英雄要垫 2 刀，攻速再慢到 2.5 秒一刀就排不进去。
- **跟着做**：每帧按当时的血量重算。前摇加弹道比塔的间隔（0.83 秒）长的英雄（例如远程英雄站在最远射程）要在塔的最后一下快落地时就出手；提前看会把塔的节奏算进红字，看到变红就按。
- **不管的**：别的兵或英雄同时在打这只兵（自己塔下通常有自己的兵在打），塔改打别的目标。这些会让数字跳变，按新数字走即可。

## 如何工作

- **采集**：Windows.Graphics.Capture 只采 Dota 窗口，帧留在显卡上，不回读画面。
- **识别**：一次计算着色器遍历整帧（每行一组线程，先把整行分类到共享内存），找“黑色左边框 + 默认 HUD 绿/红填充或空槽”，只回读几 KB 的血条记录。游戏画 `ceil(比例 × 跨度)` 个填充像素，跨度 = 77.3 × 窗口高 / 1080，所有普通兵（近战、远程、攻城、旗手、超级、巨型）同一尺寸；读数取可能区间的中点。左端被别的血条盖住的，从右边框往回读：填充末端露在外面、或露出部分全是填充（满血）就能读。填充末端被盖住、行间读数不一致的血条不显示，宁缺勿错。
- **兵种**：来自自身 GSI 的小地图单位（名称、阵营、坐标）。按拟合的默认镜头（4K 下 116 根血条，残差 3 像素）把单位投到屏幕上；GSI 不给镜头中心，就取让最多血条与同阵营单位对上的中心，再就近配对；剩下的血条再按地形高差（河道、坡、高地，GSI 不给高度）配一遍。逐帧跟踪，偶尔一次配错不会改掉显示。
- **血量上限**：出生值（npc_units.txt）近战/旗手 550、远程 300、攻城 935、超级/巨型近战 700、远程 475。近战、旗手、远程兵每过 7.5 分钟游戏时间多 12（按 GSI 的比赛时钟算：例如 24 分钟近战 586、远程 336）；攻城兵不变。中立野怪和没配上的兵显示百分比。
- **绘制**：DirectComposition 置顶、鼠标穿透、不抢焦点的透明窗口，与识别同一个显卡设备，每帧只改数字所在的小矩形。
- **不拖慢游戏**：
  - 进程的 GPU 调度设为实时类（无需管理员）。否则游戏占满显卡时，0.1 ms 的识别每次要排队约 35 ms。
  - 每帧只向显卡提交一次：本帧识别与上一帧数字的呈现一起提交，所以数字晚一帧。分开提交的代价约是它的 2.6 倍。
  - 每秒读一次本显卡的 3D 占用（Windows “GPU Engine” 计数器）：连续 3 秒低于 80% 才每帧刷新；一到 85% 立即限 60 帧/秒。刚放开就又满载时，下次放开前的等待加倍，最多 60 秒。读不到占用时按满载处理。

## 本机核验（2026-11-19/20，Dota build 6976）

开发机 RTX 3090 Ti，Dota 3840×2160 无边框，显示器 144 Hz。前两行精度用英雄试玩里摆好的兵线（静止、血量固定）对照引擎真实血量；帧率用 Dota 自己的帧计数，开/关交替各 3 段、每段 12 秒。

| 项目 | 结果 |
|---|---|
| 读数精度 | 4K 164 根：平均误差 1.16 HP，最大 4；1440p 95 根：1.32 / 4；1080p 95 根：1.74 / 7。每个场景的 17 根普通兵条全部找到，英雄血条不读。 |
| 兵种匹配（混合兵线、相机移动） | GSI 节流 0.2 秒：99.0% 对到正确单位，0.03% 对错，其余显示百分比；GSI 最新时 99.8%。实机界面 11 根血条 11 根认出兵种。 |
| 锁帧 `fps_max 182`（显卡有余量，3D 占用约 68%） | 游戏 182.4 → 182.3 帧/秒；数字约 141 帧/秒刷新，识别+呈现往返 1.5 ms。 |
| 不锁帧（显卡被 Dota 占满，约 308 帧/秒） | 游戏 307.9 → 301.8（−2.0%）；数字自动限 60 帧/秒。 |
| 对照：不锁帧下的其他做法 | 每帧刷新 −6.5%；60 帧但识别与呈现分两次提交 −5.5%；只开窗口采集（144 帧/秒）−1.1%。 |
| 真实地图 5v5 机器人对局，上/中/下三路（1–25 分钟，42 个画面） | 镜头跟随每路交战处，把游戏放慢到 0.02 倍取画面，同时导出引擎里附近每个单位的真实血量和位置。画面里看得见的 229 个兵中读出 218 个（95%：上路 95%、中路 93%、下路 98%），漏掉的都是血条填充末端被别的血条或英雄名字盖住。由填充反推的血量平均差 0.6 HP（最大 5；一次 20 是取画面与导出之间正好挨了一刀）。显示的数字 211 个里 205 个与真实血量相差不超过 3 HP（平均 0.8）；其余是 7.5 分钟升级刚过、还没升级的老兵线多显示 12（4 个），以及上面那次挨刀。兵种逐个核对没有错配（中路河道一处，评估脚本按高度对应失误，看截图产品标注正确）。英雄、防御塔血条没有被标数字。对局中数字刷新约 110 帧/秒，最低 60。 |
| 兵的血量上限随时间（同一对局 0–47 分钟，引擎读数） | 近战/旗手 550、562、574、586、598、610、622，每 7.5 分钟一级；远程 300 起每级 +12；攻城 935 不变。新出生的兵约 30 秒后才升级。 |

### 半血过滤和红字（2026-11-21，离线核对）

没有重新进游戏：用上面 5v5 机器人对局的同一批 42 个 4K 画面和当时记录的玩家 GSI（露娜 1–5 级、无装备），按新规则离线重画数字，与引擎真实血量对照（`--lethal-preview`）。

| 项目 | 结果 |
|---|---|
| 半血过滤 | 标了血量的 52 个兵，真实血量全部低于一半。 |
| 红字 | 标红 5 个（含友方反补），真实血量全部 ≤ 一刀最小伤害；没有错红。另有 4 个真实可一刀打死、但真实血量离线只差 0–4 HP 的没标红（按像素最高血量判断，偏保守）。 |
| 补塔刀 | 塔射程内 15 只兵算出了方案（3 只要垫 1 刀，其余不用垫）。用引擎真实血量和平均伤害复算，14 只按方案垫完、塔打完后剩 5–46 血、在一刀之内；1 只不成立，是取画面和导出血量之间正好挨了一刀（画面 336，引擎 316）。静态画面验证不了之后真的补到没有。 |
| 攻击力公式 | 1 级裸装露娜算出 52–58，与 4K HUD 的“53 +2”一致（白字为基础攻击均值）。其他英雄和装备组合只做了单元测试，没有对照游戏 HUD。 |
| 英雄试玩画面（静止兵、血量由 Lua 设定） | 友方远程 24/300、友方超级近战 33/700 标红（可反补）；近战 69、攻城车 86/935、超级远程 72/475 不红；半血以上的不标。在画面里放两座假想的一塔：满血敌方近战的血条右边出现黄色“1”，满血远程兵（敌我）都不显示。 |

### 补刀实验室（2026-11-23，Dota build 6989）

在 Dota 自定义游戏里用引擎真值核验红字时机，详见[补刀实验室](last-hit-lab.md)。每只兵第一次变红就出手、反应 0.2 秒：1 级露娜补到 31% → 66%（提前看＋能等就等），1 级主宰 57% → 63%；出手太早约 5%。实测塔每 0.833 秒一下、下令到命中比前摇加弹道晚约 0.04 秒，已改进计算。

## 局限

- 只认默认 HUD 的血条颜色和尺寸；色盲模式、其他血条样式、独占全屏未验证。
- 兵堆里填充末端被其他血条或英雄名字盖住的兵不显示数字（对局里约 5%）。
- 兵种依赖自身 GSI；观战、回放未适配。野怪只给百分比。超级/巨型兵按同样的成长计算，未实测。
- 血量上限按比赛时钟推算：每次 7.5 分钟升级后的一两分钟里，升级前出生的兵会多显示最多 12（约 2–4%）。
- 显卡被游戏占满（不锁帧）时仍约少 2% 帧率：窗口采集本身和每帧一次的显卡抢占都要时间。把 Dota 帧率上限设在显示器刷新率附近即无影响。
- 数字比血条晚一帧：每帧刷新时约 7 ms（144 Hz），限 60 帧时约 17 ms，镜头快速移动时数字会略微拖后。
- 提前看只认线上兵和塔的固定节奏：英雄的普攻和技能、刚开始打这只兵的攻击者、换目标都预计不到。补刀实验室里每只兵第一次变红就按（反应 0.2 秒），1 级露娜约 27%、1 级主宰约 30% 来不及（被别人先打死），约 5% 出手太早。没有敌方英雄的场景，联网延迟按设置估算，游戏机上还没跑过闭环，见[补刀实验室](last-hit-lab.md)的局限。
- 垫刀数没在游戏里实际跟着打过；塔打攻城车、塔的仇恨和目标切换都没建模。
- 兵的护甲按出生值（近战 2、远程 0）算；7.42 里兵的护甲是否随时间增长没有实测，若会增长，后期红字可能偏乐观。GSI 的 `talent_1..8` 按英雄文件里天赋的顺序对应，未在游戏里核对。
- 游戏更新改了英雄或装备数值后，要重新运行 `node scripts/client/build-hero-attack.ts`（`--check` 只比对不写入）。
- 还没在游戏机（4K/240 Hz）上验收。
