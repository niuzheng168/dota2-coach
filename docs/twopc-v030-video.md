# 双机教练 v0.3.0：游戏端持续视频，教练端按需抽帧

本版修正数据流方向。**两端都升级到 v0.3.0**，重新复制配对码；不回退到普通模式的一秒一张JPEG上传。

```text
游戏端：前台游戏采集（目标30fps）→ 容量1的最新未编码画面 → H.264编码
                                  ↓ 证书固定、配对认证的持续WSS连接
教练端：持续解码 → 内存中最新视频帧
                    ├─ 本地预览（独立约10fps，不转JPEG）
                    ├─ AI需要时抽取JPEG + 同帧自身GSI → 大模型推理
                    └─ Debug开启时约每秒抽一帧 + 保存每次实际模型输入
字幕/小地图提醒：独立HTTPS控制链路回到游戏端
```

## 使用与默认参数

- 安装、Foundry文件、GSI及4K小地图校准沿用包内 `NORMAL-USE.md`；自动教练、字幕、地图默认开启，Debug默认关闭。
- 视频：目标 **30fps / 平均6Mbps**，H.264 Baseline，Windows系统Media Foundation软件编解码，无音频。界面显示实际平均发送fps/码率和未编码丢帧数；目标值不是保证值。
- 游戏原始3840×2160缩到1600×900；4096×2160缩到1600×842（NV12要求偶数尺寸）。原始尺寸单独传输供字幕/地图投影。**不是4K原生码流，也不是NVENC/GPU零拷贝实现**。
- 游戏端不决定AI抽帧时机。模型默认每20秒最多一次、180次/进程的成本限制不变；暂停推理、达到请求上限、冻结预览均不停止视频接收。
- 不把全部视频帧逐一送到云端。云端只接收教练端明确选出的JPEG与对应自身状态。没有调用模型时，纯视频解码/预览不生成JPEG。
- 原始序号、编码时间戳和自身GSI绑定；模型结果始终引用原始来源帧，不能贴到最新帧上冒充新结果。
- 未校准小地图时仍只发字幕；未知、不可见信息不补全，不增加刷野规则回退或自动操作英雄。

## Debug

日常只在**教练端**展开Debug并勾选录制即可：

- 每秒从当时已解码视频抽一帧，事件为 `frame-sampled`；另存实际 `model-input`、模型结果和提醒等日志。
- 这是教练端可独立改变的调试采样节奏，不是传输帧率。冻结预览仍采样，关闭Debug仍解码和预览。
- 游戏端Debug正常只存状态、错误和提醒绘制回执，**不再重复保存图片**；它仅供采集/连接/绘制的本机问题排查。
- 仍使用 `%LOCALAPPDATA%\DotaCoach\Debug`，本地存储，不自动上传，不录完整视频；2GiB/2小时等限额保持。JPEG可能含聊天，没有自动打码。
- 保存的JPEG来自H.264解码结果，不等于网络原始字节，也不是4K无损原图。文件SHA标识实际用于推理/调试的JPEG。
- 周期CPU/内存指标是写日志的那台客户端进程，不把它误称为另一台游戏机的性能。游戏端绘制回执目前也不会自动汇入教练端。

更完整的隐私、日志限额和Dota Plus边界见 `DEBUG-DETAILS.md`；该文v0.2.1两端存JPEG的说明为历史实现，由本页覆盖。

## 时效、负载与停止

- 采集与编码/发送分别在工作线程。只丢弃还没编码的旧画面，不任意丢H.264参考帧；码流顺序不能破坏。
- 应用层每个视频访问单元有ACK，最多一个等待确认的发送，避免无限TCP积压。过慢时降低实际视频fps；ACK超过1.5秒停止此连接，不无限缓存旧视频。
- 独立续期的短租约在采集前取得；接收端在原生解码前复核会话/序号/租约，仍以教练机单调时钟限定来源年龄，不要求两机墙钟同步。
- 视频头/包大小、编码尺寸、解码输出及积压都有限额。只有配对认证通过的客户端才能建立视频连接，网页Origin被拒绝；撤销配对也使已经升级的WSS流失效。
- 历史来源记录由32条提升到512条，覆盖30fps下原有12秒提醒窗口。增加的是元数据容量，不延长过期建议的寿命，不缓存512张图。
- 切出Dota、窗口/分辨率改变或停止时取消工作线程、终止当前码流并清空提醒；切回后新建会话/编码器。从网络/编解码错误恢复需重新连接；不静默切回JPEG。
- 当前仍是前台检查的屏幕区域采集，不是隔离WGC，可能含通知或其他遮挡；软件采集/颜色转换/编解码有CPU开销，不保证对游戏帧率无影响。
- 旧 `--local-bot-e2e` 的JPEG像素证据工具保留为**显式历史验收入口**，不作为正常连接策略；旧720p真实游戏验收不能证明本版视频通过实机验收。

## 本版验证与未验收项

验证包含真实Windows H.264编解码（640×480、1280×720、1600×900、1600×842），PTS与解码像素核对，100帧真实证书固定WSS传输且不生成JPEG，按需提图、旧来源保留与过期、撤销配对和原生WPF按钮/预览/提醒/Debug链路。

诊断视频的原生双客户端测试曾测得约27fps。它是同机生成的诊断图，不是用户4K Dota实战、两台物理机网络、真实捕获CPU/GPU开销或最高GPM验收；本次没有发起付费模型请求。

实现依据：Microsoft Windows SDK `mfobjects.h`、`mftransform.h`、`mfapi.h`、`codecapi.h`；Microsoft Learn “H.264 Video Encoder”“H.264 Video Decoder”。直接使用系统编解码器，没有随包分发外部编解码器二进制文件。
