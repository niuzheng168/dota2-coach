# 局内战术助手设计：斩杀线提醒与刷野路线

- 状态：草案，待评审（2026-11-15）
- 范围：服务端新模块 `src/tactics/`、GSI 配置、房间实时状态、网页/桌面的提醒输出
- 不在本文范围：小地图读屏识别敌人位置（Phase 3，另写设计文档）

> 实现进度（2026-11-15）：按用户要求先实现刷野实验版。互联网已取得版本化营地/刷新框/寻路网格和游戏战斗数值；实现范围、来源、使用方式与未验收项见 [刷野路线规划](jungle-route-planner.md)。当前采用确定性数值模拟与三步搜索，不限制后续增加大模型策略层；尚未实现本文的斩杀线和原生桌面战术输出。

## 1. 目标

**对线期：斩杀线提醒**

- 实时估算对线对手对我的**最坏情况连招伤害**（下称"斩杀线"），与我当前血量比较；进入危险区时播一句简短的中文语音。
- 关键节点提前提醒：对面即将到 6 级；我买了魔抗或护甲装备后，斩杀线有明显变化。

**刷野期：路线规划**

- 根据我的位置、移速、清野能力、血量和游戏时间，规划接下来 2–3 个营地的顺序，**只播报下一步**。

**第一版验收指标**

| 指标 | 目标 |
|---|---|
| GSI 数据到达 → 开始播放提醒（P90） | ≤ 1.5 s |
| 对线期平均语音提醒数 | ≤ 2 条/分钟 |
| 在对线期被对线对手击杀前 10 s 内，曾处于"注意"或"危险"档的比例（用录制对局回放统计） | ≥ 80% |

## 2. 非目标与合规边界

- **只使用**三类信息：GSI 玩家模式数据、Valve 公开的静态数据（`dota2.com/datafeed`），以及玩家屏幕上本来就能看到的信息（Phase 3）。
- **不做**：读游戏内存、抓包、注入、模拟键鼠操作、使用观战数据（观战数据会破坏迷雾）。
- 对面实际的技能冷却、蓝量和装备看不到，一律**按最坏情况估算**。提醒宁可偏保守。
- Valve 没有明确允许这类实时辅助工具，存在政策风险。本功能**默认关闭**，由用户自行开启。
- **数值计算不经过大模型**，这条链路上不使用大模型。现有语音引擎都是翻译器，不负责主动提醒；大模型做数值计算慢，也不可靠。

## 3. 使用场景

```

       悬浮字幕：斩杀线 ≈ 480 ｜ 你 620
03:05  你被小兵和普攻压到 470 血 → 进入"危险"档
       语音："危险，斩杀线内，后撤。"
04:50  你升到 5 级
       语音："对面快 6 级，莉娜有大以后连招约 1100。"
09:30  你清完下方大野，按快捷键询问
       语音："下一个：下方中野，6 秒到；然后整分回大野。"
```

## 6. 详细设计

### 6.1 GSI 改动

- `generateDota2GsiConfigFile`（`src/auto-draft.ts:180`）的 `data` 增加 `abilities`、`items`、`buildings`、`events`。Phase 0 抓包时另外打开 `minimap`、`roshan`、`couriers`、`neutralitems`，确认它们在玩家模式下返回什么，不需要的再关掉。
- `throttle` 从 1.0 改为 0.5，`buffer` 从 0.5 改为 0.1。用户需要重新下载 cfg。
- Phase 0 增加开发开关 `GSI_CAPTURE_DIR`：把原始数据以 JSONL 格式写入该目录。写盘前去掉 `auth.token`、`player.steamid`、`player.name`。这些文件用作测试数据和回放数据。
- `/api/gsi` 处理完现有逻辑后调用 `room.tactics.ingest(parsed, Date.now())`。战术模块出现异常时只记日志，**不影响** GSI 的响应和阵容逻辑。
- 收到新的 `matchId` 或 `resetHeroes` 时重置 TacticalEngine。

### 6.2 静态战斗数据 `data/dota2-combat.json`

- 新增脚本 `scripts/build-dota2-combat-data.ts`（`npm run build:combat`），请求方式参照 `build-dota2-dictionary.ts`。输出文件记录 `patch` 和拉取日期。
- **英雄**：基础属性和成长、基础攻击力、攻击间隔、射程、基础护甲和魔抗、基础移速。
- **技能**：名称；是否大招（`type=1`）；伤害类型（`damage`：1=物理，2=魔法，4=纯粹）；各级冷却和蓝耗；施法距离；`burst` 描述。
- **物品**：按字段白名单提取属性（`bonus_armor`、`bonus_magical_armor`、`bonus_movement_speed`、`bonus_damage`、`bonus_attack_speed`、`bonus_strength` 等）。
- **`burst` 自动提取**：名称含 `damage` 的数值作为直接伤害，排除 `_pct`、`tooltip`、`per_second` 等；名称含 `stun_duration`、`root_duration`、`hex_duration` 的作为控制时长。
- **人工修正**：`data/dota2-combat-overrides.json` 处理自动提取不了的情况：持续伤害（总伤害 = 每秒伤害 × 时长）、百分比伤害、多段伤害、条件伤害、增伤效果。实在算不了的技能标为 `unmodeled`。
- **覆盖率**：构建脚本输出"需要人工确认的技能"清单。先整理用户常遇到的对线英雄。对线对手如果有 `unmodeled` 技能，计算结果是下限，播报时说"至少约 X"。

```json
{
  "patch": "7.xx",
  "heroes": {
    "lina": {
      "attackRange": 670, "baseAttackTime": 1.6, "damage": [49, 57],
      "abilities": [
        { "name": "lina_dragon_slave", "ultimate": false, "damageType": "magical",
          "cooldowns": [11, 10, 9, 8], "manaCosts": [90, 100, 110, 120],
          "burst": { "damage": [65, 125, 185, 245], "disable": null } },
        { "name": "lina_light_strike_array", "ultimate": false, "damageType": "magical",
          "burst": { "damage": [80, 125, 170, 215], "disable": [1.2, 1.6, 2, 2.4] } },
        { "name": "lina_slow_burn", "burst": { "unmodeled": true } }
      ]
    }
  }
}
```

### 6.3 我的属性（SelfStats）

- 输入：GSI `hero`（等级、血量、`magicimmune`、`talent_1..8`、`aghanims_*`）、`items`（`slot0..5`、`neutral0`）、`abilities`。
- 输出：护甲、魔抗、移速、攻击力、每秒攻击次数。血量直接用 GSI 的数值。
- 计算：基础属性 + 成长 × (等级 − 1) + 物品加成，再按 `rules.ts` 里的规则换算。规则包括属性换算系数、鞋子移速不叠加（取最高）、移速上限、魔抗乘法叠加。
- 天赋：只处理通用数值天赋（`special_bonus_armor_*`、`special_bonus_movement_speed_*`、`special_bonus_attack_damage_*`、`special_bonus_magic_resistance_*`），英雄专属天赋忽略。
- 不认识的物品或被动：忽略，同一局只记一次日志。
- 验收：Phase 0 选几个英雄和装备组合，把计算结果和游戏界面上的数值对比。允许误差：护甲 ±1，移速 ±5。

### 6.4 对手模型

- **敌我**：房间新增 `matchTeams`（§6.11），对面阵营的英雄即为敌人。
- **对线对手 `laneOpponents`**：1–3 个敌方英雄，由学员或房主在界面上指定，换局时清空。没指定时不计算斩杀线，界面提示"选择对线对手"。Phase 3 改为用小地图自动推断。
- **等级**：估算为 `min(30, 我的等级 + δ)`。δ 默认 0，可以对单个对手设置；例如中单对面单人线经验更多，可设 +1。
- **加点**：取**爆发伤害最大的合法加点**。规则：普通技能升到 k 级需要英雄等级 ≥ 2k−1；大招在 6/12/18 级可升，个别英雄例外，写在修正文件里。技能数量少，直接枚举即可。这是最坏情况，会偏保守。
- **技能就绪和蓝量**：第一版假设全部就绪、蓝量足够。
- **装备和天赋**：对线期忽略，误差由统一安全边际 `margin` 兜底，默认 +10%。
- **Phase 1b 可选：推断冷却**。如果 GSI 显示我被眩晕（`hero.stunned`），而对线对手里只有一个人有眩晕技能，就把那个技能标记为冷却中，冷却时间取自数据。这可能误判（例如有人来抓），所以放在功能开关后面，默认关闭。

### 6.5 斩杀线计算

伤害系数：

```
M_物理 = 1 − 0.06·A / (1 + 0.06·|A|)        A = 我的护甲
M_魔法 = 1 − MR（我魔免时为 0）               MR = 我的魔抗（乘法叠加后）
M_纯粹 = 1
```

单个对手的爆发：

```
T     = Σ 控制时长 + 基础窗口（默认 1.0 s）            # 控制时长按顺序相加
n_i   = floor(T × 每秒攻击次数_i)                      # 最坏情况：都在攻击范围内
B_i   = Σ_技能 伤害(技能, 估算等级) × M_类型  +  n_i × 平均攻击力_i × M_物理
斩杀线 = (1 + margin) × (Σ_i B_i) × Π(1 + 增伤)
```

- 输出 `ThreatAssessment`：`{ killLine, hp, ratio = killLine / hp, breakdown: [{ hero, ability, damage }], lowerBound, assumptions }`。`breakdown` 用于界面展开说明；`lowerBound` 表示有未建模技能。
- 示意（只算技能部分）：莉娜 3 级时，爆发最大的加点是 Q2 + W1，伤害为 125 + 80 = 205 魔法伤害；我魔抗 25% 时实际受到约 154。再加上普攻和莱恩的伤害就是总值。先天技能"缓慢燃烧"需要人工修正后才计入。

### 6.6 对线提醒状态机

| 档位 | 进入条件 | 退出条件（迟滞 0.1） | 语音 |
|---|---|---|---|
| 安全 | ratio < 0.7 | — | 不播 |
| 注意 | ratio ≥ 0.7 | ratio < 0.6 | 进入时播；停留在本档时最多每 20 s 播一次 |
| 危险 | ratio ≥ 1.0 | ratio < 0.9 | 进入时播；停留在本档时最多每 8 s 播一次 |

- **启用条件**：功能已开启；已指定对线对手；英雄存活；游戏时间在对线期内（默认 0:00–12:00，可调）；我在线上区域。线上区域在 Phase 0 录制；数据就绪前只按时间判断。
- **档位下降**只更新悬浮显示，不播语音。
- **节点事件**：
  - 我升到 5 级时，如果对面大招会让斩杀线增加 ≥ 30%，播一次 6 级预告。
  - 物品变化让斩杀线变化 ≥ 15% 时，播一次。
- **AlertScheduler**：危险提醒可以抢占排队中的低优先级提醒；生成超过 2 s 还没播的提醒直接丢弃，避免播报过时信息。

**话术模板**：数字四舍五入到十位，既好读，也提高语音缓存命中率。

| 事件 | 模板 |
|---|---|
| 进入危险 | "危险，斩杀线内，后撤。" |
| 进入注意 | "注意，{对手}连招约{X}，你{HP}血。" |
| 6 级预告 | "对面快 6 级，{英雄}有大以后连招约{X}。" |
| 装备变化 | "{物品}好了，斩杀线降到约{X}。" |
| 有未建模技能 | 数字前加"至少" |

### 6.7 地图数据 `data/dota2-map.json`

- 坐标系：GSI `xpos/ypos` 的世界坐标。
- 内容：
  - 区域多边形：泉水/基地、上中下路（分阵营）、双方野区、河道。
  - 营地：`id`、阵营、类型（小/中/大/远古）、中心坐标、刷新框半径、拉野时间。
  - 营地数值：按类型取平均的金钱、经验、总血量、每秒伤害、单位数，标注版本。
  - 刷新规则：首刷时间、整分钟刷新等，写在数据里，不写死在代码里。
- **采集方式**：开一个自定义房间，开启 GSI 录制，依次走到每个营地并停留 3 s，再沿三条路各走一遍。脚本 `scripts/calibrate-map.ts` 从录制数据中聚类出停留点，生成数据草稿，再人工命名。每次大版本改图后重录，文件里记录对应版本。

### 6.8 营地状态跟踪

- 每个营地的状态：`假设满`（默认）或 `我已清(t)`。
- **判定"我已清"**：我在营地半径内，期间正补数增加的数量 ≥ 该营地单位数（或 `gold_from_creep_kills` 增加），然后我离开了营地，就记为在离开时刻已清空。
- **刷新**：按数据中的规则，一般在下一个整分钟、且营地刷新框内没有单位时刷新。
- **局限**：别人清的营地无从得知，一律当作满营。这个假设偏乐观，在 §10 列为已知局限。

### 6.9 清野模型与自校准

```
普攻DPS  = 攻击力 × 每秒攻击次数 × M_物理(野怪护甲)
范围DPS  = Σ_范围技能 伤害 / 冷却 × 命中单位数
清野时间 = 营地总血量 / (普攻DPS + 范围DPS) × k
受到伤害 = 营地每秒伤害 × 清野时间 × M_物理(我的护甲)
```

- `k` 是本局校准系数。用实际清野时间（进入营地半径到最后一次正补的间隔）对比预测值，用指数移动平均更新；初始值 1.0，限制在 [0.5, 2]。
- 如果预计打完一个营地后血量低于 30%，在路线里优先安排回血或回线。

### 6.10 路线规划

- **候选点**：己方野区中预计到达时是满的营地。敌方野区作为可选项，默认关闭，等 Phase 3 有了敌人位置后再开放。后续可以加"回线收兵"节点。
- **路程时间**：直线距离 × 1.25 ÷ 移速。
- **搜索**：从最近的 8 个候选点里枚举长度 ≤ 3 的序列（最多 336 种）。
  - 打分 = (金钱 + 0.5 × 经验) ÷ 总耗时 − 惩罚项（低血量、敌方野区）。
  - 计入整分钟刷新：已清的营地过了整分钟、且我不在刷新框内时，重新可用。
- **触发方式**：
  - 按需：桌面快捷键或网页按钮。
  - 自动：我在野区且刚清完一个营地时。
  - 后台每 10 s 重新规划一次，但只在"下一步"变化或用户主动询问时才播报。
- **输出**："下一个：{营地}，{秒}秒到；然后{下一个营地/时间点}。"

### 6.11 房间状态与界面

这些都是**运行时状态**，不放进 `RoomSettings`。原因是修改 `RoomSettings` 会通过 `applyRoomSettings` 断开全员重连。

| 新字段 | 说明 |
|---|---|
| `matchTeams: { radiant: string[], dire: string[] }` | 来源：视觉识阵直接提供；GSI 提供本机英雄和阵营；选人面板增加敌我标记 |
| `laneOpponents: string[]` | 学员或房主设置，换局清空 |
| `tactics: { enabled, laningEndsAt, margin }` | 房间级开关和参数 |
| 每个连接的 `tacticalVoice: boolean` | 学员是否接收语音提醒 |

新增 WebSocket 消息：`room.set_match_teams`、`room.set_lane_opponents`、`room.set_tactics`、`client.set_tactical_voice`、`tactics.request_route`。`room.state` 中包含上述字段。

### 6.12 提醒输出

- **文字事件**：
  - `tactics.state`：最多每秒 2 次，包含斩杀线、血量、档位、数值明细和当前路线，供界面显示。
  - `tactics.alert`：单条提醒。
  - 教练端显示英文标签的数值面板，不播语音。
- **语音**：服务端用 `AzureTtsPoolClient` 和房间的 `ttsZhVoice` 合成语音，只发给 `tacticalVoice=true` 的学员连接。固定话术放入 LRU 缓存（200 条）。
- **二进制帧**：新增帧头 `0x03` 表示战术提醒（参考 `src/app-server.ts:233` 的帧格式）。
  - 网页目前不区分帧头，任何帧都直接播放（`public/app.js:708`）。
  - 桌面端只接受 `1` 和 `2`（`NativeVoiceChannel.cs:128`），需要升级；旧版本会静默丢弃 `0x03`，不会出错。
- **播放**：网页现在所有音频共用一个 `nextPlayTime` 排队。战术提醒要**另开一条播放时间线，与翻译语音混音**，不能排在长句翻译后面。桌面端同样处理。
- **桌面悬浮**（Phase 1b）：在 `SubtitleWindow` 中增加一行常驻显示，例如"斩杀线 ≈ 480 ｜ 你 620"，不需要语音也能看到。

## 7. 延迟预算

| 环节 | 预算 |
|---|---|
| GSI 节流 + 缓冲 | ≤ 0.6 s |
| 网络到服务端 | ≤ 0.1 s |
| 战术计算 | < 5 ms |
| TTS 首包（命中缓存则约为 0） | ≤ 0.5 s |
| 推送到客户端开始播放 | ≤ 0.2 s |
| **合计（P90）** | **≤ 1.5 s** |

  - 用 GSI 测试数据计算 SelfStats。

## 10. 风险与已知局限

- **假设偏保守**：假设技能全部就绪、蓝量足够、加点爆发最大，会导致"注意"档偏多。靠迟滞、限频和只播档位上升来压低噪音；阈值用回放数据调。
- **不知道对面在不在附近**：Phase 3 之前，斩杀线说的是"如果对面现在出手"，不是"对面就在你身边"。
- **复杂技能覆盖不全**：未建模技能会让结果偏低，播报时用"至少"标明。
- **版本变化**：技能数值和地图会随版本改变。每个版本更新后需要重新构建数据、必要时重录地图；数据文件带版本号，版本不一致时服务端打印警告。
- **别人清的野不知道**：路线可能指向已被清空的营地。Phase 3 可以部分缓解。
- **Valve 政策风险**：见 §2。
