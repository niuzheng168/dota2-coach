# Luna 本地模型闭环 E2E：已通过

日期：2026-11-16（香港时间）。本机源码版本 **v0.1.2**。

**通过范围：同一台电脑上的两个独立客户端，真实 Dota 机器人局画面＋自身 GSI → 真实 Foundry 大模型 → 条件化下一步方案 → 原始帧时效复核 → 游戏内字幕和小地图目标 → 到期清除。最终连续 3 次全部通过。**

不是诊断测试图、mock 模型、人工填写标记或仅有“发送成功”的日志；已保存实际屏幕像素并做对照检查。

## 场景和信息边界

- 已安装 Dota build 6975、7.41f 地图参考，1280×720 客户区、DPI 240、默认左下小地图。
- 本地 `matchId=0`，天辉 **Luna**；实际游戏画面显示10级。
- 官方自身 GSI 核对：动力鞋、疯狂面具、月光3级、环月2级、月刃4级、月蚀1级；血1220、蓝555。
- 等级、装备及起始位置由**本地受控测试夹具**设置，不是自然发育或收入实验。测试场景位于己方下路与下侧营地之间；没有进入真人匹配。
- 测试准备通过本机安装的游戏控制台接口完成。临时控制台使用每轮随机口令；实际验证未认证命令被拒绝，认证命令可执行。其监听并非操作系统网络沙箱，结束后已关闭端口、删除口令和临时脚本。
- 游戏端只做采集、传输和绘制。实际视觉与决策由用户指定独立配置对应的 **`gpt-6-astra` 云端部署**执行；不是3090 Ti本地视觉模型。
- 模型输入仅有真实玩家画面、白名单自身 GSI、静态地图地标，以及从100场研究中提取的三场、六条带窗口证据引用的历史观察。没有注入当前全图敌人、野怪存量或旁观者信息。
- 测试夹具移动英雄只用于准备画面。**教练客户端不执行英雄移动、攻击或施法命令。**

### 地图点不是手填的

1. 模型从**未排序的己方静态地标目录**选择 `targetId`，可以选择不标记。
2. 程序校验该ID存在、阵营符合当前自身状态；敌方地标和捏造ID拒绝。
3. 使用已核验的 Valve overview（左上世界坐标 `(-9472,9472)`、跨度18944），投影到本次测量的160×160小地图区域。
4. 11号营地落在原始1280×720画面的约 **(73.92,705)** 像素；实际游戏左下出现了对应黄色圆环和箭头。

这是**下一步目标点**，不是已验证的完整世界路径。静态地标的阵营不证明当前安全、存怪或塔仍存活。其他分辨率、右侧小地图或自定义HUD没有复用这次标定的资格。

## 回归与排障结论

- **88项**协议、真实TLS/GSI、模型调用约束和投影检查通过。
- **27项**实际 WPF 窗口 UI 事件检查通过。
- 两端构建零警告、零错误，差异空白检查通过。
- 最初三次较长模型请求超过11秒，均被取消、没有回传；没有放宽12秒原始帧时限来凑通过。
- 精简输出、明确地图目标ID、固定坐标投影后，完成上述三条真实闭环。没有规则路线回退。
- 修复验收启动竞争：教练端新配对文件就绪后才启动游戏端，避免读取上一进程的旧凭据。
- 同一验收过程重启游戏端时，只能复用散列未变化的专用GSI文件；普通启动仍使用新凭据。

最终三次验收模型用量 **28,781 tokens**。包含排障及两个接口探测的本轮**已记录至少59,318 API tokens**；另有3个取消请求没有返回usage，不能把这个下限当完整账单，也不含Codex对话或早先100场研究。

## 复测方式

在仓库根目录，先确认没有其他测试客户端占用端口：

```powershell
# 创建独立验收目录并启动两端；此时不调用模型
.\desktop\run-local-e2e.ps1 -Action Start -FoundryEnvFile C:\g\foundry.use2.env

# 记下脚本输出的目录。加载生成的GSI，进入本地机器人局，确认真实画面后显式启用
.\desktop\run-local-e2e.ps1 -Action Arm -RunDirectory <本次目录>

# 最多3次模型请求（可显式设置1–6）；只接受本地matchId=0
.\desktop\verify-local-e2e.ps1 -RunDirectory <本次目录> -MinimumCompleteChains 3

# 停止两端，并在散列相符时移除本次GSI和配对文件
.\desktop\run-local-e2e.ps1 -Action Stop -RunDirectory <本次目录>
```

默认10分钟自动结束测试客户端；正常应用启动不会自动读取云端密钥。不要用旧v0.1.0游戏端验证新的实验提醒类型。v0.1.2已在本机构建，未覆盖旧发布ZIP。

夹具源文件保留为 `scripts/client/coach-live-e2e-fixture.lua` 和 `coach-live-e2e-observe-camp.lua`。它们只用于你拥有的、明确开启作弊的本地测试进程，分别准备装备技能和观察位置；不能在真人局或用户正在进行的其他游戏上执行。正常客户端不会加载它们。首轮选人界面快捷键不可用，最终通过已验证的游戏控制台 `dota_select_hero npc_dota_hero_luna` 完成选择；不是把自动随机到的其他英雄标成Luna。

本轮专用GSI、Lua夹具、临时按键、配对文件、控制台口令与测试进程均已清理；测试监听残留为0，未修改防火墙。Steam原有会话保留。

## 尚不能由本次结果证明

- 两台物理电脑的网络表现、游戏帧率/帧时间、零性能损失。
- 3090 Ti上的本地模型速度和识别准确率。
- 复杂局势下路线质量、完整通行路径、真实收益或最高GPM。
- 夜魇真实对局、其他分辨率/HUD的像素验收；只有阵营/投影约束单元检查。
- 当前云模型耗时8.6–10.1秒，导致严格时效下字幕只显示约1.6–2.9秒。**数据闭环通过，但低延迟体验仍不达标，也不适合据此声称已经能做秒级拉野提醒。**

普通实战自动路线仍保持关闭；这次通过的是明确限定的本地机器人局实验链路。
