# 补刀视觉模型：从画面认出兵的出手

[补刀实验室](last-hit-lab.md)测出：只看血条，红字要提前约 1 秒判断兵的血量，补到率约 63–66%；如果能从画面上认出正在打这只兵的出手（近战兵抬手到命中 0.47 秒，远程兵抬手 0.5 秒加弹道约 0.3 秒，攻城车约 1.4 秒，塔约 1.2 秒），露娜能到 76%、主宰 84%；认出得晚 100 毫秒只少约 2 个百分点。这里是训练这个模型的数据和脚本。

## 数据：实验室录画面

```powershell
dotnet build desktop/DotaCoach.GameClient -c Release
node scripts/lasthit/lab.ts Z:/dota2coach/data/lasthit-vision/rec1.jsonl --frames Z:/dota2coach/data/lasthit-vision/rec1 --hero npc_dota_hero_luna --seed 11 --rounds 40
dotnet run --project desktop/DotaCoach.TwoPc.Tests -c Release -- --vision-label Z:/dota2coach/data/lasthit-vision/rec1.jsonl Z:/dota2coach/data/lasthit-vision/rec1
```

- `--frames DIR`：记录模式，按实时速度跑（动画和画面一致）。每回合随机一天中的时间（白天、夜晚光照不同）。游戏端（实验室参数 `--frames`）把 Dota 窗口的客户区每秒存 30 张 JPEG（质量 92），Dota 在别的窗口后面也照存。只在实验室里用，正式版不会存画面。
- 竞技场额外记录每次攻击的**抬手开始**（`swing`）和**出手**（`launch`：近战这时命中，远程这时放出弹道），来自挂在每只兵、塔和英雄身上的 `modifier_coach_watch`。
- 1080p 下约每小时 10 万张图、57 GB。

每次录制的文件：

| 文件 | 内容 |
|---|---|
| `recN.jsonl` | 引擎真值：每 1/30 秒所有兵的血量、位置、攻击目标（`f`），英雄（`h`），每次伤害（`dmg`，`inflictor` 为 -1 的是普攻），`swing`、`launch`、`kill`、回合（`round`，含 `daytime`） |
| `recN.sync.jsonl` | 每个服务器帧的第一行到达本机的时间（和画面同一个 QPC 时钟） |
| `recN/NNNNNN.jpg` | 画面 |
| `recN/frames.jsonl` | 每张图：文件名、采集时间 `at`（QPC 秒）、游戏端找到的血条 `[x, y, 行数, 填充像素, 友方, 被遮挡]` |
| `recN/labels.jsonl` | `--vision-label` 生成：每张图的服务器时间 `t`、镜头注视点、每根血条属于哪个单位（`bars`，-1 为没配上）、所有单位血条中心在屏幕上的位置（`units`：`[id, x, y]`） |

**对齐**：服务器时间 = 画面采集时间 − 偏移 − 画面滞后。偏移取同步文件里此后 3 秒内“到达时间 − 服务器时间”的最小值（服务器卡顿时游戏时间会少走一截，偏移随之上跳：rec1 在第 116 秒少了 0.75 秒，所以按每张图各取）；画面滞后按“配上单位的血条显示的填充像素和引擎血量算出的一致”拟合（试录：约 0，一致率 77–81%，精度约一个服务器帧 33 毫秒）。血条配单位用产品同一套方法（引擎位置代替 GSI），试录配上 93–96%。

试录（smoke4，3 回合）核对过：近战兵抬手到命中 0.467 秒、远程兵 0.5 + 0.3 秒、攻城车 0.7 + 0.73 秒、塔 0.53 + 0.63 秒；每次伤害都找得到之前的出手；目标死了的抬手会取消（约 6%）。

## 训练样本：`scripts/lasthit/vision/prepare.py`

```bash
python scripts/lasthit/vision/prepare.py REC.jsonl REC_DIR OUT_DIR [--near 256] [--far 768] [--size 128] [--steps 0,1,2,4]
```

- 每张图里每只兵裁两块，以兵身（血条中心下方 40 像素）为中心：**近**（256 像素见方，看贴身近战兵的抬手）和**远**（768 像素见方，看远程兵、塔的出手和弹道），都缩到 128×128，JPEG 存进 `crops.bin`。尺寸按 1080p，其他分辨率按高度缩放。
- 样本：游戏端找到并配上单位的每根血条。输入是这只兵在这张图和之前第 1、2、4 张图（0、33、67、133 毫秒前）的两块裁图；目标是接下来 1 秒内每 0.1 秒落到它身上的兵和塔的伤害（不含英雄：自己的出手玩家知道，实验室里没有敌方英雄）。附带它自己正在抬手的进度和目标方向，以及血量、兵种、回合、离死还有多久，供分析和辅助训练。
- 试录 2146 张图生成 12568 个样本、13142 对裁图，159 MB（原图 1.2 GB），8 进程 21 秒。

## 训练：`scripts/lasthit/vision/train.py`

```bash
python scripts/lasthit/vision/train.py OUT DATA_DIR... [--test DATA_DIR...] [--epochs 12] [--batch 512] [--workers 16]
```

- 模型：近、远两块各一个小卷积网络（4 帧叠成 12 个通道，128 → 4×4），拼起来过两层全连接，输出 10 个 0.1 秒格子的伤害（softplus），另有辅助输出：自己是否在抬手、抬手进度、目标方向。约 450 万参数，ONNX 18 MB；CPU 上 16 只兵约 22 毫秒，显卡上会快很多，游戏机上要实测。
- 回合号是 5 的倍数的回合做验证；`--test` 留出整段录制（例如换英雄、换种子的那段）测泛化。每轮输出到 0.3/0.5/0.8/1 秒累计伤害的平均绝对误差，和“总猜平均值”对照。
- 输出 `model.pt`、`model.onnx`（输入 `near`/`far`：uint8 `[n, 12, 128, 128]`，输出 `damage`：`[n, 10]`）、`log.jsonl`、`predictions.npz`。
- 环境：Python 3.12、PyTorch（CUDA）、numpy、pillow、onnx、onnxscript、onnxruntime。`--limit 600` 可在任何机器上几分钟内跑通一遍。

## 交给训练机：`scripts/lasthit/vision/pack.py`

训练不在开发机上做，交给另一台 A100 上的会话；数据经 Azure Blob 传过去（私有容器，SAS 由训练机会话用本机临时 RSA 公钥加密后发来，私钥只在本机）。

```powershell
python scripts/lasthit/vision/pack.py Z:/dota2coach/data/lasthit-vision rec1 .tmp/upload
```

每段录制打成 `runs/REC/`：轨迹、同步文件、日志、`frames.jsonl`、`labels.jsonl` 原样，图片按约 1.5 GiB 一片打成不压缩的 tar（成员路径 `REC/NNNNNN.jpg`），最后写 `manifest.json`（每个文件的字节数和 SHA-256）；全部传完再放 `_SUCCESS`。已录：rec1 露娜、rec2 主宰、rec3 卓尔游侠，各 40 回合、约 19 分钟、3.4 万张图；试传用 rec2 开头 4 分钟（rec2-head4m，7193 张）。

## 离线测补到率：`--last-hit-eval … --pictures`

```powershell
dotnet run --project desktop/DotaCoach.TwoPc.Tests -c Release -- --last-hit-eval REC.jsonl --fps 30 --height 1080 --pictures REC_DIR `
  [--model weights.json] [--golden golden.json] [--margins -20,-10,0,10] [--hero npc_dota_hero_juggernaut] [--repeats 20] [--chances-out FILE]
```

用游戏端在录下的画面里**真正读到**的血条（`frames.jsonl` 的填充像素，`labels.jsonl` 配的单位和服务器时间），对最后一秒在屏幕上的每个补刀机会，按第一张红字的图模拟玩家（和 `Decompose` 同一个玩家：反应 0.2±0.04 秒或正好 0.15 秒），比较：同一批兵在模拟屏幕上的血条节奏（产品现在的规则）、真画面上的血条节奏、真画面上的模型（红字条件：血条最多的血 + 回血 − 模型预测到命中时的伤害 ≤ 最弱一刀 + 余量；超过 1 秒的部分按最后半秒的速度外推），以及“看得见出手”和引擎两个上限。带 `--model` 时先用训练机给的 golden 向量核对特征和网络，再在全部配上单位的血条上算 0.3、1 秒伤害的平均绝对误差。模型的 `weights.json` 由 ONNX 导出（三层全连接，C# 直接算，不需要 ONNX Runtime）。

每只兵在每种预测下用同一组随机数（额外延迟、反应、伤害浮动），重复 `--repeats` 次取平均；模型各个余量和产品规则逐只配对，按回合（一波兵、一个镜头，是独立的单位）给出差值、重采样回合的 95% 区间和好/差/平的回合数。`--chances-out` 把这批固定的补刀机会和每只的期望补到写成 JSONL。**这是录像回放加模拟玩家，不是真人实战的补到率。**

2026-11-24 第一版候选 `bar-874768f16703`（训练机用 rec1 + rec2 训练，只用血条历史 20 个特征；画面融合没过它预先定的门槛）在**没参与训练的 rec3** 上：golden 向量最大差 5.7e-6 HP；17.8 万根血条上 1 秒伤害误差 11.2 HP（猜 0 是 22.7），0.3 秒 5.0 HP（6.8），和训练机自己的留出结果一致。余量在 rec1 + rec2 上按补到率挑（那是模型的训练数据，预测偏准，挑出的余量可能偏激进），再用到 rec3。rec3 的 138 个补刀机会（35 个回合），反应 0.2±0.04 秒：

| 模拟的英雄（判断提前量） | 模拟屏幕 / 节奏 | 真画面 / 节奏（产品） | 真画面 / 模型（余量） | 配对差（95% 区间；回合好/差/平） | 看得见出手 | 引擎 |
|---|---|---|---|---|---|---|
| 主宰（0.50 秒） | 25.1% | 24.6% | 34.3%（0） | +9.6（+4.2..+15.2；20/5/10） | 45.4% | 77.7% |
| 露娜（0.93 秒） | 53.8% | 46.6% | 45.0%（−15 HP） | −1.6（−8.3..+5.2；12/17/6） | 67.8% | 82.8% |
| 卓尔（1.18 秒） | 46.8% | 42.6% | 45.4%（−25 HP） | +2.8（−4.2..+10.3；14/11/10） | 58.9% | 82.5% |

- 模型对近战（判断窗口短）明确好约 10 个百分点；远程和现在的节奏规则分不出高低。远程要往保守调 15–25 HP（第一次越线的那张图往往是预测偏高的那张），余量 0 时露娜、卓尔反而少 7 个点左右。它和节奏规则用的是同样的信息（血条），所以超不过“只看血条”的上限；要接近“看得见出手”还得靠画面。
- 真画面比模拟屏幕少几个点（露娜 54→47%，过早 5→12%）：读血条的误差本身也是一个可以改进的地方。
- 卓尔的判断要看 1.18 秒，模型只预测 1 秒。
- rec3 有 33,736 张图，最后一张（033735.jpg）存盘时游戏端已在退出，`frames.jsonl` 没有它那一行，所以带标注的是 33,735 张。

## 还没做

- 模型直接学“现在按下、h 秒后命中能不能补到”（h 作为输入，输出概率或分位数），预测到 1.5 秒；有了能超过血条的画面模型，再接进游戏端实测延迟和补到率。
- 数据只有中路竞技场、默认兵模型、没有敌方英雄和技能特效；真实对局的画面更乱。
- rec1–rec3 录制时实体编号在后几回合被新一波兵复用而没有重新描述（rec3 有 18 只兵）；之后的录制每个新实体都会重新写 `unit`，`--vision-label`、`prepare.py`、`--last-hit-eval` 按时间查单位，旧录制里这些兵被略过。
