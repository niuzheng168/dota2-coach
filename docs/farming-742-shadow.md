# 7.42 打钱影子观察：下一次本体补刀更像兵线还是己方营地？

**可以运行，也会弃权；不能据此自动选路。** 在按时间封存的最后 4 场里，历史检索只在 **4/116** 个窗口给出宽类预测。这 4 个都命中，但全部来自**一个露娜账号**；检索与时钟基线同时出手的 2 个窗口都是 **2/2**。没有证明检索优于基线，更没有证明它能提高实战收入。

截至本次 **2026-11-22** 本地快照，[扩展采集审计](farming-742-expanded.md)有 101 场目录/分钟数据（露娜 65、巨魔 36），有本体轨迹与击杀归属的仍是 **16 场／13 个目标账号**（两英雄各 8 场，各 6／7 个账号）。扩展档新增可定位回放 **0**。已优先跑扩展档，也独立保留原档结果；**不是两份独立证据，不能相加**。另外 85 场没有进入检索、基线、时间切分、命中率或覆盖率的分母。输入缺轨迹或击杀事件流的分钟行会在切分前排除，纯分钟文件不能用来建这个索引。

## 给手动输入桥

模块：`src/tactics/shadow-742.ts`。无服务器、网络、凭据或游戏依赖，建索引一次即可复用。

```ts
import { buildShadow742Index, observeShadow742, shadow742StillCurrent } from './src/tactics/shadow-742.ts';

const index = buildShadow742Index(corpus);                  // 只读的历史空间回放
const r = observeShadow742(index, observation, { signal }); // 当前玩家自己的数据 + 手工确认
// 绘制前，用刚取得的 latest 重验，不要反复给同一条缓存消息续期：
if (r.status === 'observed' && shadow742StillCurrent(r, latest, { signal })) {
  // 可展示 r.broadCandidates 或 r.candidates 的历史票数；不得执行或播成行动指令。
}
```

| 输入 | 含义 |
|---|---|
| `informationScope:'player-visible'`, `patch:'7.42'`, `matchId`, `timeSec`, `hero`, `team` | `timeSec` 为本局游戏秒；英雄用 `luna` / `troll_warlord`，阵营用 `radiant` / `dire`。库外局须传 `matchStartUnix`（Unix 秒），不拿未知开局时间搜索全库。 |
| `accountId?`, `contextId?`, `capturedAtMs?` | 已知就传当前账号，尤其是回测；库内局从元数据取真实开局及目标账号，不接受冲突覆盖。库外没给账号时明确返回 `account-not-provided`，不能称已排除同人。实时手动桥应传上下文 ID 和采集墙钟（Unix 毫秒）；后者须不在未来且不旧于 5 秒。省略墙钟只适合按游戏时钟演示已有记录。 |
| `self:{observedAtSec,alive,canAct,position:{x,y}}` | 只读本体，世界坐标；自 `timeSec` 向前最多 3 秒，不能用镜头中心、队友英雄或未来位置。`canAct` 未知时不展示。可选 `itemsSeen:[{itemId,seenAtSec,matchId}]` 只接受本局 **已经亲见过** 的主槽物品；不是“现在仍持有”。 |
| `visibleTargets:[{targetId,matchId,seenAtSec,source:'manual-confirmed',state,area}]` | 对同局、最近 3 秒内的**手工确认**取最新状态。`state:'present'/'empty'/'unknown'`；`area:'own'/'enemy'/'unknown'` 为目标所在段的目击，不是通行许可。只保留 `present + own`；同秒冲突按未知。拒绝自动 `screen`、`minimap`、`replay` 来源。填 `[]` 是没有确认，不是全空或全满。 |
| `dangerVisible?`, `cancelled?` / 第三参 `{signal}` | 看见危险、死亡、不可行动、主动撤回时停止展示。换局、英雄、阵营、账号、上下文、时钟回退/过期、依据目标变空或消失，`shadow742StillCurrent` 拒绝复用。危险未报告不意味着安全。 |

`targetId` 是 `good_1`、`evil_2` 等 7.42 出生器编号，或 `lane:bot`、`lane:mid`、`lane:top`。敌方营地即使填成 `area:'own'` 也会被拒。兵线 ID **不是** 地图地盘，仍须手工确认眼前那段在己方区域。接口信任适配器提供的是手工事实，字符串本身不能证明来源；不要给回放全图、纯扫描结果或推断的单位盖“手工确认”标签。

**两个输出不要混读：**

- `r.broadCandidates` 至多一项，`family:'lane'|'own-camp'`。只有历史严格多数支持，而且本局至少有一个已确认的同类目标才展示。`visibleTargets` 列出的是**输入事实，不是对这些具体地点的预测**。若 `reason==='visible-family-only'`，就没有具体地点证据。
- `r.candidates` 是历史有**同一地点**标签且本局刚确认的交集。两项都附历史票数、以全部邻居为分母的频率、描述性 Wilson 95% 区间和可追查的比赛 ID/时钟。历史证据中的秒数属于**另一场已结束的比赛**。没有把遮掉的标签剔除后重新归一化。
- `status` 为 `observed` / `abstain` / `cancelled`；始终 `mode:'read-only-shadow'`、`liveActivation:'disabled'`、`pathSafety:'unknown'`。己方营地不等于安全，未验证去路、追击、弹射、队友占用或实际净收益。即便所有候选为空也**不回退为固定路线、最近营地或自动模型实战策略**。区域约束沿用[既有撤回审计](sandbox-own-area-audit.md)。

示例的**当前观察是虚构的**，不是评估样本；其邻居来自真实已结束回放。固定档下，4 个独立历史账号中 3 个的下次标签为己方营地，只有 2 个为 `good_1`：可说“己方营地类 3/4，具体 `good_1` 2/4”。显式标空的 `good_2` 不展示；不意味着需要前往 `good_1`。

## 怎样从录像学习，什么绝不用作当前状态

1. **固定决策时钟。** 每条空间轨迹在 5:15、5:45、…、19:15 取样，每次观察未来 30 秒的标签。特征只用 `t` 及此前最近一次新鲜、存活的**本体**坐标、`firstHeld[item] <= t` 的正向自身目击，以及英雄/阵营。绝不从 `t+1` 插值，也不以“最后一次持有”、之后的首次购买、死亡位置、胜负、MMR 或金币做查询特征。`matchId/accountId/start` 只用来隔离历史。相邻营地、未见敌人、路径几何都不生成“可见目标”。
2. **标签与输入分仓。** `events` 只生成 `(t,t+30s]` 内**首次本体打钱击杀**的来源。兵线取小兵出生线，野点取出生营；都不是目的地、清完一营或路线安全。幻象不算本体。先碰到归属不明、演员不明或同秒多种来源，留作未知，不向后挑一条好猜的。首个是对方营地记作越界类别；没有本体击杀记作无补刀。完整窗口里的这两类都不是宽类或地点预测的“命中”。
3. **不补齐短局。** 末界点缺失用实际轨迹、事件、已采样端点的时间（扩展档可用 `endPoint.t`）保守界定记录结束，并受实际时长限制。尾部不足 30 秒的整窗右删失，即使已有一次击杀也不偏选；比赛已结束的网格单列。经济计数的值完全不参与检索或标签。测试覆盖短局。
4. **经验条件概率，不训练权重。** 只检索同英雄、同阵营已结束回放中时钟相差 ≤90 秒、本体相距 ≤2400 世界单位的历史决策点。按 `距离²/1200² + 时差²/90²` 排列；若至少两个历史账号也已见过查询中的全部正向物品，限定在这批目击内，否则只用时空条件（缺失仍未知）。每账号最多一票，取最近的至多 7 个账号，少于 2 个弃权。没有为谁在哪分钟刷哪营写分支，也没有按留出结果拟合权重。
5. **先合类、再决定是否出手。** 主任务把各出生营聚为“己方营地”，把三条出生线聚为“兵线”；某一类必须占全部历史票 **> 1/2**，否则弃权。越界、无补刀、未知票都留在分母。不是先挑一个营地再给它改名。精确地点是另一项诊断，按历史票数排序，同票优先较近案例。没有因果标签或反事实收益，不报“最优路线”。

## 真正的留出与结果

**主时间切分**：按开局时间封存最新四分之一比赛，切点同秒的整批一并留出。固定/本次扩展档的切点为 **2026-11-21 00:21:16 UTC**。训练 11 场／9 个账号，测试 4 场／4 个账号。较早的 `9098472218` 因账号在测试集而整场剔除。训练不能有测试比赛，或有任何测试目标账号的其他英雄、阵营、轨迹；`开局 + ceil(时长)` 须严格早于切点，结束不明或重叠的也排除。该结束时间是可复核的代理，不是实测录像发布时间。测试 ID、账号、剔除列表均在机器报告中。无法隔离未提供的其他九位玩家、隐匿号或同人的不同账号。

**补充滚动切分**：16 场轮流作测试，训练库只含当时已经结束、与该局及目标账号都不相交的回放，最早几场无历史也计入。较早的测试局可以在较晚、不同账号的一折中成为历史。它与主留出有重叠，不能把两份结果相加。两种切分都单列英雄、阵营以及 5–10／10–15／15–20 分钟。

**基线**：同一折训练库、同英雄/阵营、同一 ±90 秒时钟窗的历史频率；不看位置或装备。每账号总权重为 1，不让多场账号淹没其他人。宽类使用相同严格多数和至少两个账号。下表“命中”为各方法出手且真值明确时的精度；比较优劣须看**同窗**一列。

- **弃权也算成本。** 主留出 116 个完整窗口中：93 个缺至少两个相近的独立账号，8 个本体已死，11 个历史无严格多数，剩 4 个。3 场夜魇巨魔共 87 窗全部弃权，不能把露娜的 4/4 推给巨魔。滚动宽类 72 次出手中 1 次真值不明。按全部完整窗计正确覆盖，主留出检索为 **4/116，基线 9/116**；滚动为 **40/464，基线 60/464**。滚动三个五分钟段的检索覆盖分别为 **38/160、24/160、10/144**。
- **不确定性**按测试目标账号重抽样，若一个测试 match 有多条目标账号轨迹，把相连比赛/账号算作同一簇。固定种子、2,000 次簇 bootstrap；只有一个有效簇时不报区间。主留出宽类覆盖 95% 区间 **0–10.3%**；4/4 命中及 2/2 配对只有一簇，区间不可估。滚动宽类覆盖 **6.2–24.6%**；条件命中 **45.5–67.2%**（7 个有效簇）；配对差 **+5.6 个百分点，95% 区间 0.0 至 +11.8**（6 簇，含零）。这些是对当前选择样本的描述，不是部署保证。候选上的 Wilson 区间另指少量历史账号票，不能代替留出区间。
- **精确地点是次任务。** 主留出有历史地点排名 15/116；14 个已知真值的共同窗口，检索 7/14、基线 6/14，仅一账号。滚动有排名 126/464；同窗 49/118 vs 36/118。不同任务的覆盖率和精度不可互换。
- **当前可见候选展示：主留出 0/116，滚动 0/464。** 本包不含目标的手工 POV 标注，也没有 `canAct`，不能将击杀、主体附近的营地或静态地图反喂成当时的可见清单。用这些真实缺失字段调用公开接口必须弃权。真实手工输入时的展示覆盖率、命中、走路安全和经济增益均**未测**；不能用上表历史诊断的命中率充数。
