### 夜魇远古附近“很多野”的解释

三场的初始出生器中，**夜魇常规远古营地都是一个：`neutralcamp_evil_8`**，并不是把附近多个普通营地都认作远古。
在第一场的约 10:00 快照，这个出生器所属的存活野怪为 **6 只**；另外两场都是 **3 只**。
同一营地的单位数会因堆野/清理而改变，不能把多个单位等同于多个营地。

旧页面没清楚区分营地类型、单位数量，还画了穿过野区内部的**示意兵线**。
这使画面和模拟行为都可能误导。新的核验页用菱形标远古、圆圈标其他营地、方形标塔；
点击营地展示该时刻**回放实际出生器所属**的活单位、名称和血量，不使用随机生成的野怪。

### 已证实的旧模型缺口

- 旧下路几何从野区内部穿行，与固定地图的沿边路径不同；新页面可叠加“旧错误兵线”直接比较。
- 树木被压进 64 单位网格并统一扩张 80 单位，无法表示砍树/动态通路。
  三场 Luna 的 10–13 分钟实际路径各有 **43、21、42 个样本落在旧网格的阻挡格**。
  这可能包括砍树、碰撞膨胀、特殊移动等；不能简单删除这些格子让测试变绿。
- 旧模拟将野怪移速统一设为 300，不能覆盖实际单位字段。
- 河道斜线已移除。现在背景是固定版本原始 overview；**它只证明图像参考，不是水流区域/方向/加速或碰撞模型**。
- 塔坐标有了，但没有把“能画塔”冒充“塔攻击机制已接通”。

运行 `npm run sandbox` 后，**默认入口现在是地图/回放核验页**，不再默认展示随机出兵沙盒。
原机制实验保留在 `/sandbox`，依旧禁用路线建议及付费规划。

核验页提供：

- 三场可切换原始回放，10–13 分钟每 5 秒一个快照；不会伪造中间单位插值。
- 全场解析中的 Luna 细粒度实际坐标，用于显示这段轨迹；大的位置跳变不画成步行直线。
- 原始地图底图、静态树点、双方六条地图兵线路径、防御塔与真实活单位。
- Luna 等级、血蓝、主背包装备、兵线/野怪分账和逐项核验结果。
- 底图缓存缺失会明确提示，不画假河道替代；不会从图片颜色推断通行性。

**回放是全图离线数据，不是用户实战可见信息。**
录像中的敌区行动不能直接照搬。新数据没有被自动送进实时规划器；敌区约束仍然生效，建议开关保持关闭。

## 获取与复现

解析器采用 **gem-dota 0.14.0** 的底层 `ReplayParser`，另查阅了 Manta / Clarity 的官方仓库说明。
没有调用 gem 的规则化 `build_farming_routes` 等实验分析模块，更没有让固定循环生成路线。

```powershell
# 本项目内的隔离环境，不修改系统 Python 或 WSL
py -3.13 -m venv .tmp/replay-tools
.tmp/replay-tools/Scripts/python.exe -m pip install -r scripts/replays/requirements.txt

# 固定 Git 提交、SHA256 和 Git blob 双重检查；底图仅留本机缓存
npm run map:reference

# 只查公开 API，默认最多 3 场、最多审阅 10 条目录，不自动批量下载
npm run replay:discover -- 3

# 显式下载已选 match ID，不猜 replay salt、不绕过登录/验证码
npm run replay:download -- 9090576268
.tmp/replay-tools/Scripts/python.exe scripts/replays/decompress.py 9090576268
.tmp/replay-tools/Scripts/python.exe scripts/replays/extract.py 9090576268
# 另外两场同理
npm run replay:report -- 9090576268 9088923051 9090701002

# 无云、无真实游戏依赖的复核（完整 facts 需在本机先解析）
npm run map:reference -- --check
npm run replay:report -- 9090576268 9088923051 9090701002 --check
```

已存在文件不会被下载/解析命令覆盖，失败的 partial 保留待检查。
归档上限 512 MiB、解压上限 2 GiB，验证 Source 2 文件头与哈希。
Valve 这三条回放地址走 HTTP，哈希仅建立本地可复现性，不伪称获得了 HTTPS 来源认证。
归档虽然扩展名为 `.bz2`，**这三场实际是 Zstandard**；按魔数而非文件名解压。

本次 Dota2ProTracker / STRATZ 网页返回访问挑战，没有绕过；使用的是可正常访问的 OpenDota API。
目录发现只保留 API 职业赛事中有选手名、rank tier ≥80 的 Luna；匿名、缺段位或较低段位的条目不假定为高分样本。
目录请求可能超时；脚本保存 `partial-error` 和已取得的候选，非零退出，不把旧目录冒充本次完整抓取。
公开回放 URL 是否长期有效没有保证，故保留原始文件，不将整个回放提交到仓库。下文的历史 `.tmp/replays/` 在 Windows 现对应 `Z:\dota2coach\data\replays\`（见[录像工作目录](luna-hundred-study.md#录像工作目录)）。

### 输出

- `data/dota2-map-reference-sources.json`：静态输入的固定提交、实际 SHA256、Git blob、上游 manifest 的差异。
- `data/dota2-map-reference.json`：可复建的营地、树点、塔、双方兵线路径和原始导航参考。
- `data/replay-map-validation.json`：三场完整回放的审计报告、版本/哈希、坐标误差、出生波、金币分账与击杀关联可信度。
- `data/replay-map-samples.json`：网页用的紧凑时间段快照与真实 Luna 路径。
- `.tmp/replays/<id>.facts.json`：完整实体提取，包括每秒全图快照、Luna 细粒度轨迹、出生/死亡与原始战斗日志。

### 解析时发现并处理的问题

1. `EntityNames` 和 `UnitNames` 是两张表。把单位名索引放进实体名表会让 Luna 名字变成营地名，现已分开读取并校验。
2. 全录像包含结束后的录制时间；采样截止于真正 postgame，终局回调后再取一次实体快照，否则补刀可能差 1。
3. 6975 回放的营地框出生器索引字段观察为实体索引的 2 倍。通过 **28 个命名营地的整体一一对应**复核这个转换，
   不是按英雄就近猜营地；其他 build 若不能建立唯一匹配则拒绝。
4. 两个基地四塔可能使用相同单位名，校验用唯一地图实体 ID，不用名称去重。
5. 营地击杀只在相同 tick、单位定义名对应到唯一营地时关联；三场分别有 34/238、48/295、27/259 条不能消歧，保留 `unresolved`。
6. 固定上游提交的 manifest 对 `mapdata.json`、`building_vision.json`、`overview.json` 有陈旧哈希。
   没有忽略错误后假称通过：保留差异，实际输入逐项与该 Git 提交的 blob ID 核对，再固定实际 SHA256。
