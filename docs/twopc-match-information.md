# 双机教练 v0.6.1：实时对局档案与赛后全图复盘

自 v0.6.0 起，一场正式对局在教练机上有一份档案。**采集、显示和分享给模型是三件不同的事。** 关掉游戏端装备面板，不会停止已经配置的装备来源或抹掉读过的装备；开启赛后录像也不会把录像中的敌人或眼位加进实战输入。

**解压包里的入口：** 本页是包内 `README.md`。不传画面先看 `NO-VIDEO.md`；模型服务、分钟路线分别看 `MODEL-PROVIDERS.md`、`MINUTE-FARM.md`。小兵、Plus 提醒、眼位和显示设置分别看 `CREEP-HP.md`、`PLUS-ALERTS.md`、`ENEMY-WARDS.md`、`GAME-OVERLAY.md`。`USAGE.md` 保留 v0.4.3 的历史操作。下文的仓库链接使用源码文件名。

## 实战怎么用

1. 游戏机和教练机分别运行同版本 `DotaCoach.GameClient.exe`、`DotaCoach.CoachClient.exe`；同一台 Windows 11 x64 也可以两端都开，用 `127.0.0.1` 配对。游戏端连接后只传本人 GSI，不传画面，即可记录。首次写入 GSI 配置后，Steam 启动选项加 `-gamestateintegration` 并完全重启 Dota。
2. 接收到经验证的本人对局号、阵营、英雄和游戏时钟后，教练端自动记录；**不需要打开 Debug、开模型或使用露娜/巨魔**。每个游戏秒采样本体位置、血蓝、可读的等级与经济、物品槽/技能冷却；阵亡、装备变化和阶段切换另记。数据源没给的字段留空，暂停/断线也不会生成虚假的比赛结束。
3. 要记录敌方装备和插眼线索，在教练端「Plus 实时观战」接入同一场、同阵营的**队伍视角**。需要读装备栏时开启「启动视觉扫描」，配置本机扫描素材和 Python 环境（见[视觉扫描与守卫](twopc-enemy-wards.md)，包内 `ENEMY-WARDS.md`）。没有这个来源时，档案只有实际收到的本人等信息；不会猜出五名对手的出装。远端全图观战、错局、错阵营、未来或过期的数据不进入实战资料。
4. 游戏端可分别显示敌方装备、眼位和兵线。装备保留到局末，标明**上次读到**的槽位和年龄；实际目击与推测眼位分开显示，未校准时眼位仍使用游戏端自己的小地图设置。**兵线与迷雾推演**要求标准 7.42 / build 6989；和眼位一样，没确认 HUD 框时按游戏端自己的小地图设置画；实见小兵、进雾估计、理论增援和交汇各有标记。只下发过滤后的结果，不是原始小地图或录像，也不是给队友发 ping。
5. 露娜/巨魔的 **7.42 / build 6989** 分钟规划仍需显式开启、确认本局和小地图。默认用本人状态、地图和时钟模拟行程，提供三路空线交汇基线。要让 LLM 同时参考团队信息，勾选模型设置中的 **「允许分钟模型读取本队当时已知的装备、视野、推测眼位及兵线」**。模型只得到请求开始那一刻的快照，不补用之后的观测或录像全图。模型弃答、失败或过期不回退成固定指令。详细操作见[分钟打钱](twopc-minute-farm-742.md)和[模型设置](twopc-model-providers.md)；发布包内分别是 `MINUTE-FARM.md`、`MODEL-PROVIDERS.md`。

每个分钟请求在发出前，会把**实际要发的结构化比赛数据**（包括候选路线、行走/访问预算、可选的团队信息）和对应档案序号写入本机。复盘的「教练决策」可以看到它当时有哪些选择，以及最后选择、放弃还是超时。没有成功保存输入就不会发出这个付费请求；“准备发送”也不是“已经收到答复”。

## 赛后怎么查

在教练端主页点 **「打开对局复盘窗口」**，选择对局号，拖动游戏时间游标，按装备、视野、眼位或规划筛选。重新启动客户端仍能打开以前的记录。

| 视图 | 游标回答的问题 |
|---|---|
| **当时已知** | 到这个游戏时间，教练实际收到过什么？有两个时刻：事件发生/来源采样时间，以及本机最早获知的游戏时间。比如 12:04 才收到 12:01 的队伍视角，拖回 12:02 时不会显示这条消息。 |
| **录像全图** | 已结束的比赛中，回放实际记下了什么？展示双方的英雄位置/等级/血量/物品、观察/岗哨守卫生命周期、已确认的英雄死亡及支持的地图目标事件。 |
| **并排对照** | 用同一时间看两条记录。可对照「当时推测这里有眼」与「录像里实际的放眼位置」，而不是让录像覆盖原判断。 |

在录像窗格可选择双方十个席位中的任意英雄。坐标图和装备栏使用**游标之前最近一帧**的记录；未选定的英雄或缺失的坐标仍显示未知，不会从未来补值。

**加载录像：** 对于已验证终局并封存的本地档案，点 **「下载官方公开录像」**，或者 **「导入本地 .dem / .dem.bz2」**。下载时先查公开终局元数据，再从允许的 Valve 录像主机取文件；不登录 Steam、不猜回放盐、不访问游戏进程。下载不是后台自动任务，可能因录像过期或服务不可用而失败，可取消或改用同局号的本地 DEM。若只记录到断线、没看到可信终局，则保留已有时间线但不解锁录像。外部团队扫描工具和赛后 DEM 解析器相互独立；**发布包的教练端已包含解析器运行时**，解析 DEM 不需要另装 Python 或 Node。

解析会核对 DEM 内部局号、终局结果及录像完整性。英雄按约 **5 个游戏秒**采样，同时保留终局状态；选人前没有英雄的席位明确记为未知。只要录像包含，双方英雄、装备、眼位等不限于己方战争迷雾。按选定英雄和阵营席位核对后，另保留**净值、正补、反补、累计所得金、击杀小兵所得金和当前经验**的直接读数；累计所得不等于身上可花的金币。旧档案没有这些字段时仍能打开，缺失项标为未知。**“全图”不是“每一帧、每个实体、每个数值都已导出”**：例如还没有逐帧技能冷却、每个野怪的视野和每次移动指令。看不见守卫不等于它被拔掉，录像中没有删除证据也不会编造消失时间。

## 本地文件与边界

- 档案在教练机 `%LOCALAPPDATA%\DotaCoach\MatchArchive\<对局号>\`。`live.jsonl` 是按序追加的实战资料，`sealed.json` 表示终局，`replay.json` 是独立的赛后资料。导入只会原子替换赛后文件，不改写实战事实、原始序号或当时的模型输入。
- 不在档案里保存配对码、API 密钥、Steam 账号、聊天、截图或原始 GSI 包。原始 DEM 只在解析作业中临时使用，结束后保留核验过的时间线；自行准备的原始文件不会修改。需要备份时先关闭教练端再复制整个档案目录。
- 如果另一个教练端占用了目录，或磁盘写入失败，窗口会标出 **「仅实时显示」**。配对、装备/眼位显示仍可继续，但不再写这段历史、发起实战付费决策或加载录像。释放目录或修复磁盘后重启；不会悄悄切到另一个档案，或把这段缺失补成“没有敌人”。
- 下载/解压有大小与时间上限：公开元数据 8 MiB、压缩回放 512 MiB、解压 DEM 2 GiB，建议临时盘预留 **3 GiB**。每局实时文件上限 128 MiB；录像时间线 32 MiB / 10 万事件。空间或写入异常会提示，不会静默把缺失当作零。

## 可复核的实测

用公开已结束比赛 **9097559249** 做了完整下载与解析，并与本地同一 DEM 的结果比较。含经济的时间线逐字节一致（2,037,899 字节；SHA-256 `8bcd9ca84b345e8ff2fbaa54faa714645d9b9bda29d637aa9c2604fd42a69d9f`）：从赛前到 **24:47.433** 得到 **3,599 条事件**。十个席位中，3,170 条已选英雄采样有经济读数，另 250 条选人前的记录没有补值。65 次首次观测到的放眼，**55 次在当时的录像标志中对敌方不可见**；另有 54 次有证据的移除。详情及采样覆盖见仓库的[赛后解析验证记录](../scripts/replays/postgame/VALIDATION.md)。这不是声称当时的玩家知道那 55 个眼位。

另走通了原生教练窗口的端到端流程（左栏为**合成实战输入**，右栏为上述真实 DEM）。在 24:45 采到、24:46 才收到的装备和眼位，倒回 24:45 均不可见；导入录像前后的实战文件逐字节不变。仓库中可打开 [并排复盘截图](../benchmark-results/match-full-journey-9097559249-v2/comparison.png) 或查看 [测量记录](../benchmark-results/match-full-journey-9097559249-v2/journey.json)；教练端解压目录中也有 `MATCH-REVIEW-EXAMPLE.png`。
