# Windows 双机客户端：7.42 分钟打钱路线（v0.5.0 引入）

**看游戏里的小地图，不用切到网页。** 露娜或巨魔在打普通对局时，游戏端读取本机玩家 GSI。教练端用这一刻的本体位置和状态模拟“打野、接线、野后回线”等可行行程，让已配置的大模型在这些行程中选择一个，或不作建议。游戏端把 **1–3 个有先后顺序的目的地**画在你自己的小地图上，不向队友发 ping，不移动英雄。

## 开一局

1. 两端使用配套的 **v0.6.3** 客户端。可以在同一台 Windows 11 x64 电脑运行 `DotaCoach.CoachClient.exe` 和 `DotaCoach.GameClient.exe`，教练端接收地址选 `127.0.0.1`；用两台电脑则选局域网地址。按[模型服务说明](twopc-model-providers.md)在教练端选 Foundry 或 Codey（GitHub Copilot）；复制配对码，不要公开配对码或模型密钥。
2. 游戏端粘贴配对码并连接（只传本人 GSI，不传画面；本机小兵血量照常可开关）。游戏端会安装 GSI 配置。首次安装或配置更新后，在 Steam 的 Dota 启动选项保留原参数并加 `-gamestateintegration`，**完全退出再启动 Dota 一次**。游戏建议用无边框窗口。仅 GSI 模式不需要传视频、不需要 Dota Plus、观战账号或扫描器。
3. 教练端主页勾选「自动教练」和「**7.42 分钟打钱**」，「设置 → AI 模型」里保持「小地图路线」勾选。第一次在该分辨率使用，打开「设置 → 小地图校准」：选**左下**或**右下**预设，必要时填实际 HUD 地图正方形的左、上、边长（原始游戏像素），点「**确认校准**」。游戏端不传画面，没有预览底图；如果不知道自定义 HUD 的准确边界，在游戏机截一张图量出小地图正方形的左、上、边长再填。
4. 进入有正式对局号、进行中的本人对局后，确认**本局是标准 `dota` 地图、7.42 / build 6989，且小地图框已对准**。可在游戏机安装目录的 `game\dota\steam.inf` 检查 `appID=570`、`ClientVersion=6989` 和 `ServerVersion=6989`。换局或重新配对需再确认，不是每分钟确认；换地图、客户端更新或 HUD 改动后不要沿用旧确认。`provider.version` 不是这个版本证明。
5. 游戏保持可用，回到 Dota 看编号。关闭教练端「游戏字幕」可只看标记；关闭「小地图路线」或点「撤回本局确认」则停止这项工作。开启分钟模式后，即使未确认或模型报错，也不会偷偷走旧的截图/7.41f 路线逻辑。

## 如何读一分钟

比如刚接入时已经是 **10:17**，只规划到 **11:00**，不是重新从 10:00 算 60 秒。① 表示先到的位置，②、③ 是后续目的地。字幕显示对应地标及预估到达的游戏时间。「有野再打」「有线再收」是条件：没怪跳过，兵不在或走过去有危险就别接。地图点不是路径拐点，也不是有视野的标记。

[看编号标记的实际绘制效果（局部示意）](../benchmark-results/minute-farm-742-overlay-example.png)。这是把本版悬浮组件画在已存的 HUD 底图上，不是 7.42 排位实录；发布包里也附有 `MINUTE-OVERLAY-EXAMPLE.png`。

**一个能复算的模拟例子，而非固定路线：** 10:00，假设天辉 10 级露娜已在一塔旁小野 `good_1`，移速 370、面板攻击读数 120、总攻速 180。一条候选是 **① 就地查看小野 → ② 回下路接线点**：第一站预算到 10:23，若此时离开，按静态通路约 10:30 到线。它不表示野点一定有怪、10:30 一定有兵，或者模型在你的对局一定选这条。对同样从小野出发的夜魇巨魔，比较的是夜魇上路的地标，而不是把地图镜像。

- **只问一次。** 同一真实对局、同一游戏分钟、同一教练进程最多一次模型请求（失败也占用），不是每收到 GSI 或视频帧就请求。还没有可行候选时可以本地重算，不计费。进程请求上限和模型超时沿用「设置 → AI 模型」。
- **只标来得及的。** 模型选择整条已模拟行程，不能自造坐标。模型返回后，用新鲜的本人位置和本分钟剩余时间重算，只保留原顺序中还能完成的前几站；没有可行前缀、模型弃答、超时或越过整分就不画。不把上分钟的路线续到下一分钟。
- **会撤回。** 死亡、暂停、失去可靠本人数据、对局或 HUD 不匹配、断线都会使旧结果失效。仅沉默（例如露娜开疯脸）不等于不能走或普攻，所以不会只因沉默就撤掉路线。仅 GSI 模式不采集游戏画面；悬浮层仅在 Dota 窗口处于前台时显示。游戏内的走位、危险判断仍由你完成。

## 模拟知道什么，不知道什么

| 输入或结果 | 依据与边界 |
|---|---|
| 当前位置、英雄、阵营、游戏时钟、血蓝、装备/技能 | 默认只取经验证的本人状态，不含图片、聊天或观战原包。对局号用于本地绑定，不随模型请求发送。仅在另行授权后，才附上请求发出时本队已知的装备、视野、推测眼位和兵线；思考期间的新读数及赛后全图不会倒填。见[对局档案](twopc-match-information.md)。 |
| 哪几个点走得通 | 构建资产来自 **build 6989** 的导航、树木/障碍、出生器和实际兵线路径。只在保守划定的己方区域找静态通路，不拿两点直线距离假装路径；己方半场不代表安全。兵线点是接线观察位置，不是假设兵线在那里。 |
| 行走、清营和接线预算 | 模拟用面板属性（有则采用）或 build 6989 英雄基值估步行及普通未堆叠阵容的普攻时间。超出可估范围或仅能短暂停留，写「限时探营」：这是**该离开的时间**，不表示能清完。20 分钟后不外推早期清营耗时。兵线仅估到达，不捏造处理一波兵要多久。 |
| 兵线在哪里交汇 | 本机按三路估算 **两边兵首次进入 500 世界单位内时的中点**，不是开始攻击或还剩多少兵。无 Plus 时，分钟模型仅有按时钟推出的下一次同批空线交汇；另行授权队伍信息后，可参考实见接近、双侧位置外推，或单侧位置配假设增援。交汇点不是英雄目的地，不改写路线标记。 |
| 高分局习惯 | 105 场 D2PT 分钟记录中，仅 16 场有可定位的回放（8 露娜、8 巨魔），从中提取 240 个 5–20 分钟的录像分钟；只有与当前英雄、时段相符的那一行匿名汇总才进模型。例如 5–10 分钟露娜本体同分钟既有线补又有己方野补 **26/40**，巨魔是 **16/40**。不是当前视野、营地占用或指定路线。 |
| 金钱 | 现有离线模型可以在已知怪物组合和版本档位下核验毛赏金；实战 GSI 不能确认野点现状，分钟模式不承诺某一营或某条路线的实际金币/GPM。 |

没有标记时先看教练端状态行，再看：客户端是否配套、是否有新鲜本人 GSI、对局号和本局确认、当前分辨率是否**已确认**、当前区域及剩余时间是否有可行路线、模型配置/调用上限。正常的弃答不是断线；不会用固定循环填空。

## 读实时兵线：不用开模型

教练端按**当前游戏秒**计算三路交汇、在途增援和最近所见个体的短时外推；中途在 20、40 或 70 分钟接入，不用从开局补放。配对两个支持兵线 HUD 的客户端，在教练端「设置 → 小地图校准」确认实际 HUD 框。教练端「设置 → Plus 观战与扫描 → 兵线与迷雾推演」和游戏端「设置 → 游戏内显示 → 在小地图显示兵线与迷雾推演」默认开启，可以分别关闭。无需开启模型，也不向队友发 ping。教练窗仍显示时刻和相对该路塔原址的位置。**塔原址是地标，不表示塔还在。** 需要标准 7.42（build 6989 或本局人工确认）。没有 Plus 队伍视角时只有按当前时钟出发的假设增援、空线理论交汇和可能的残兵区域，不会从录像里读出迷雾真值。

| 显示 | 含义 |
|---|---|
| 实见双方兵已接近 | 本队小地图在标出的采样时刻确实给出了附近的两方线上兵；不证明谁在打谁。 |
| 双方可见前排推演 | 沿**各自**的兵线路径从实测坐标出发，估计接下来 40 秒内最早的接近位置。 |
| 仅见一方兵 | 从可见前排出发，对面只是假设从界面标出的 `:00`/`:30` 刷出的增援沿空路正常走，不把隐藏的兵记成已见。 |
| ○ 迷雾外推 | 每个小空心点锚定一个过去确实看见过的小兵。按同阵营、同路、同兵种、合理位移做一对一关联，估算沿线移动；GSI 没有可靠个体 ID。邻近同型兵可能换位。至多保留 12 个游戏秒；刚在交汇中消失最多 4 秒，不穿过已知交战区假定胜出。友军近旁丢失、位置矛盾或超时就收回，**不是确认死亡**。虚线范围随时间变大，并非覆盖率保证。 |
| △ 理论增援、× 交汇 | 从六条各自的路径按出生时钟推出**波的位置**，不是凭空给未见小兵逐个报坐标。实见交汇用交叉，预测带 `~Ns` 倒数；已经可能交战的理论波只留不确定区域，不模拟出一队必然存活的小兵继续推到基地。 |
| 最后交汇处／若守 | 若最后实见的前线明显偏离河道，单兵痕迹消失后最多 30 秒保留该区域。`若守~Ns` 指**假如前线还在此处**，下一批增援约多久到，不代表仍有兵。一旦看见线已推过旧点、分线冲突或超时即撤。 |
| 当前线未知／空线基线 | 无队伍证据、当前可见兵不能配对或多个地方同时交汇时，不指定一个“当前交汇点”。另显示同批兵从两侧出生器畅通前进的参考位置与时间。 |

几何来自本 build 的六条 `path_corner` 链；325 是单位 KV 的基础移速，不是实测每个兵当前移速。每个游戏秒从同局、同阵营的 Plus 数据重算；延迟观战、错局、未来包、来源达到 3 秒、`(0,0)`、视野半径为零或未给、明显脱线或分路不清的单位不用。剔除可疑条目不等于判定它死了；视野半径也不是可见性真值。模型**不模拟**卡兵、勾仇恨、拉野、清兵、残兵交战、塔火或路上变速；不保证到了还有兵或可以安全去收。精确到秒的界面时间是估计，不是误差上界。

**离线核对：** 3 场 build 6989 真实录像，固定在游戏 **0:12 后第一个采样**预测三路，另从实际出生小兵的实体轨迹找第一次接近（9 个交汇，约每秒采样）。不以未来帧修正预测，也不认定比赛里没有人卡兵。双方起点都给时，时间/位置绝对误差中位数 **1.4 秒 / 126 世界单位**，最大 **3.4 秒 / 449**；只按时钟的基线是 **1.9 秒 / 455**，最大 **5.3 秒 / 951**。人工只保留天辉或夜魇一侧的输入时，位置误差中位数分别为 **190 / 257**。这是开局小样本、非真实 Plus 迷雾覆盖率或中后期准确率。复算：`node scripts/replays/lane-wave-openings.ts`，再运行 `dotnet run --project desktop/DotaCoach.TwoPc.Tests -c Release -- --lane-wave-eval <输出的文件>`。

**另测整局迷雾与中后期。** 用同三场录像（9099209663、9099283649、9100049738）的引擎队伍可见性位，分别以天辉/夜魇视角按秒输入小兵。预测阶段不读实体编号、未见敌兵或未来帧；另一个评分文件按“当时最后看见的坐标 → 原实体”核对。第 5 分钟以后每 5 秒取一次，共 **2,172 张队伍视角图，最长比赛采样至 37:29**。这不是当前真人 Plus 实机对照；重放只给可见兵，不使用可选的己方英雄邻近证据。

| 时段 | 外推的敌兵点次 | 评分时仍存活且确实在雾里 | 这部分的位置误差，中位 / P90（世界单位） |
|---|---:|---:|---:|
| 5–15 分钟 | 1,000 | 473 | 172 / 1,232 |
| 15–30 分钟 | 2,550 | 1,420 | 164 / 1,288 |
| 30 分钟以后 | 868 | 415 | 195 / 1,488 |

不能只看存活者的误差：全部 4,418 点次中，**1,422 点次**当时已找不到那个存活实体，**688 点次**并非该实体真的在雾里。单点绝不能作为该波一定有钱收的凭据。每 30 秒另核对未来 40 秒内、该出生路双方兵的首次接近：有起点的交汇预测发出 412 次（2 次按真值已接近，10 次窗口内无交汇）；其余 400 次时间误差中位 **2 秒**、P90 **16 秒**，位置误差中位 **696**、P90 **4,650**。纯空线基线的 18 次可比未来交汇位置误差中位约 **4,978**。出生路不等于当前所在路，拉兵、拆塔和多处同时打兵都会影响这个比较。**不要用开局准确率担保中后期。**

复算：对上述局号分别运行 `python -B scripts/replays/lane-wave-visibility.py <局号>`，再运行 `dotnet run --project desktop/DotaCoach.TwoPc.Tests -c Release -- --lane-wave-fog-eval <产物目录>`；Windows 默认产物在 `Z:\dota2coach\data\farm742\tmp\wave-visibility-6989`。`--wave-overlay <overlay-example.json> <输出.png>`（UiTests）用实际游戏端绘制器在六条路的示意底图上渲染；不是比赛截图。
