# 刷野路线规划：第一版实现与数据调查

更新：2026-11-15（北京时间）。对应 `tactical-assistant-design.md` 的刷野部分，提前于斩杀线实现。

> 以下是数值原型的历史实现记录。按用户后续要求，生产默认已改为大模型提案与工具复核，无规则选路回退；最新说明见 [多录像与模型推理](luna-multi-replay-reasoning.md)。本文件的 beam 搜索描述仅对应保留的离线基准。

当前目标：在血蓝安全约束下，寻找 180 秒内**预计野怪掉落总金钱最多**的路线。已移除三步/最近八点限制；次数和经验只展示，不给路线加分。支持 Luna 月刃、刷新回访和框外等待。

**状态：可运行的实验版，不是已通过实机验收的竞技辅助。** 数值/地图来自固定快照；营地组合仍待核验。默认关闭。没有敌方位置、游戏内存、抓包、键鼠控制或观战信息输入。

**Luna 数值更正（2026-11-15）：** 对话中“10 级、满月刃、假腿疯脸，三分钟约 940 金”来自 `.tmp` 中的专项简化实验，不是实测，也不是生产模型已支持这套装备的证明。该实验缺少主动环月、动态升级等机制，不能作为实际刷野能力或上限。录像核对及下一轮验收条件见 [Luna 7.41f 核验记录](luna-741f-validation.md)。

后续已逐段分析录像，并给出“天辉内侧短循环＋按刷新选择外侧支路”的[条件路线与路径图](luna-741f-validation.md#6-基于该思路的天辉纯野候选路线)。核验还发现当前将水生营地套作普通营地的缺口；**下面描述的是现有实现，不能据此宣称新路线的战斗动作或水生进化已经支持**。

## 2. 已实现的计算链路

### 地图，不再先画一张“猜出来的地图”

- 坐标统一为 GSI 的世界坐标，刷新框采用资源中的实际边界。
- GNV `Traversable=1`、`Blocked=2`、`HeroBlocking=4`，结合静态树木得到步行网格。
- 八方向 Dijkstra，禁止对角穿墙；以营地为目标缓存距离场，房间之间只共享**静态**路径数据。
- 起终点不可走或不连通时返回无路线，**不退回穿越悬崖的直线估算，也不把玩家“吸附”到悬崖另一边**。
- 网页显示坐标示意图、步行折线、路线顺序和己方营地选择；不假装这是小地图识别结果。
- “上/下/左/右侧、边缘”是按坐标生成的辅助名称，编号是地图资源里的 camp ID，不是官方野区名称。
- 不处理砍树、树再生、飞行、跳跃、传送、双生之门和动态阻挡；静态树的碰撞近似仍需校准。

### 英雄属性

- 基础属性 + 成长 ×（等级−1）+ 装备白名单，计算攻击力、护甲、攻速、移速和回复。
- 使用各英雄**自己的基础攻速**，不是统一写死 100。例如快照中 Sven 是 110。
- 只计算 `slot0..5`、`neutral0`；背包、仓库不加属性。GSI 物品的 `passive=false` 不是“属性失效”，不会因此漏掉动力鞋等可主动使用的物品。
- 鞋子移速取最高；分裂和补刀斧额外对野怪伤害单独计入。
- 动力鞋当前切换属性未知，暂不加那 10 点属性，明确显示警告。
- 只采用 GSI 明确给出的已学技能等级、当前冷却和蓝量，不替玩家编造加点。
- 不支持的英雄机制、技能、物品效果在面板中列出；特别不保证变体精灵、米波、德鲁伊、幻象流、复杂被动/成长叠层英雄的准确度。

### 清野模拟，而不是“总血量 / 泛用 DPS”

- 0.1 秒离散模拟，每只野怪独立血量、护甲、魔抗、攻速、回复和死亡状态。
- 普攻伤害使用护甲公式；法术按照物理/魔法/纯粹分别减免。
- 优先击杀剩余血量最低的单位；死掉的单位不再攻击，泥土傀儡死后才加入碎片单位。
- 技能消耗蓝量、占用施法时间、按实际冷却再次就绪；保留至少 15% 最大蓝量，走路期间冷却和回复继续推进。
- 第一批明确建模：
  - Sven：风暴之拳、巨力挥舞；
  - Luna：月刃逐次弹射、递减伤害；已有单位都命中后允许弹回仍存活的单位，不向当前弹射目标自身连弹；
  - Ursa：震撼大地、怒意狂击逐目标叠层；
  - Axe：反击螺旋按受击次数触发；
  - Lina：龙破斩、光击阵；
  - Crystal Maiden：冰霜新星；
  - Dragon Knight：火焰气息；
  - Centaur：马蹄践踏；
  - Magnus：震荡波。
- 群体技能命中数和分裂站位仍是假设；没有模拟上述技能的所有控制、命石、天赋和升级效果。没有把名称含 `damage` 的任意字段自动当成伤害。
- Luna 使用快照的 `bounces=[3,4,5,6]`、`damage_reduction_percent=[50,45,40,35]`；逐目标计算物理护甲，不把被动数据中的默认伤害类型误当魔法伤害，也不把补刀斧额外伤害复制进弹射。假设营地内单位在弹射范围内，不模拟弹道飞行时间、主动环绕刃、暴击或临时攻速/攻击力增益。数值已与 Valve `https://www.dota2.com/datafeed/herodata?language=english&hero_id=48` 交叉核对，未升级原有快照。
- **未模拟野怪技能、光环、治疗、攻击类型特殊修正和召唤**，只给普攻承伤加 15% 不确定性余量。这不构成安全保证；不能把输出理解为经过验证的真实斩杀/安全血量。
- 各类营地对所有代表组合分别模拟：收益等权平均，耗时取最大、剩余血蓝取最小，并显示最快—最慢区间。保守包络会降低连续路线的收益，但避免把“平均野怪”当成真实的一只怪。

### 按时间窗口规划连续刷野，不固定营地数

- 候选包含全部可走到的己方营地，按 **180 秒窗口**规划。快清英雄可以刷多个营地，再跨整分钟回访；没有“每分钟三波”或“三分钟三个点”的规则。
- **唯一收益目标是窗口内预计掉落总金钱**：`score = Σ 已完成营地的 expectedGold`，单位为金，不是次数、经验或短时金钱/秒。候选队列排序、搜索剪枝与最终选优统一使用此目标，经验不参与平局判定。
- 单营地 `expectedGold` 来自各代表组合中每种野怪的单位数 × 单位平均金钱，再考虑数据中的随时间成长，并按当前假设的组合概率取期望。当前组合概率均等，尚未实机核验；不是每个营地固定加同样的分。
- 例如同一窗口内“2 次清野赚 600 金”应优于“更多次清野只赚 240 金”，即使后者经验更多。金钱相同时才比较完成时间、剩余血蓝和稳定排序。路程、等待和清野耗时影响能否在窗口内拿到钱，不用缩短分母来抬高短路线得分。
- 只计本路线中窗口内清完的营地掉落，不含被动收入、兵线/英雄击杀收入或尚未完成营地的部分击杀收益；也不把经验直接折算成金钱。
- 使用 5 秒时间桶，每桶最多保留/扩展 12 个候选状态，约束计算量而非输出营地数。搜索会丢弃备选，不保证全局最优。营地间路径按本次规划缓存，不为每条分支重复寻路。
- 每条搜索分支独立传递血量、蓝量、技能就绪时间和清空记录，不能在下个营地“重新满蓝”。
- 同一营地只有越过有效刷新时刻才可重新计算收益；包括只有一个可用营地时先走出刷新框、等下一波再回来。有效等待不再被旧的 12 秒等待上限排除。
- 规划记录框外等待位置 `waitAt` 和假定刷新时刻 `spawnAt`。`arrival` 是等待结束后真正到达营地的时刻，不是在框内提前到达再假装等到了刷新。
- 按路径和时间核对未完成的刷新：例如 `x:59.8` 开始离开、`x+1:00` 仍在刷新框内，就将该营地可用时间推迟到下一分钟，不能立即再刷同一波。已存在的野怪不会因为经过整分钟就消失。
- 页面优先显示**预计总金钱**，每一步显示该营地的预计金钱和累计金钱；窗口、清野次数、不同野点数、经验作为辅助信息。重复营地在地图上合并标注如 `1/8/14`，紫色标记是框外等待点。完整路线可滚动查看，语音仍只读下一步。
- 任一步剩余血量低于 30% 或无法在模拟时限内清完，会排除该分支。预测不安全时返回补给建议；**尚未规划泉水、商店或兵线节点**。
- 清空状态可以手动校正；自动推断要求在同一营地内观察到足够的正补增长，再离开，金币变化本身不算证据。
- 自动推断仍可能把其他来源正补算入、漏掉多波堆野或未满足阈值的少怪组合，因此显示为假设。只基于符合条件的观测更新本局耗时校准系数 `[0.5, 2]`。
- GSI 驱动，每 10 秒重算；死亡、无法行动、低血量、显著位移等会撤回或更新路线。超过 8 秒没收到合格玩家数据会撤回路线。

## 3. 大模型怎么用

用户允许大模型做规划，并明确允许 **GPT-6 Astra** 这类更强的模型。下一版采用“强模型提出和搜索策略，确定性工具负责验证”的方向，而非只让模型在现有 12 宽度搜索得到的候选 ID 中选一个。

**以下是设计，不是已接入的功能。** 当前运行时仍使用确定性限宽搜索，没有发起 Astra 付费请求，未验证当前 Azure/Foundry 资源是否有对应部署。

### 模型和职责

- 规划模型目标为 `gpt-6-astra`，独立配置模型/实际部署名，不更改现有视觉识阵或语音翻译模型。2026-11-15 已读取 OpenAI 官方模型页及 function calling 文档；工具调用采用 Responses API。官方模型存在不代表当前租户具有访问权限。
- Astra 可查询静态地图和英雄数据、提出新的行动序列、调用仿真、根据失败原因继续修改；不局限于原有限宽搜索的候选集。
- 数值工具返回预计掉落总金钱、耗时、刷新记录、血蓝轨迹、建模缺项和失败原因。最终收益只能来自工具，不能采用模型回答中的自报金钱。
- 当前工具不能模拟的行为必须返回 `unsupported`，例如未经实现与校准的边走边打、合拉多个营地、堆野、主动环月。不能因为强模型提出了这些行为，就假定它们已被模拟和验证。
- 仍以 180 秒内**预计野怪掉落总金钱**为唯一收益目标；纯野与线野混刷必须使用不同的任务范围和统计口径。经验可通过真实升级影响战斗能力，但不能直接加进金钱评分。

### 工具接口方向（尚未实现）

1. 查询本机状态与版本化地图：固定 camp ID、刷新框、可行走路径、已知清空记录、英雄技能/物品及缺失项。
2. 模拟行动序列：先支持移动、已建模的技能/物品使用、清野、框外等待、刷新回访；之后逐项加入经实测的引野、合拉和堆野。没有按真实行为建模前，不开放对应工具。
3. 对比已验证的路线：保留数值工具产生的结果与调用记录；让模型继续尝试新路线，而非只改写旧路线说明。
4. 最终提交：引用已验证结果 ID；服务端重新校验，拒绝未知营地、重复计钱、跨刷新错误、不支持的动作、超时或不安全路线。

### 异步运行和过期处理

- 三分钟是计划覆盖窗口，**不是允许把三分钟前的状态原样应用到现在**。规划期间继续处理 GSI 和安全撤回，不阻塞同传、房间事件或现有数值回退。
- 每房间最多一个待处理任务；换局、换英雄、关闭功能、死亡等取消或使结果失效。普通 GSI 更新不应每 0.5 秒重新发起一次付费请求。
- 返回时用最新本机状态重放剩余路线并重新计算新的时间窗口；不得只平移旧时间戳。失效路线丢弃或重新规划。
- 显式限制总请求时限、工具调用数、输出 token 和每房间请求频率；超时/不可用时说明降级原因。更强模型不构成延迟或全局最优保证。
- 不上传 GSI token、玩家身份或房间密钥；外部录像只用于离线校准，不能把观战敌人信息注入局内规划。

不复用同传引擎的翻译提示词来做战术决策，也不把大模型算术当成战斗计算器。

## 4. 使用和开发

1. 正常启动服务，登录房间；房主**重新下载 GSI cfg**。本次新增 `abilities/items`，`throttle=0.5`、`buffer=0.1`。继续使用该房间专属 GSI token。
2. 在自定义局/机器人局中测试。第一版尚未采集真实玩家 GSI 样本，不能保证当前客户端玩家模式一定提供所有必要字段；缺失坐标等信息时页面明确等待，不会借用观战信息补齐。
3. 房主或学员在“刷野路线 · 实验功能”开启开关。状态属于房间运行时，不写 `RoomSettings`，不会重连或重启同传引擎。
4. 查看自动路线，或点“规划下一步”/页面内 `Alt+J`；“这里已清空”用于修正选中的营地。
5. 可选本地中文朗读，仅学员接收，默认不朗读；没有已安装的本地中文音色则只显示文字。不依赖云 TTS，不占用翻译音频队列。**未实现 Windows 全局快捷键、原生悬浮面板或 `0x03` 音频协议**。

```bash
npm run typecheck
npm test
node tests/jungle.browser.mjs       # 需要已有的 Playwright + Chromium
npm run build:jungle                # 从固定提交重新构建，不是自动追踪最新版
# 可使用自己准备的、与固定提交一致的源文件缓存：
npm run build:jungle -- --cache=/private/path/to/source-cache
```

构建器会校验同一固定提交下已有的输入 SHA-256，并检查营地元数据中的补丁及 GNV 散列。缓存目录不是授权来源：首次使用自备缓存仍需核对提交，不能混放不同补丁的源文件。升级时先修改版本/固定提交，复核组合和技能适配，再整体重建、运行测试，不要单独换地图。

### GSI 采集与回放

```bash
GSI_CAPTURE_DIR=/private/gsi npm start
npm run replay:gsi -- /private/gsi/<room>-<UTC-date>.jsonl
```

- 采集默认关闭，只在验证 GSI token 后写入；排除观战块。
- 递归移除认证、Steam ID、玩家姓名，包括 `previously` 中的信息，保留英雄/技能名字。
- 私有目录 `0700`、新文件 `0600`；后台顺序写盘，最多 16 个排队任务，每房间每日文件上限 32 MiB。
- 超限会丢弃录制帧；这不是审计日志。定期清理私人录制目录，不要提交原始录制。
- 回放读取 `{receivedAt, payload}` JSONL，输出规划/收益/校准时间线；没有接入未实现的斩杀线指标。
