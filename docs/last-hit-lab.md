# 补刀实验室：用自定义游戏核验红字时机

[小兵血量](game-creep-hp.md)的红字要在“现在出手、这一刀落地时能补到”的那一刻出现。这需要知道出手到命中多久、兵还会挨谁几下。补刀实验室在 Dota 自己的自定义游戏里拿到引擎真值，用来调校和核验这件事：离线评估几秒一轮，可以反复改规则再测；闭环测试用真实的游戏端读画面、按红字出手，由引擎判补没补到。

只在本机自己启动的 `-insecure` 本地游戏里运行：不进匹配，不连别人的对局，有别的 Dota 开着就拒绝启动。

## 组成

- **自定义游戏 `coach_lasthit`**（`scripts/lasthit/addon/`，默认 dota 地图，不需要 Workshop Tools 编译）：中路两座一塔之间轮流三种回合——空地、天辉一塔下、夜魇一塔下。每回合双方各一波兵（2 近战、旗手、远程，每 3 回合加攻城车）对推，英雄（默认 1 级露娜，无敌，不会自动攻击）站在天辉兵后面。兵按比赛时钟加血（和游戏端的假设一致）。每个服务器帧（每秒 30 帧）打印所有线上兵的血量、位置、攻击目标，以及每次伤害和击杀。
  - **记录模式**：奇数回合英雄按引擎血量自己补刀、反补，出手时机故意随机偏早偏晚，用来测下令到命中；偶数回合英雄不出手，这些兵全部留给离线评估。
  - **闭环模式**：英雄只在收到 `coach_attack` 时出手。这是这个自定义游戏里注册的服务端命令，只在本地沙盒里存在，匹配对局里没有。
- **运行器** `scripts/lasthit/lab.ts`：把自定义游戏复制进 `game/dota_addons/coach_lasthit`，启动 Dota、开局、按倍速跑完，记录写成 JSONL；结束后退出它启动的 Dota、删除自定义游戏、恢复 `video.txt`。闭环模式另外启动 Release 版游戏端（实验室参数），收到“数字变红”就按模拟的反应时间 N(0.2, 0.04) 秒发命令；奇数回合按提前看出手，偶数回合按只看这一帧出手。闭环里 Dota 可以在其他窗口后面，游戏端照常识别但不在别的窗口上画数字，也不会抢焦点。
- **评估** `DotaCoach.TwoPc.Tests`：`--last-hit-eval` 用记录把屏幕上的血条（按 4K 或 1080p 的像素取整）逐帧回放给产品同一套代码，模拟玩家在每只兵第一次变红后反应再出手，按引擎血量判补到、太早（落地时兵没死）、太晚（之前被别人打死）、没变红；最后拿同一批兵比较不同的预知（见下文“上限在哪”）。`--last-hit-loop` 给闭环打分，并测屏幕比服务器晚多少。

```powershell
node scripts/lasthit/lab.ts Z:/dota2coach/data/lasthit-lab/luna.jsonl --rounds 120 --timescale 4 --size 1280x720       # 记录，约 25 分钟
node scripts/lasthit/lab.ts Z:/dota2coach/data/lasthit-lab/jugg.jsonl --hero npc_dota_hero_juggernaut --rounds 40      # 换英雄
dotnet build desktop/DotaCoach.GameClient -c Release
node scripts/lasthit/lab.ts Z:/dota2coach/data/lasthit-lab/loop.jsonl --loop --patient --rounds 30 --lead 0.15 --latency 0.03  # 闭环，实时约 15 分钟
dotnet run --project desktop/DotaCoach.TwoPc.Tests -c Release -- --last-hit-eval Z:/dota2coach/data/lasthit-lab/luna.jsonl [--height 1080] [--latency 0.08] [--distance 280]
dotnet run --project desktop/DotaCoach.TwoPc.Tests -c Release -- --last-hit-loop Z:/dota2coach/data/lasthit-lab/loop.jsonl
```

记录和结果在 `Z:\dota2coach\data\lasthit-lab`（`*.jsonl` 引擎记录，`*.cues.jsonl` 闭环收到的红字，`*.hp.jsonl` 游戏端每秒状态，`*.log` 控制台）。

## 测到的事实（Dota build 6989）

| 项目 | 结果 |
|---|---|
| 线上兵出刀节奏 | 近战、远程、旗手都是每 1.000 秒一下（近战 93% 正好在节拍上，远程 83%，弹道距离会变）。同一个攻击者打完一下，88–93% 会接着打同一只兵的下一下。 |
| 塔 | 每 0.833 秒一下（0.9 ÷ 1.1 = 0.818 秒，服务器按每秒 30 帧取整到 25 帧），98% 在节拍上。之前按 0.82 算，已改。 |
| 下令到命中 | 前摇（按攻速缩短）＋实际中心距离 ÷ 弹道速度，再晚约 0.04 秒：1 级露娜 58 次，正对目标中位 +0.02 秒，要转身 +0.065 秒；1 级主宰 83 次中位 +0.03 秒，90% 在 0.13 秒内。产品已加上这 0.04 秒。 |
| 屏幕比服务器晚 | 本地游戏：红字那一帧的采集时间换算到服务器时钟，比引擎血量到达那个数晚中位约 0（−0.016 秒）。联网时再加 ping，由设置里的网络延迟补上。 |
| 画面上的掉血 | 1080p 下一下兵的伤害是 2–3 像素，塔约 11 像素；画面上兵的节拍 1.00–1.03 秒、塔 0.80–0.82 秒，都在 0.07 秒的容差内。 |

## 离线评估：每只兵第一次变红就出手

英雄没碰过、半血以下后死掉的兵；4K 血条，网络延迟 0.08 秒，模拟反应 0.2 ± 0.04 秒，出手到命中按实测的晚到量随机抽取。“上限”是存在任何一个出手时刻能补到的比例。

| 规则 | 1 级露娜（208 只，上限 93%） | 1 级主宰（139 只，上限 92%） |
|---|---|---|
| 只看这一帧（旧） | 补到 31%，太晚 61% | 补到 57%，太晚 34% |
| 提前看 | 补到 70%，太早 11%，太晚 18% | 补到 57%，太早 12%，太晚 29% |
| 提前看＋能等就等（默认） | 补到 66%，太早 5%，太晚 27% | 补到 63%，太早 4%，太晚 30% |

- 露娜分场景（提前看＋能等就等）：空地 72%、我方塔下 63%、敌方塔下 59%；只看这一帧是 44%、11%、23%。主宰在空地上只看这一帧已有 90%，提前看主要帮在塔下（18% → 35%）。
- 提前量要配合反应：反应 0.15 / 0.2 / 0.25 秒时，提前量 0.10 / 0.15 / 0.20 秒最好，所以默认 150 毫秒对应 0.2 秒左右的反应。
- 试过但没用的：单独一次掉血也推测下一拍（太早更多）、按平均伤害而不是最弱一刀判（没提升）、要连续三下才算节奏（露娜掉到 59%）、预计会被别人先打死就不红（太晚少了，补到也少 2%）。1080p 和 4K 的差别不到 1 个百分点。

## 闭环：真实游戏端读画面、按红字出手

1920×1080 窗口，游戏端 60 帧左右识别；模拟玩家对红字反应 0.2 ± 0.04 秒后下令，英雄一次只能打一只兵（同时变红的只打第一个）。

| 轮次（各 30 回合，1 级露娜） | 规则 | 出手 | 补到 | 太早 | 太晚 | 这类回合里英雄补到的兵 |
|---|---|---|---|---|---|---|
| 第 1 轮（提前看，延迟按 0.08 秒） | 提前看 | 78 | 55% | 15% | 30% | 46% |
| | 只看这一帧 | 74 | 54% | 1% | 45% | 40% |
| 第 2 轮（提前看＋能等就等，延迟 0.03 秒＝本地实测） | 提前看＋能等就等 | 70 | 59% | 10% | 31% | 45% |
| | 只看这一帧 | 70 | 43% | 3% | 54% | 30% |

- 同一条旧规则两轮差了 11 个百分点：30 回合的样本，单轮上下有约 ±8 个百分点的波动。两轮合起来，提前看补到约 57%、旧规则约 48%；英雄补到的兵 45% 对 35%。
- 闭环比离线评估的差距小，原因有：英雄一次只能打一只兵，一波兵同时进斩杀线时只能顾一个（被跳过的红字两轮共 58 个）；本地延迟比离线评估假设的短，对旧规则有利。
- 调试中修掉的问题：英雄会被玩家的自动攻击设置拉去打别的兵（改为无命令时取消攻击能力）；按 GSI 位置找兵会找错同名的兵（GSI 位置晚约 0.1–0.2 秒，改为按显示的血量和最近一秒的引擎血量认兵，相当于玩家点的就是那只红字兵）。

## 上限在哪：缺的是“接下来谁会打它”，不是反应

`--last-hit-eval` 最后一张表把同一批兵分别交给几种“预知”和两种玩家（离线，4K，网络延迟 0.08 秒）。“看清出手”是假设画面上能认出每个正在打这只兵的出手动作：近战兵挥砍前 0.47 秒、远程兵约 0.9 秒（前摇加弹道）、攻城车约 1.1 秒、塔约 1.2 秒就能看出来；“引擎真值”知道将来的血量，红字打在可补窗口的正中。

| 预知 / 玩家 | 1 级露娜，站 340 | 1 级露娜，站 200 | 1 级主宰 |
|---|---|---|---|
| 只看血条（现在的产品）/ 反应 0.2 ± 0.04 秒 | 66% | 77% | 63% |
| 只看血条 / 反应恰好 0.15 秒、零误差 | 68% | 76% | 63% |
| 血条 + 看清出手 / 反应 0.2 ± 0.04 秒 | 76% | 79% | 84% |
| 引擎真值 / 反应 0.2 ± 0.04 秒 | 90% | 90% | 88% |

- **反应快慢不是瓶颈**：把玩家换成零误差的机器只多 0–2 个百分点。
- **瓶颈是预知**：红字要提前约一次出手的时间（露娜站 340 时约 0.93 秒：反应 0.15、延迟 0.08、前摇 0.28、弹道 0.38、下令 0.04）判断兵那时的血量。血条只记录已经发生的掉血，一秒内新来的攻击者、换目标的兵都看不到。露娜漏掉的 43 只“太晚”里，红字到落地之间的 97 刀有 42 刀是血条节奏预见不到的：17 刀的攻击者上一拍才开始打它，25 刀来自换目标或刚开打的兵。
- 在 60% 血以下的兵上按血条把掉血串成节奏：连续 3 拍以上的节奏下一拍还来 83–87%，只有 1 拍的 60%；每只兵每秒约 0.3 次新攻击者出现（中位 32 血，多于一刀），约占这段时间掉血的四分之一。
- 试过但没用：按这些概率做蒙特卡洛，算“现在出手补到的概率”，到概率不再上升时才红。概率本身大体准（说 60% 的时刻实际补到 72%），但补到率反而降到 51–62%（反应 0.2 秒）；同样的信息换一种决策规则提升不了。只用引擎里“谁锁定了谁”、不看出手时机也不行（太早 23–39%）。
- **缩短提前量最直接**：露娜从 340 站到 200（弹道少 0.16 秒），补到率 66% → 77%，和“看清出手”差不多。远程英雄补刀时站近一点比任何算法改进都有效，代价是更容易被对面消耗。
- 再往上要读出手动作（兵的前摇、远程兵和塔的弹道）：近战英雄提前量短，主宰在完美识别时能到 84%。这需要从画面识别兵的攻击动作，可以用这个实验室生成带引擎真值的训练数据（`--frames`，见[补刀视觉模型](last-hit-vision.md)），但工作量远大于现在的血条识别。认出得晚一些代价不大：晚 33 毫秒不变，晚 100 毫秒露娜 76% → 74%、主宰 84% → 82%，晚 200 毫秒 71% 和 80%。

## 局限

- 竞技场里没有敌方英雄：没有对方的补刀反补、消耗和技能伤害；兵波和站位比真实对线规整。
- 只测了 1 级裸装露娜和 1 级主宰；其他英雄、装备和高等级只用同一个公式，没有实测。
- 闭环是本地服务器（ping≈0）；联网时的延迟按设置里的 ping 加 0.03 秒估算，没有在真实对局里测过。
- 1080p 的闭环在开发机上跑；游戏机（4K/240 Hz）还没有跑过。
