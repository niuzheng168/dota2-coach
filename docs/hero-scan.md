# 教练机视觉扫描：观战时轮流切换英雄读状态、装备和位置

`scripts/vision/hero_scan.py` 在教练机（观战用的那台）上运行。它让观战中的 Dota 不停切换“当前选中的英雄”，从屏幕底部 HUD 读出每个英雄的等级、血量、魔法、存活、装备和身上的守卫数量，并从同一个客户端的 GSI 小地图记下每个英雄最后出现的位置。结果在后台维护成一份对局状态，按时间轴记录，可以在本机沙盒的 `/hero-scan` 页面上回放验收。Plus 实时观战时默认只扫描敌方英雄（见下文“只扫描对手”）。

它本身只记录、不生成建议。Plus 观战时写出的敌方等级、装备和守卫数量由双机教练端读取（对手面板、插眼推测），没有接入自动教练。

## 信息边界

- 只用这台观战客户端自己的画面和 GSI。Plus 实时观战是好友所在队伍的视角：敌方英雄只有在这一方视野内时才能被选中、读到；看不见时保留**最后一次读到的状态和最后出现位置，并标明多少秒前**，这是推测，不是实时位置。
- 不绕过战争迷雾，不读内存，不用其他数据源补齐看不见的信息。
- 延迟观战、公开高分局观战和本地回放能看到双方全部信息（GSI 里 `mode` 为 `full-spectator`）。这类记录只用于离线验收，页面顶部会写明，不能当作实战可见的信息。
- 小地图上同一英雄出现多个单位（幻象、分身）时，敌方本来就分不出真身。记录会保留全部候选，页面用小空心圈画出，并写“分不出真身”。

## 一次性准备（教练机）

1. Python 环境：按 `scripts/vision/requirements.txt` 建 `.tmp/vision-tools` 虚拟环境（文件开头写了 CUDA 与 rapidocr 的安装顺序）。
2. 识别素材：`node scripts/vision/extract-assets.ts` 从已安装的客户端提取物品/技能图标、英雄小头像（对手面板用）和中文名到 `.tmp/vision-assets`（只读客户端，素材不提交）。**Dota 每次更新后都要重新提取**（新物品、改过的技能图标，否则新物品读不出来）：先备份其中的标定文件 `hud-1080.npz`，把 `.tmp/vision-assets` 整个删掉重新提取，再把标定文件放回去（还有守卫数字模板 `hud-digits-1080.npz`，见下文“守卫数量”）。2026-11-19 之前的提取没有英雄小头像，对手面板上的头像会是灰色方块，也要这样重新提取。客户端还没翻译的新物品（如 7.42 的 Bloodslinger）用英文名，和中文客户端里显示的一样。HUD 标定文件 `.tmp/vision-assets/hud-1080.npz` 由 `hud_recognizer.py calibrate` 从 `capture_replay.py` 采的回放帧生成；本机已有。
3. 写入 GSI 配置：
   ```bash
   .tmp/vision-tools/Scripts/python.exe -I scripts/vision/hero_scan.py setup
   ```
   它在 Dota 的 `cfg/gamestate_integration/` 写 `gamestate_integration_coach_hero_scan.cfg`（本机 127.0.0.1:3298），密钥存在 `%LOCALAPPDATA%\DotaCoach\hero-scan\secrets.json`。写入后完全重启 Dota 一次。Steam 启动项需要 `-gamestateintegration`。
4. Dota 设置：默认 HUD，1920×1080 窗口化（目前只在这个分辨率实测过；其他 16:9 分辨率会先缩放到 1080 高，未验证）。观战快捷键“选择玩家 1–10”保持默认的 `1`–`0`；改过的话用 `--keys` 按顺序传入 10 个键。

## 使用

配合双机教练使用时，直接点教练端的“启动视觉扫描”：它在仓库目录里运行 `hero_scan.py scan --stop-with-stdin`（缺 GSI 配置时先运行 `setup`），停止按钮或关掉教练端时关闭扫描的标准输入，扫描写完最后一次状态后退出。见 [`twopc-plus-alerts.md`](twopc-plus-alerts.md)。下面是单独在终端里运行的步骤。

1. 打开 Dota，进入观战（Plus 好友实时观战，或 观看 → 直播 → 游戏内观看）。
2. 运行：
   ```bash
   .tmp/vision-tools/Scripts/python.exe -I scripts/vision/hero_scan.py scan --print
   ```
   启动时会把 Dota 窗口提到前台一次。**扫描期间 Dota 要保持在前台**：Dota 只在前台时才响应发给它的切换按键；按键是直接发给 Dota 窗口的，不会打到别的程序里。切到别的窗口后扫描自动暂停切换，只记录画面上自己出现的英雄，切回 Dota 后继续。按 Ctrl+C 结束。
   - 可以先启动扫描再开 Dota：它会等 Dota 窗口出现。
   - 只在 GSI 显示正在观战时才按切换键；在菜单里或自己打游戏时不按。
   - Dota 窗口变了也会继续扫描，比如全屏时切出被最小化、改了分辨率、重启了 Dota：等窗口恢复后重新采集，等待期间对手面板照常发布最后读到的内容。2026-11-20 之前的版本遇到这种情况会卡住不动，对手面板随之消失。
3. 看时间轴：另开终端运行 `npm run sandbox`，打开它打印的地址，把路径换成 `/hero-scan`（保留 `#token=…`），例如 `http://127.0.0.1:3221/hero-scan#token=…`。默认打开最新一段记录；正在进行的记录勾选“跟随实时”会每秒追加。

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--session NAME` | 开始时间 | 记录文件夹名（字母、数字、`-`、`_`） |
| `--duration` | 3600 | 最长秒数 |
| `--timeline-every` | 0.5 | 时间轴快照间隔（秒） |
| `--items-every` | 3.0 | 同一英雄的装备隔多少秒读一次。每读一次要让画面停在这个英雄上约 0.15 秒，所以越小状态刷新越慢（见下） |
| `--item-visits` | 1 | 每轮最多几个英雄停下来读装备 |
| `--select console` | `keys` | 用控制台命令切换，只适用于本地回放（见下文） |
| `--allies` | 关 | Plus 队伍视角下也切换己方英雄（默认只扫描敌方，见下） |
| `--truth` | 关 | 每次读取同时记下完整观战 GSI 真值，用于验收 |
| `--save-misses N` | 0 | 保存 N 张没读出来的 HUD 截图，排查用 |
| `--stop-with-stdin` | 关 | 标准输入关闭时结束（教练端的启动按钮这样用） |

每次运行在 `.tmp/hero-scan/<session>/` 生成：`timeline.jsonl`（时间轴快照，页面读取它）、`scan.jsonl`（每一次读取）、`state.json`（最新状态）、`summary.json`（速度统计）。这些文件只在本机，不上传。

## 推送到游戏机的对手面板

Plus 实时观战时，扫描每 0.5 秒把敌方英雄最近读到的等级和装备写进 `%LOCALAPPDATA%\DotaCoach\hero-scan\live.json`（`--live` 可改路径，传空字符串不写），面板用到的英雄头像和物品图标复制到旁边的 `icons\`。教练端读取后推到游戏机，显示在游戏画面左侧，规则和用法见 [`twopc-plus-alerts.md`](twopc-plus-alerts.md)。只在 Plus 队伍视角下写入敌方；完整观战的扫描不写任何英雄。2026-11-21 之前的扫描在教练端正好读这个文件时会自己退出（Windows 不让替换正被读取的文件），对手面板随之消失；现在跳过那一次写入，v0.4.5 教练端读取时也不再锁住文件。每名敌人还附上最近 4 次完整读取的守卫数量（`wards`：游戏时间和假眼、真眼、种类不明各几个），教练端用来推测插眼，见 [`twopc-enemy-wards.md`](twopc-enemy-wards.md)。

## 只扫描对手

Plus 实时观战（队伍视角）时默认不再切换己方英雄：对手面板和插眼推测只用敌方，少切己方 5 人，敌方每人轮得更快。具体是：

- 已认出是己方的玩家不选；敌方只在友方看得到时选（看不到的本来也选不中）。
- 还没认出是谁的玩家照常试选；但如果他所在的那半边快捷键（`1`–`5` 或 `6`–`0`）里已认出的全是己方，就当他也是己方，不试。
- 延迟观战、完整观战照旧扫描全部 10 人（只用于离线验收）。

要像以前一样连己方一起扫描（例如在 `/hero-scan` 上验收己方），加 `--allies`。

## 玩家和英雄怎么对上；看不见时不记

- 切到某个玩家后 HUD 变了，就把画面上认出的英雄记成这个玩家的。但快捷键 `1`–`5` 是天辉的玩家、`6`–`0` 是夜魇的，所以 GSI 说是另一队的英雄不记；已经对上别的玩家的英雄也不记。2026-11-21 的真人 Plus 局里，开局号角那一刻按 `0`（夜魇第 10 名，卡尔）时 HUD 正好换成了天辉的不朽尸王，于是第 10 名被记成了尸王、当成队友，整局再没被选过，对手面板上卡尔一直没有装备。用当时的数据集确认过，卡尔本身的 HUD 认得出来（认英雄 0.95 分，装备全对）。
- Plus 队伍视角下，敌人走出友方视野后 HUD 可能还停在它身上，显示的是它最后一次被看到时的样子。这样的读取只用来认是谁，不记等级、装备和守卫数量（扫描记录里标 `"unseen": true`），免得对手面板把旧装备标成“刚刚读到”、插眼推测把旧的守卫数当成现在的。
- GSI 小地图上刚进入视野的单位会在地图正中 (0,0) 停一两个包，这样的位置不记为最后出现的地方。

## 守卫数量

读装备时顺带读守卫数量：侦查守卫（假眼）、岗哨守卫（真眼）格子右下角的叠加数字；守卫分发器右下角是前面那种守卫的数量，左下角灰色小字是另一种的数量，前面是哪种看图标颜色（黄假眼、蓝真眼）。背包里的、刚从背包拿出来（6 秒冷却）的图标是灰的，看不出种类，记为种类不明。数字用掩码模板匹配读（OCR 读这么小的数字不可靠），两位数和对不上模板的都不认，那次读取就不记守卫。只记整栏（主物品栏和背包）都认出来的读取。

数字模板 `.tmp/vision-assets/hud-digits-1080.npz` 从带 GSI 真值的离线帧生成（和 `hud-1080.npz` 一样不提交，本机已有）：

```bash
.tmp/vision-tools/Scripts/python.exe -I scripts/vision/hud_recognizer.py digits .tmp/vision-dataset/r1080 .tmp/vision-dataset/test1
```

验收（2026-11-21，同一批 285 帧，和 GSI 对照）：

- 数字逐个读：每次留出一局、用其余对局生成模板来读，主物品栏和背包的数字 422/423。
- 守卫总数：没有守卫的 203 帧一个都没多读；有守卫的 82 帧里 81 帧和 GSI 一致，剩下 1 帧是画面和 GSI 本身不同步。
- 守卫分发器在背包里时左下角的小数字只有 3 个样本，这一项基本没验证。

## 为什么这样快

- 选择英雄：每采到一帧就切下一个英雄。英雄身份、血量、魔法、等级在切换后的**第一帧**就画好。Dota 大约每 20 ms 才能显示一次新的选择（60Hz 时 23 ms，144Hz 时 20 ms），所以 10 个英雄一轮约 0.2 秒。
- 身份从画面判断，不假设切换成功：先认技能图标（GPU 上做模板匹配，只在本局 10 个英雄里比），再看头像上方的名字标签。标签里读到完整英雄名时以标签为准（拉比克偷来的成对技能会让图标像另一个英雄）；饰品图标或阵亡时图标为空，就用“这次只切了这一个玩家”的结果，九名玩家都已对上时最后一名就是剩下的英雄。所以敌方在迷雾里选不中、或观战自动导播抢了镜头时不会张冠李戴。
- 装备栏切换后有约 0.12 秒的淡入淡出，只在停留 0.13 秒以上的帧读装备。到了该读装备的英雄（默认隔 3 秒）排在一轮最后，停下来读；其余轮次一轮接一轮，中间不停。
- 采集用 Windows.Graphics.Capture，在显卡上只裁 HUD 底部一条（`wgc.py`），识别在独立线程跑在 GPU 上（单帧中位约 20 ms）。

所以速度主要由 Dota 显示新选择的快慢和读装备的停顿决定，显示器刷新率影响很小：用 UU 连上时桌面是 144Hz，每名英雄刷新只从 0.327 秒变成 0.306 秒（约快 7%）。

装备间隔和状态刷新的取舍（2026-11-18 高分局实测，60Hz，各 75 秒）：

| `--items-every` | 每名英雄状态刷新（中位 / P90） | 每名英雄装备刷新 | 每秒读取次数 |
|---|---|---|---|
| 3（默认） | 0.29 秒 / 0.45 秒 | 约 3.4 秒 | 33 |
| 6 | 0.17 秒 / 0.34 秒 | 约 6 秒 | 40 |

## 实测（2026-11-18，RTX 3090 Ti，1920×1080 窗口，60Hz）

| 场景 | 结果 |
|---|---|
| 离线回放帧（283 帧，13 场回放，与 GSI 真值对照） | 英雄 99.6%（1 帧未认出，0 认错），等级 100%，血量 100%，魔法 100%，主装备 100%，背包 100%（图纸不计，见下），中立 98.9%，TP 100% |
| 本地回放播放中（控制台切换） | 身份 1420/1420，装备 100%，血/魔 ±3% 99.9% |
| 本地回放，安全模式下用快捷键切换 | 身份 960/960，每英雄刷新中位 0.30 秒，切换生效中位 27 ms |
| **公开高分局观战 120 秒，全部修正后**（对局 9095008711，`--truth`，`live-topgame-8`） | 识别 3571/3573，未见认错；每英雄刷新中位 0.327 秒（P90 0.385），切换生效中位 31 ms；等级 99.9%（2 次是升级瞬间），存活 100%，血/魔 ±3% 99.8%/99.7%，主装备 100%，背包 100%，中立 99.4%，TP 100% |

血/魔严格相等只有约 81–87%：比赛在走，画面和最近的 GSI 包之间数值本来就差几点，所以看 ±3% 那一列。

同一段记录在 `/hero-scan` 页面的验收（每个快照与同一时刻最新 GSI 对照，状态最多 1 秒前读到）：等级 99.9%，血量 ±5% 99.4%，魔法 ±5% 98.1%，存活 100%，主装备格 99.7%，小地图位置（单个同名单位）100%（2067/2068）；有幻象时真身在候选中 98.4%（251/255）。

这轮实测发现并已修正的问题（修正后离线数据集无退步，再用上表那局复测）：

- 护盾（屏障）布局下血条变矮，血量数字压进了测量填充的那两行，半血以下读成空值。现在按“血条从左往右填”处理数字所在的列。离线血量 99.6% → 100%。
- OCR 漏掉开头的 1（“1770 / 1814”读成 770/814）时，若血条动画还没追上数值，错的读法反而和血条对得上。现在读到斜杠时不再重新拆分数字（斜杠被读成紧挨着的 1 的情况仍然处理）。
- 拉比克偷到成对技能（如森海飞霞的大招和它的释放技能、灰烬之灵的残焰和激活残焰）时被认成被偷的英雄。现在名字标签完整读出时以标签为准。
- 阵亡且图标为空的英雄（如记录 live-topgame-3 里一直阵亡的主宰）整段认不出。现在九名玩家已对上时，最后一名就是本局剩下的那个英雄（只用本局英雄名单推断）。用当时保存的画面复核：等级 26、0/2188、全部装备都对。
- 活动道具“挚爱回忆”（item_ofrenda，25 种信封图标）从未出现在任何记录的真值里，却常被误配到背包里的暗图标和图纸上，已从参照中去掉。离线背包 99.1% → 99.5%。
- 67 件物品（大多是中立物品）原来显示英文内部名，现在用客户端里的中文名（`extract-assets.ts --manifest-only` 重建）。
- 装备轮询会把同一个英雄连读两次：下一轮排计划时，后台还没记下上一轮的装备读取。`--items-every` 因此没起作用（设 5 秒照样每轮都停）。现在已排队的读取也算数。
- 连续切换和单人确认切换之间不再空等，但单人确认切换要等前面连续切换的画面都显示完再开始；否则会把别人的画面记成这名玩家（实测出现过 9 号被对成光之守卫）。

复现验收：`--truth` 记录后运行

```bash
.tmp/vision-tools/Scripts/python.exe -I scripts/vision/eval_scan.py .tmp/hero-scan/<session>/scan.jsonl
```

本地回放也可以用控制台切换：Dota 以 `-insecure -gamestateintegration -netconport 29009 -netconpassword <setup 打印的密码>` 启动，再加 `--select console`。`-netconport` 不带 `-insecure` 时 Dota 不会开端口；这个端口监听所有网卡，靠密码保护。若同时用 `-condebug`，启动命令行（含密码）会写进 `game/dota/console.log`。

认英雄：技能表变了的 17 名英雄逐个换上（1 级、技能已学），在本局 10 人里认和在全部英雄里认都是 17/17。7.41f 离线数据集（283 帧）用新素材重跑，各项结果和旧素材完全相同（主装备、背包 100%，中立 98.9%）。

测试中发现（和 7.42 无关的老问题）：英雄有没点的天赋时，天赋树按钮会发光，HUD 定位用的正是这个按钮，12 级、天赋没点时两轮各 17 帧里都有 6 帧整块判为“没有 HUD”，没读出任何东西。实战里点了天赋就恢复；面板上那名英雄这期间保留上一次的读取。

## 已知限制和未验证项

- **Plus 好友实时观战还没有用真人对局实测。**未验证：队伍视角下敌方在迷雾里时切换按键的反应、己方阵营判断、Plus 模式下快捷键是否同样生效、观战导播/玩家视角是否会抢走选择。第一次真人局请先短跑一段，在 `/hero-scan` 上确认。
- 只在 1920×1080 窗口、默认 HUD 下实测（60Hz 和 UU 的 144Hz 虚拟显示器）。教练机的 HDMI 接着待机的电视，驱动在这种状态下不接受改刷新率（试过 1440p@144：屏幕关着时能切，屏幕一唤醒就退回 4K@60），所以不连 UU 时是 60Hz。
- 图纸（合成卷轴）不跟踪：都是同一个图标，说不出是哪件的，背包里的图纸还常被认成别的暗图标（如碎甲、树之祭祀）。验收时真值是图纸的格子不计分，页面上那一格的名字不可信。不同等级的达贡等同图标物品分不出等级，页面写成“A（或 B）”。
- 采菌套具（foragers_kit）在某些状态下会读成别的物品（live-topgame-5 里 30 次中 10 次读成挚爱回忆），没抓到对应画面，原因未查明；去掉挚爱回忆后还没在有这件物品的对局里复测。中立物品另见一例：基迪花粉袋读成行巫之祸（2 次）。
- 有没点的天赋（天赋树按钮发光）时这名英雄的 HUD 常常读不出来，见上一节。
- 背包里普通战斗号角和大战斗号角分不出（只差颜色）；还不在掉落池里的 Nothl Sigil 在中立格读不出。
- 拉比克阵亡时名字标签被“阵亡总结”盖住，若此时还带着偷来的成对技能，仍可能认成被偷的英雄。
- 敌方幻象/分身在小地图上与真身无法区分，位置只给候选。
- 扫描期间 Dota 必须在前台；离开前台只被动记录。
- Plus 队伍视角下默认不扫描己方（`--allies` 可打开），`/hero-scan` 上己方英雄基本没有 HUD 读取，只有小地图位置。
- 守卫数量还没在真人 Plus 对局里读过。
