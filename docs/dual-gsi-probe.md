# 双机 GSI 对照测试（X 打游戏 + Y Plus 实时观战）

> 双机客户端 v0.3.1 已内置同样的测量（一键配置、实时延迟、Debug 记录），见 [twopc-v031-plus.md](twopc-v031-plus.md)，优先用客户端。
> 本页脚本作为不依赖客户端的独立备用方案保留，例如只想单独测一台机器的 GSI。

目的：用同一局真人对局回答三个问题。

1. **Plus 实时观战比游戏本身慢多少**：决定危险提醒能不能用 Y 的数据。
2. **X 自己的 GSI 有没有小地图**：玩家模式会不会给按队伍视野过滤的小地图（队友、可见敌人、野怪、眼）。
3. **Y 的观战界面能读到什么**：能否切到每个队友查看装备和金钱，能否点选视野内的敌人，有没有统计面板。

只记录 Dota 发到本机 `127.0.0.1` 的 GSI，不开放局域网端口，不调用模型，也不接入教练。

## 工具

| 文件 | 在哪运行 | 作用 |
|---|---|---|
| `scripts/dual-gsi/gsi-probe.ps1` | X 和 Y 各运行一份 | 写入 GSI 配置，记录收包时刻，并在开始、结束和每 5 分钟用 NTP 测本机时钟偏差 |
| `scripts/dual-gsi/compare.ts` | 装有本仓库的电脑 | 对比两份记录，生成延迟和字段报告 |

`gsi-probe.ps1` 是单个文件，只依赖 Windows 自带的 PowerShell 5.1，直接拷到 X 即可。文件带 UTF-8 BOM，用其他编辑器另存时不要去掉，否则中文提示会乱码。

不在脚本里自动截屏：截屏代码会被 Windows Defender 当成可疑脚本拦截（`ScriptContainedMaliciousContent`）。Y 上改用 Steam 的 F12 截图，文件名自带时间，报告会自动和游戏时间对齐。

## 两台机器都要做（只需一次）

1. Steam 库 → Dota 2 → 属性 → 启动选项，保留原有参数，末尾加上 `-gamestateintegration`，例如：
   ```text
   -perfectworld -gamestateintegration
   ```
2. **先运行采样器，再启动 Dota。** Dota 只在启动时读取 GSI 配置。如果采样器提示"Dota 在配置写入之前启动"或"没有 -gamestateintegration"，就完全退出 Dota，从 Steam 重新启动。之后再运行采样器时配置不变，不用重启 Dota。

## X：账号 A，打游戏的机器

1. 把 `gsi-probe.ps1` 拷到 X，例如放在桌面。
2. 打开 PowerShell，进入该目录后运行：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\gsi-probe.ps1 -Role X
   ```
   窗口里会显示 Dota 目录、配置路径、时钟偏差，然后开始监听 `127.0.0.1:3291`。**窗口不要关。**
3. 从 Steam 启动 Dota，进入菜单后窗口应开始显示"包 N"。
4. 排一局**真人对局**（普通匹配或天梯）。本地机器人局无法被 Plus 观战。正常打，不需要做任何特殊操作。
5. 对局开始后，窗口每 5 秒显示一行，例如：`GAME_IN_PROGRESS 12:34 | 身份 radiant | 英雄 npc_dota_hero_luna 装备 6 技能 7 | 小地图 N`。这里的"小地图 N"就是问题 2 的答案。
6. 对局结束（或对局内至少 15 分钟）后，在窗口里按 **Ctrl+C**。它会压缩记录并测结束时的时钟偏差。不要直接关窗口。
7. 把 `C:\Users\<用户名>\DotaGsiProbe\X-<时间>` 整个文件夹拷到装有本仓库的电脑。

X 上不截图，也不做额外处理，对游戏帧率基本没有影响。和已有的双机教练 GSI 配置可以同时存在，端口不同。

## Y：账号 B，Plus 实时观战的机器

前提：B 有 Dota Plus，并且和 A 互为 Steam 好友。

1. 运行：
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\gsi-probe.ps1 -Role Y
   ```
   如果 Y 就是装有本仓库的这台电脑，脚本在 `scripts\dual-gsi\gsi-probe.ps1`。
2. 启动 Dota。等 A 的对局开始后，在好友列表右键 A，选 **实时观战**（Plus 功能，不要选有延迟的普通观战）。
3. 按下面的顺序操作。每做一项都**停留 10 秒以上并按一次 F12**，再把看到的现象简单记下来：

| 时间（进入观战后） | 操作 | 要看什么 |
|---|---|---|
| 0–5 分钟 | 什么都不动 | 基线数据，用于测延迟 |
| 5–8 分钟 | 找有没有能同时看到己方 5 人装备和金钱的面板（左上角按钮、右上"覆盖视角"下拉、计分板快捷键） | 有的话，一张截图就能读全 5 个人 |
| 8–12 分钟 | 依次点顶栏的 5 个队友头像，每人停 10 秒；做两轮 | 底部界面是否切到该队友（等级、血蓝、装备、技能、金钱）；记下切换失败的次数 |
| 12–14 分钟 | 用"覆盖视角"切到某个队友的玩家视角，再切回 A | 是否稳定 |
| 视野里出现敌方英雄时 | 点选这个敌人 | 能否看到它的血量、装备、技能等级 |
| 之后 | 切回 A 的视角，不再操作，直到对局结束 | — |

4. 可选，用来复核上次的结论：对局最后 2–3 分钟退出实时观战，改用普通（有延迟）观战看同一局。报告会把这段单独列为"完整观战"，可以看到它是否有 10 人分组数据，以及实际延迟多少。这段数据只做对照，不接入教练。
5. 对局结束后按 **Ctrl+C**。
6. Steam 截图在 `<Steam目录>\userdata\<数字ID>\760\remote\570\screenshots`，也可以在 Steam 截图管理器里点"在磁盘上显示"找到。

## 生成报告（在装有本仓库的电脑上）

```powershell
node scripts/dual-gsi/compare.ts --x <X记录文件夹> --y <Y记录文件夹> --y-shots <Y的Steam截图文件夹>
```

（在 PowerShell 里用 `npm run probe:compare -- ...` 时，`--` 可能被 npm.ps1 吞掉，所以直接用 node 运行。）

输出 `report.md`、`report.json` 和 `y-screenshots.csv`（截图对应的游戏时间），默认放在 `.tmp\dual-gsi-report-<时间>\`。报告包括：

- **延迟**：比较两台机器第一次收到同一游戏秒（`clock_time` 从 T-1 变为 T）的时刻，用两边测到的共同 NTP 服务器偏差校准。观战模式切换前后的数据会分开统计。
- **各机器 GSI 字段**：自身英雄、装备、技能、10 人分组、小地图、建筑、事件类型等。
- **X 有没有小地图**：如果有，和 Y 在同一游戏秒的小地图做对照。
- **Y 小地图里 A 的英雄与 X 自身坐标的距离**：距离最小处应在偏移 0，用来验证两边确实是同一局、时间对得上。
- **每个英雄在 Y 小地图的出现率**，以及同名英雄重复条目所占比例。

注意：延迟的精度受 NTP 往返时间和 0.2 秒发包间隔限制，大约在 ±0.1–0.3 秒；Steam 截图时间只精确到秒，并按本机时区解析。

## 收尾

两台机器都测完后，各运行一次，删除本工具写入的 GSI 配置（采样记录会保留）：

```powershell
powershell -ExecutionPolicy Bypass -File .\gsi-probe.ps1 -Role X -Uninstall   # Y 上用 -Role Y
```

## 隐私

记录里保留原始 GSI 字段，但会去掉鉴权 token、Steam ID 和聊天内容。玩家昵称等仍可能出现在记录中，所以记录只放在本机，不要公开分享。

## 已做的验证

- `tests/dual-gsi.test.ts`：6 项。合成数据里 X 时钟慢 250 ms、Y 时钟快 400 ms、Y 延迟 1.5 s，另有一段 120 s 的完整观战，能分别还原两段延迟；同时覆盖暂停或跳秒、截断的 gzip、BOM、坏行和 Steam 截图对齐。
- 在本机用真实 `gsi-probe.ps1` 和一个模拟 Dota 的发包脚本，对指向假 Dota 目录的 X、Y 两个角色测了 45 秒：注入 1.5 s 延迟，测得 1.48 s；错误 token 被拒；token、Steam ID 和聊天内容都没有落盘；`-Uninstall` 能删除配置。
- **还没有用真实 Dota 跑过这套工具**，下一局真人对局就是第一次实测。
