# 双机教练 v0.4.0：60/120fps、后台继续传、显卡缩放编码、字幕时长与刷钱路线

**两端都要升级到 v0.4.0**（视频协议 v3），重新复制配对码。旧版游戏端会提示“视频协议不兼容”。

> v0.4.1 在此基础上增加了游戏端的玩家模式小地图明细记录，并解除窗口采集约 60fps 的系统默认上限，见 `PLAYER-MINIMAP.md`（仓库内 `docs/twopc-v041-minimap.md`）。

## 改了什么

| 问题 | v0.3.1 | v0.4.0 |
|---|---|---|
| 帧率 | 固定 30fps（代码常量） | 游戏端可选 **30 / 60 / 90 / 120fps，默认 60**；码率可填，0 = 自动 |
| 切到其他窗口 | 只采集前台，切走即停，教练端黑屏 | **窗口采集**（Windows.Graphics.Capture）：Dota 被其他窗口挡住也继续传 **Dota 窗口自身**的画面；其他应用的内容不会进画面 |
| 缩放/压缩位置 | 游戏机 CPU：GDI 拉伸 + 托管代码转色 + 软件 H.264 | 游戏机 **显卡**：显卡视频处理器裁剪/缩放/转 NV12，显卡独立编码单元（NVENC / AMD / Intel）编码；可选 **原生分辨率**，把缩放全部交给教练机 |
| 字幕停留 | 源画面最多活 12 秒，模型要 8.6–10.8 秒 → 实测只显示 0.7–3.2 秒 | 从回传那一刻起显示 **设定秒数（默认 3 秒，1–15 可调）** |
| 刷钱路线 | 未校准小地图 → 模型拿不到地标 → 只有字幕；11 秒超时丢掉约 40% 结果 | **默认左下小地图框自动生效**；模型给出 **1–3 个有序地标** 组成路线，游戏内画编号圆圈和连线，并显示“下一步：①…→②…”；模型超时默认 15 秒（8–20 可调） |

## 游戏端设置（连接前选择，自动保存）

- **帧率**：30 / 60 / 90 / 120。若分辨率×帧率超过 H.264 5.2 级上限（例如原生 4K + 120fps），会自动降到可行的最高帧率（4K 为 60），界面会写明。
- **传输分辨率**：原生（游戏机不缩放）/ 最高 1440p / **最高 1080p（默认）** / 900p / 720p。只缩小不放大，保持游戏画面比例。
- **编码器**：自动（优先显卡硬件编码，失败自动回退 CPU）/ CPU 软件编码。CPU 编码最高 1080p。
- **采集方式**：**窗口采集（默认）** / 前台屏幕复制（旧版行为，切出即暂停）。
- 状态栏显示实际 fps、码率、采集耗时、编码耗时、丢帧数，以及当前采集方式和编码器名称。

### 缩放在哪里做

压缩（编码）必须在游戏机做：原始 4K 60fps 画面约 6 Gbps，局域网传不动。v0.4.0 把游戏机上的工作都放到显卡的固定功能单元：

- 裁剪、缩放、RGB→NV12 由 D3D11 视频处理器完成，CPU 不做逐像素运算；
- 编码用显卡的独立视频编码单元，不占渲染用的 3D 核心。

选“原生分辨率”时游戏机不缩放，教练机负责缩放给预览和模型（模型输入仍是 ≤1600×900 JPEG）。代价是码流更大、教练机解码更重，所以默认是 1080p。

### 后台传送的前提

- Dota 必须**没有最小化**。独占全屏在 Alt+Tab 时会最小化，没有画面可传；请在 Dota 视频设置里改为 **“无边框窗口”**。游戏端会明确提示“Dota 已最小化”。
- 窗口采集只取 Dota 窗口；游戏内悬浮提醒不会被录进去，Dota 不在前台时提醒会隐藏，到期前切回仍会显示。
- 采集到的是 Dota 实际渲染出来的帧。如果 Dota 在后台时自己降低渲染帧率，实际 fps 会跟着降。

### 远程桌面会把帧率限制在约 30fps

通过 Windows 远程桌面（RDP）登录时，系统按约 30Hz 合成桌面。本机实测该会话的合成频率为 32Hz，从真实 Dota 窗口采集也恰好是 32fps。任何窗口采集都受这个限制，设置成 60/120fps 也只有约 30fps。

想要 60fps 及以上，请在本机控制台（显示器前）运行游戏和游戏端；或者由管理员按微软文档设置 RDP 帧率（`DWMFRAMEINTERVAL`），本程序不修改系统设置。

## 教练端设置

- **游戏内字幕/路线显示（秒）**：默认 3，1–15。从回传时起计时；死亡、换局/阵营、分辨率变化或断线仍会提前撤回。
- **模型超时（秒）**：默认 15，8–20。超时的结果直接丢弃；源画面超过 22 秒的结果永远不会回传。
- **未校准时使用默认左下小地图框**：默认开启。预览里画**虚线框**；如果没有对准你的小地图（镜像 HUD、超大小地图），请手动校准，已确认的校准优先，显示为实线。
- 预览按收到的视频帧率刷新（受 WPF/显示器刷新率限制，最高约 60fps）。缩放在后台线程完成，原生 4K 也不卡界面。

## 路线提醒

- 模型从**己方**静态地标目录（营地、塔）里按顺序选 1–3 个，程序用校准过的 Valve 地图坐标投影到小地图，**不接受模型给出的坐标**。
- 游戏内画法：第一站是带箭头的大圆圈，后续站是编号小圆圈，各站之间用虚线连接；字幕下方显示“下一步：①…→②…→③…”。
- 字幕标题会写明“依据约 N 秒前画面”（由游戏机自己的时钟计算）。路线只是条件化的观察/接近顺序，不保证有怪、安全或收益最高。

## 验证（2026-11-17，本机）

- 协议/编解码检查 234 项，两个原生客户端的 UI 检查 71 项，全部通过。
- 显卡编码：本机 NVIDIA H.264 Encoder MFT 在 1080p 和 4K 下编码，再用软件解码，颜色与时间戳顺序都正确；排在前面的 AMD 核显编码器在本机初始化失败，程序自动改用下一个。
- 端到端：诊断视频源设为 60fps 目标，实测接收 **59.9fps**（v0.3.1 约 27fps）。
- **被完全遮挡的窗口**：经显卡缩放链路采到的仍是该窗口自己的颜色，而不是盖在上面的窗口。
- 真实 Dota 窗口（2560×1440 窗口模式，远程桌面会话内）：
  - 裁剪准确，只有客户区，不含标题栏；
  - 每帧采集+缩放约 3.7ms，NVENC 编码调用约 3.5ms（1080p）；
  - 进程 CPU 约占单核 12–18%（约 32fps 时）；
  - 帧率被远程桌面限制在 32fps，见上文。
- 尚未验证：本机控制台下 60/120fps 的真实 Dota 采集、两台物理机器、开启采集前后 Dota 的帧率对比，以及真实模型生成路线的质量。
