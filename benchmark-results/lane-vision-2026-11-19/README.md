# 本机纯视觉对线与塔下节奏（2026-11-19）

### 后续：HP 标签（普通近战 550 / 远程 300）

[HP 像素 E2E](hp-pixels-e2e.json)：2,274 帧已知血量的合成图，按对应兵种/基准读取时最大误差 4 HP；未分类时验证对应的条件读数，不能解释成程序在首帧已认出兵种。12/12 个留出的第三击落在预测 HP 区间内。[Windows 窗口 E2E](hp-window-e2e.json)：7/7 次受控掉血绘出正确 HP，最大 27.92 ms。两者都不是天梯实测或对实战精度的保证。

### 之前的百分比版（历史记录）

**结论：** 游戏端不连接教练，也不读取 GSI。真实 Windows 采集链路的三次受控运行，已启动后的 21 次掉血都画出了正确的新数字，P95 **25.10 ms**、最慢 **29.09 ms**。测试用的是自己的 960×540 目标窗口和软件位图终点；没有截取玩家的对局。**这不是 4K 天梯实战的延迟、物理出光时间、游戏 FPS 或补刀成功率。**

| 证据 | 方法与结果 |
|---|---|
| 真实采集链路 | [第 1 次](window-e2e-1.json)、[第 2 次](window-e2e-2.json)、[第 3 次](window-e2e-3.json)。对已存在的前台窗口不发输入、不改变焦点；另建一个被其遮住的、不激活的测试 HWND，只捕获测试 HWND。输入变化时开始计时，经 WGC、D3D11 缩放/NV12、实际识别线程、UI Dispatcher、生产 `Surface.OnRender`，到位图与期望数字像素一致为止。60 FPS 上限，实际交付/处理合计 434 帧。21/21 次正确，0 次超过 50 ms；每轮都看到了节奏提示并验证失焦撤标。**冷启动后的首个可读数用了约 330–352 ms**，不能混入稳定期数字里当作同一指标。测试不测置顶透明窗口的最终 DWM 合成。 |
| 塔下时序与读数 | [逐帧结果](pixels-e2e.json)。合成 1080p、有行填充的 NV12，60/150 Hz，两队血条，6 种血池／伤害组合，共 2,274 帧。目标血条填充与输入一致；相对生成时 HP，显示数最大偏差 1 个百分点。210 帧单行局部遮挡恢复。用前两击预测第三击：12/12 个留出的第三击落在显示区间内，显示倒计时最大偏差 33.3 ms。这是构造的受控节奏（6 种组合 × 两档），**不验证游戏中攻击者身份**。 |
| 拒判及时效 | 覆盖间隔不符、伤害幅度不符、夹杂小伤害、换目标、两个目标竞争、长断帧、下一击未到、友方、轨迹相交、血条尺度改变共 10 种反例。另验只剩一像素、阵营反转、切镜、长预测放不下时回退为短血量；一个新出现的兵在测试中 35 ms 后被发现。独立的实时时钟/Dispatcher 测试中，12/12 次预设掉血均出现在软件位图上，P95 16.83 ms，采集停滞后清空。 |
| 已有游戏画面 | [随测试提供的样本](../../desktop/DotaCoach.TwoPc.UiTests/Fixtures/lane-rims.json.gz)为 8 个时间点、30 块真实试玩 4K→1080p 的 96×14 NV12 候选裁片，仅含兵条附近像素和贴回坐标。按原坐标贴回空白画面，28/30 根与候选坐标匹配、无额外检测；同一批裁片上上一版为 27/30。它们是筛选过的候选、有重复目标、不是完整自然兵线、也没有单位 HP 真值。不能据此算天梯准确率或整屏误报率。 |
| 识别开销 | 同一张合成 1080p、8 根静止兵条，交错运行，新旧扫描策略均预热：每帧扫描平均 0.031 ms（强制全扫）和 0.018 ms（定期全扫＋局部重读）。不含 GPU 转换或录屏，不能换算成游戏 FPS 收益。独立软件绘制测试首次初始化还有约 200 ms 的冷开销。 |

### 复现（Windows、.NET 10）

```powershell
dotnet run -c Release --project desktop/DotaCoach.TwoPc.Tests -- --last-hit
dotnet run -c Release --project desktop/DotaCoach.TwoPc.UiTests -- --offline-practice
dotnet run -c Release --project desktop/DotaCoach.TwoPc.UiTests -- --lane-vision-e2e
dotnet run -c Release --project desktop/DotaCoach.TwoPc.UiTests -- --lane-window-e2e
```

前三项不抓屏。第四项需要交互式 Windows 桌面和足够大的前台窗口遮住测试窗口；中途切换或没有合适窗口会停止，不改用桌面或 Dota 采集。完全放在显示器之外的目标在本机只交付过一帧，因此不作为通过证据。全程没有替玩家操作。要验证自己的实战端到端误差、漏检率及游戏 1% low，仍需独立的带标注连续兵线、以及相同场景的开/关对照。
